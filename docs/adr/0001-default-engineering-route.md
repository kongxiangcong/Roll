# 采用独立 Roll 仓库和模块化单体，保持取证与正式决策权限分离

2026-10-11后端范围修订：用户明确只批准Codex真实审阅，DeepSeek暂不测试且后续忽略。当前仅交付/验收CODEX，以下2026-10-07双后端选择作为历史决定保留，由[新范围](../../.scratch/roll-p0/provider-scope-2026-10-11.md)覆盖；不删除旧接入证据，也不把排除DeepSeek记为通过。

依据 2026-10-07 的实现对齐指示，Roll 采用独立仓库、Python/FastAPI 模块化单体、React Web；SQLite 保存正式状态，Parquet 保存适合归档的行情与研究数据，原始依据按内容指纹留存。此路线已合入 [PRD V1.3](../../ashare_market_decision_prd.md)，用于承载本地优先、单用户单账户、可重放和受控写入的产品边界，避免整仓迁入参考项目的业务流程。归档分析不另建能够覆盖账户事实的权威来源。

OpenAI Agents SDK 承载受控取证任务。后续 Q7 已明确选择 Codex 与 DeepSeek 两种后端并支持切换：Codex 接入完整任务运行时，DeepSeek 接入受控 Agent 的模型路径。两种后端分别验收后以同一任务与证据契约对接，不因配置能切换就宣称工具能力相同。用户已说明两者均已订阅，本轮不再评估金额预算；具体接入权限和模型标识在实现阶段查证，不把订阅说明写成接口已通过验收。

后端返回证据候选与缺口，正式账户、能力资格及风险规则的写入仍由 Roll 的受控服务负责；不引入多角色金融裁决。用于开发 Roll 的技能，以及参考项目的 AGENTS.md、SKILL.md、示例配置，不自动成为生产取证 Agent 的指令、权限或业务规则。

优先评估 daily_stock_analysis 的数据和导入组件，参考 LangAlpha 的证据追踪方法及 ai-hedge-fund 的连续影子设计。每个候选组件分别记录检查版本、许可证、必要依赖、语义差异和适配测试，再区分直接复用、改造后复用、仅参考设计和不采用。

本决策确立工程默认值，不证明任何外部组件已完成适配。仅在发现与 PRD、实际环境或关键正确性要求冲突的具体证据时，提出最小替代方案及代价。本轮不初始化仓库、不修改生产代码、不提交或推送；规格、任务与实现由用户另行调用对应流程。
