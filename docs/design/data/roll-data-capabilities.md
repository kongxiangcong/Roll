## 1. 当前可读取的数据

下表命令省略前缀 `roll`。例如 `roll prices 600362.SH --start 2025-07-21 --end 2025-07-23 --adjustment raw` 读取本地日线，`roll inputs etf_flow 510300.SH --start 2025-07-21 --end 2025-07-22` 读取估算净流量。`roll sync --daily-only` 才触发行情同步；`--market-inputs`、`--financials-only` 可缩小范围。历史 `--backfill` 需要起止日，每段最多 93 个自然日，取基准指数和选定市场输入。股票与财报分别走各自同步入口。[现有命令定义](../../../backend/src/roll/cli.py#L43)

本节依据 v2.1 当前采集、存储和读取代码，以数据项为单位列出能力。表中的范围指程序可请求的范围，实际覆盖以选定数据目录的记录和失败日期为准。未读取个人账本或使用供应商账户验证权益。Windows 默认 CLI 数据库位于 `%LOCALAPPDATA%/Roll/v2/roll.sqlite3`；`ROLL_DATA_DIR` 更换基础目录，`roll --data-dir DIR` 直接选择含库的目录。[配置入口](../../../backend/src/roll/config.py#L47) · [同步入口](../../../backend/src/roll/market/sync.py#L11)

## 2. 逐项选择来源

**本地已有合格版本时直接读；确需联网时，扶摇是相同口径、已获外部访问权的首选商业接口。** 每项能力登记主取数渠道、原始发布者、可用于何种用途及生效版本。交易所、基金管理人和发行人分别负责自己的行情统计、净值与公告；它们的记录也是裁决日期、权益和更正冲突的依据。AKShare 是取数工具，独立性要追溯到它实际访问的站点。同花顺官方同时提供 REST 与工具入口，部分目录项仅供其客户端使用；列入目录只足以安排试验。[同花顺官方服务](https://github.com/Hithink-Tech-Org/Financial-API) · [外部接口范围](https://github.com/Hithink-Tech-Org/Financial-API/blob/main/docs/api/README.md)

| 需求 | 默认路径与近期开发选择 | 何时动用 Investoday |
|---|---|---|
| 股票和基准指数原始日线、权益、复权、个股量额 | 继续用扶摇。先核现有历史接口是否实际返回量额、单位和交易状态；Roll 当前日线表只保留 OHLC。分红登记日、除息日、支付日按用途分别核公告。 | 扶摇缺必要字段／区间，或指定除权窗口需要第二渠道核价时，只查相关股票和日期。已有江西铜业除息日原始开盘 23.73 元的对照。 |

## 3. 用途决定需要多少佐证

同一个数可以用于浏览，却不足以支撑仓位参考。请求方声明用途，数据层按用途规定最低证据；证据是否满足由返回的材料决定。**高需求指错误会改变结论、金额、信号方向或样本资格，而非访问次数多。** 实际质量按数据项和窗口评估：预期行数、有效行数、最长连续段、陈旧天数、迟发／修订记录、未解决分歧，以及上次核对的对象和日期。当前质量高且用途普通时复用；质量不足但用途普通时标注缺口；质量不足且用途关键时优先查原件，仍无证据则阻断；即使历史质量稳定，关键字段仍须有覆盖本次对象、口径和版本的佐证。每次先过身份、日期、单位、复权口径、缺失值和重复记录检查。按实际精度判差，例如总份额规范为整数后精确相等，价格按券种最小报价单位，净值按管理人披露精度；日期错位不能用数值容差消除。

| 用途／所需置信度 | 可接受证据与校验频率 | 不满足时的输出 |
|---|---|---|
| 浏览与线索：看市场背景、找本周研报 | 一个可追溯来源，通过基础检查；显示发生日、采集时间和最近可用日。观点标为观点。 | 可返回标日期的旧值、单源结果或空值，供人工阅读。 |
| 可重复研究：做图、探索因子、重建历史 | 固定口径、样本池、版本及日历分母。新增源、字段变化、沪深市场、历史断点与公司行动优先抽样对账。日常正常行复用已验证规则；突变、改版或符号冲突转逐项核查。 | 返回覆盖、失败日期和允许研究的范围；互相冲突的观察分别保留，不进入依赖它的特征。 |
| 高需求且要求高置信：决定可成交价格、权益、参考股数、信号翻档、冻结或前向成绩 | 对**实际改变结论的字段及日期**必须有针对性佐证：独立来源同口径比对，或沿渠道回溯至权威原件，核对记录、披露时点和版本。会改变结论的修订重新验证。派生值还需输入清单、公式版本及可独立重复的计算。交易事实以确认凭证为准。 | 证据欠缺返回“待佐证”，存在分歧返回“冲突”；阻断受影响的数量、档位或标签，保留可用背景和未受影响的字段。 |

两家供应商都转载同一条交易所记录，可以发现传输、日期或换算错误；证据列为“已对原表”，独立原始来源数仍为一。两个 API、两个模型或三个相同数字也不能增加原始独立性。唯一权威事实（例如某基金管理人发布的单位净值）可凭可定位原件及独立抽取核对达到要求，不强求第二家发布同一净值。无法追溯的共同上游标为“独立性未知”。佐证过的输入不会自动证明一个策略有效。[领域定义](../../../GLOSSARY.md) · [历史重建与当时可得性的边界](../../adr/0004-reconstructed-price-volume-research.md)

## 4. 单独维护的数据层接口（目标契约）

保留本地 Python 模块和 SQLite，先让 CLI、HTTP、回测和研究工具复用一个能力入口。模块负责查目录、取数、规范化、证据、版本和费用；晴雨表权重、仓位规则、交易模拟、账本确认及日报冻结仍由各自业务模块维护。调用者只需说明“哪项事实、哪个对象、何时可用、用于什么”。

| 操作 | 输入 | 输出与副作用 |
|---|---|---|
| 查能力 | 数据项、市场、频率 | 字段及单位、支持范围、现有适配器与候选源、历史或快照、证据要求、可能的计费。不联网。 |
| 读数据 | 数据项、标的、区间、决策截止、用途，可指定版本 | 返回符合要求的最新本地版本或冻结版本；含覆盖与缺口。不联网，回测重放与页面重读走这里。 |
| 按需获取／核验 | 同一请求，加允许来源、此次可用付费预算和待核查字段 | 先复用本地合格结果，规划缺失页或佐证样本，执行允许的请求；返回规范记录、证据和费用回执。显式选择单一来源时，其失败按实返回。 |

每条返回区分**业务日期**（交易日或报告期）、**发布／可得时刻**、**Roll 实际取得时刻**、**观测版本**。发布时间未知时允许做标注假设的历史重建；要求严格历史时点时返回不可用。结果同时有三项判定：数据覆盖（完整／部分／缺失）、证据（单源／已对原件／独立佐证／冲突）、用途（可用或原因）。明细保留来源渠道、原始发布者、单位、复权锚点、查询参数摘要、内容指纹、版本和修订关系。派生值引用输入版本；同日多个来源分开存，再选可用版本。供应商修订产生新版本，已冻结快照仍可重读。原件按授权缓存；只有哈希且无可重放材料时如实说明限制。

**调用例。** 盘后浏览江西铜业最近 20 日收盘价：本地够用就返回；缺日时只向扶摇取该窗口。复核 159915 的某日资金方向：读取两日份额及当日净值，优先使用深交所原表佐证日期；已知冲突未解时返回冲突明细，不花钱反复请求同一回答。查询江西铜业一周新增研报：在范围匹配、免费路径无合格结果且有相应预算时查 Investoday，一次查询供同一周报和详情页复用。三个例子的缓存身份包含证券、数据项、频率、区间、口径及版本；较低证据等级的缓存不能自动满足较高等级请求。

### Investoday 的预算与失败处理

账户已充值，日常刷新、回测重放和服务启动的默认付费预算为 **0**。具体研究任务可设端点、标的、窗口、最多页数和权益上限；预算可以随任务保存，授权范围内自动执行。触发条件只有三类：合格的首选渠道缺少所需字段或日期；高置信用途有能解决具体疑点的交叉核对；任务明确需要研报等特有内容。已有原件能回答问题时直接复用。扶摇超时本身不足以触发付费全量回填。

执行前按端点等级和剩余页数保守预估，取数过程中逐页核对业务码、总数和去重结果；达到覆盖目标、预算上限或确定拒权即停止。相同请求并发合并；短时缓存空结果并记录查询水位。网络超时可能已扣费，先记“扣费待确认”，不得无限重试。按回执分别记请求次数、预计权益、实际已确认消耗及未完成页。供应商新版计费 L1/L2/L3/L4/L5 分别为 1/2/5/10/10 倍，成功空结果按其规则也可能计费；具体以账户套餐及供应商回执为准。只在适配器内读取密钥，查询日志不保存请求头。[官方定价](https://std.investoday.net/apidocs/pricing) · [Investoday 调用合同](https://std.investoday.net/apidocs/quick-start)

## 5. 开发顺序与验收

1. **先统一读取。** 从跟踪股原价、ETF 份额和净值三项开始，把当前入口映射到同一份能力目录。对同一 SQLite 副本比对旧 CLI 与新读取结果，要求值、单位、缺口和截止日一致；纯读的外部请求计数为零。
2. **再统一按需获取。** 用现有扶摇和 AKShare 实现先接通限定标的与区间的小窗请求、来源回执和版本存储。并发相同请求只抓一份；部分失败保留成功行；来源冲突和后续修订均可重放。用沪深两市 2025-07-21/22 份额和江西铜业除息窗口验收。
3. **最后接付费能力。** 先用留存样本验证字段，再在确有需求的任务下接入 Investoday 量额或研报。用计数器验收四个情形：缓存命中零调用、未授权付费零调用、指定页预算触顶停止、研报重复刷新不重复消费相同已满足的请求。实际扣费缺少账单依据时列为待核。
4. **按效果扩项。** 先看缺口是否补上、冲突是否被识别、每项能力花费多少。四只宽基资金维要看相邻日、净值与两融共同有效的窗口，以及实际新增多少有效信号。八指数聚合另作观察；研报按可追溯的新证据和去重效果评价。每新增一项能力，同时更新本文目录、源路由、单位、历史界限及最近一次验证证据。
