## 3. 两个会改变可行性判断的结果

**旧回测有日期、有价格，仍然可能没有可以评价的策略交易。** 既往隔离库的 510300 对照在定权期 970 日、样本外 700 日都没有缺价，两段有效晴雨表信号都是 0。它能验证持有对照的计价路径，却无法回答控仓是否有效。v3 的首个趋势实验应仅依赖自身必要特征，单列信号机会、成交次数、无法评价区间和连续净值。新增市场或 ETF 条件时，另报覆盖减少了多少，以及在相同机会集上结果变了多少。[历史验收表](../../../.scratch/roll-v2-1-refactoring/issues/12-etf-backtest.md) · [评分特征与预热](../../../backend/src/roll/barometer.py#L101)

**旧撮合用了开盘后才知道的价格。** 本轮直接调用现有 `Portfolio.rebalance`，给定同一买入意图、前收 10、开盘和最高均为 11。只把当天最低从 11 改为 10.99，结果由跳过买入变成按 11.006 买入，甚至高于当日最高。这个合成反例说明，单把 ETF 常量替换为股票代码，会让回测接受事前无法判定的开盘成交。重写时，开盘执行只能消费该时点可知的状态和合理成交假设。方向受限、排队结果无法辨识时记录未证实，滑点的经济成本与实际可成交价明确区分。日频数据足以检验盘后决策、下一时段执行。日内多档网格的先后顺序仍需更细数据。[现行撮合](../../../backend/src/roll/backtest.py#L46) · [滑点计算](../../../backend/src/roll/costs.py#L25)

## 4. 评审判断与重构取舍

采纳外部研究、独立发布和本地裁决的边界。让模型在盘后给出第二个动作倾向，会让用户同时面对两套选择依据，还会为这个过程导出个人账户。研究者或其选用的外部工具可以查询公开指标、提交 Markdown 草稿。Roll 发布结构化研究约束，决策只依据已发布版本、冻结规则及本地账户。M4 再考虑外部研究流程的自动化。此决定沿用 ADR 0001 的模块化单体，取代其内置取证 SDK 路线；ADR 0004 对历史重建与严格历史时点的区分继续适用。[主方案 §4.4](../architecture/roll_v3_trading_pipeline_spec.md#44-本地-cli-与外部研究助手) · [ADR 0001](../../adr/0001-default-engineering-route.md) · [ADR 0004](../../adr/0004-reconstructed-price-volume-research.md)

**账户按新契约重写。** `backend/src/roll` 的 29 个 Python 文件共 4,230 行，其中 `accounts/` 的 8 个文件占 1,559 行，即 36.9%（含空行和注释）。三个 CSV 版本分别有 28、32、40 列。草稿有 READY 与 QUARANTINED 分支，普通读取使用版本快照，确认时重放并写入 JSON 快照。重写的理由是 v3 只需要可信账户基线、实际流水、可卖批次与共享预算，现有主要复杂度围绕草稿、对账和旧格式，且缺少独立 RiskBudget。实现规模以业务契约验收，不设 200 行配额。[CSV 字段](../../../backend/src/roll/accounts/csv_import.py#L22) · [账户读取](../../../backend/src/roll/accounts/ledger.py#L125) · [确认](../../../backend/src/roll/accounts/ledger.py#L293)

**数据目标上调到多年真实回测，覆盖以实取为准。** 扶摇已有原价和公司行动接入，Investoday 已通过个股三日量额、机械设备行业 20 个交易日分页的实际取样。行业端点文档允许从 2020-01-01 起查询。以上证据支持直接安排多年拉取；首标所属行业、各字段实际连续性、账户授权及全窗耗时仍要在 M0 记录。跨除息的 63 日用于验证算法，不能据它缩短 M0。M0 的当前基本面研究可以引用可定位公告；到 M1 尝试 E4 时，再对进入历史实验的事件核对首发和更正。[数据路由](../data/roll-data-capabilities.md) · [供应商实际取样](roll_dual_pipeline_review.md#41-已用账户验证的数据项)

### 实施顺序

1. **建立可重放的多年市场输入。** 从 2020 年开始拉取江西铜业、沪深 300 和已确认分类的行业指数，按交易日生成覆盖表。使用追加观察版本与一次冻结的版本水位取代同键覆盖。先验证除息窗口中税前派息、参考昨收和原始开盘三个独立字段，再以同一读取逻辑跑多年窗口。表、主键、版本选择及修订示例以主方案 §11.1 为准。
2. **跑通账户、趋势规则和双基准。** 初始账户、资金预算和持仓批次版本化，冻结一套简单趋势规则。历史和前向共用次日执行及权益结算，报告资金、股数、成交、成本及连续净值。不主动交易与买入持有按实际初始状态解释。候选在评审前可全程模拟，实验本身必须完成。
3. **先签收工程，再签收真实运行窗口。** CLI 发布带证据的档案，P0–P4 用同一账户余额处理各股候选。冻结输入和输出版本，追加真实与影子结果。M0a 通过前向登记与影子结算演练即可投入日常使用并解锁 M1；M0b 从真实运行日起连续记录 20 个交易日，包含观察、未成交与未执行。两道门分别按主方案 §13 签收。M1 增加行业、ETF 和有条件的 E4 对照，M2 再做多策略独立验收和切换。[表契约、裁决与里程碑](../architecture/roll_v3_trading_pipeline_spec.md)

## 核查边界

前一轮可行性核查检查了运行代码、用户指定的两份文档、ADR、既有实施记录和发行人原文。在隔离环境运行账户、ETF 回放、指数校准及财报相关的 14 个选定测试，全部通过，另单独复现了开盘撮合的合成反例。这里的测试只说明对应 v2.1 行为。本工作副本不含旧验收所指的历史 SQLite 库，因此长窗覆盖和交易数引用既有验收表。没有访问个人账本或调用付费数据接口，没有以本次分析代替 v3 策略回测、完整数据验收或 20 日前向运行。本轮评审核对了代码规模、账户实现、取样范围和文档一致性。首标及趋势原型已纳入主方案，用户风险预算和准入数值仍按方案 §16 确定。
