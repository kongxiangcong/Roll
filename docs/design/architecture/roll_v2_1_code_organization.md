# Roll v2.1 代码组织方案

2026-11-25 确认。Roll 在 Windows 本机以 Python 模块化单体运行，共用一个 SQLite 数据库。下面的目录是 v2 的目标布局，按交付周次建立。产品行为和验收以[实施规格](../../../.scratch/roll-v2-1-refactoring/spec.md)为准。代码归属与依赖方向以本方案为准，取代 [v2 原稿](roll_v2_refactoring_spec.md)中的目标目录草图。

## 目标布局

```text
backend/src/roll/
  cli.py          命令行入口与参数解析
  web.py          本机 Web 入口、路由与静态页面装配
  config.py       本机设置与跟踪池配置
  db.py           SQLite 连接及连接设置
  accounts/       账户事件、现金、成交、CSV 导入与对账
  market/         盘后同步、本地行情读取、扶摇与 AKShare 数据转换
  reports.py      日报冻结、重读与导出
  barometer.py    四维覆盖率、市场总分与仓位档
  risk.py         真实账户及个股风险提示
  backtest.py     单 ETF 模拟持仓、交易成本与净值
  calibration.py  指数标签、同档历史频率与前向成绩
frontend/src/
  pages/          今日晴雨表、持仓与跟踪池、回测与校准
backend/tests/    账本、日报、评分、回测等业务行为测试
```

## 四项组织决定

### 1. CLI 与 Web 直接调用相同的业务模块

命令行负责参数和输出，Web 负责请求、响应与页面装配。两者都在本进程调用相同的记账、同步、日报和回测逻辑。新的独立入口只装配当期已交付的模块。沿用旧应用工厂会拉入研究、审阅与后台线程，因此首周从新入口启动。

React 的三个页面分别读取所需数据。例如，市场首页可以直接读取晴雨表，持仓页打开时再读取账户。页面负责呈现与交互，分数、超限金额和校准频率由后端计算。

### 2. 日报模块独占冻结、重读与导出

同步更新本地行情，工作台读取最新结果。用户显式生成日报时，`reports.py` 读取本地账户和行情结果，保存内容与截止时间。SQLite 对日报交易日设置唯一约束，同日 CLI 与 Web 重复或并发生成均返回首次成功冻结的报告。读取旧日报与导出 JSON、Markdown 都使用已保存的内容。

该模块可以在首周仅用账本与两项真实行情工作。后续接入评分和风险提示时，日报保存这些模块在截止时点给出的结果。前向校准读取已冻结的预测并向自己的记录追加成熟标签。这样，补行情和补标签都可以独立于原日报执行。

### 3. 共用连接方式，业务模块各自拥有 SQL

`db.py` 负责打开和配置指向同一数据库的连接。账户表及账户确认事务归 `accounts/`，行情表及同步写入归 `market/`，日报表及按交易日冻结的事务归 `reports.py`。其他模块从账本读取真实账户镜像，直接使用连接设施存取自己拥有的数据。账本无需代其他业务建表。

复用现有十进制记账、成交导入、对账与重试回执行为。同一笔账户确认在同一事务内完成，移除确认成交时对旧执行意向的回调。使用具体 SQLite 连接即可，省去通用仓储与 ORM。

### 4. 评分、风控、回测与校准各有一个归属

| 模块 | 独占的规则 | 使用方 |
|---|---|---|
| `barometer.py` | 必需输入、整维计权、评分、档位及上限 | 工作台、日报和历史回放复用同一计算 |
| `risk.py` | 账户总仓位超限、单票上限与可卖股数、个股风险提示 | 持仓页和日报读取相同结果 |
| `backtest.py` | 510300.SH 的换档调仓、买入持有对照、费用、净值和回撤 | 回测页面与命令行 |
| `calibration.py` | 沪深 300 的 20 个后续交易日标签、同档成熟频率和 Brier 分母 | 回放与前向统计，首页和日报展示截止时点的频率 |

市场评分只消费市场数据。行业 ETF 的相对强弱用于个股风险提示。回测消费晴雨表档位，校准消费预测时的档位和指数结果。这四个模块各从一个普通文件开始。

## 分周落地与验证

| 周次 | 实施及可观察结果 |
|---|---|
| 第一周 | 建立独立入口、SQLite 连接、账本、行情同步与日报模块。从新入口录入一笔资金和一笔成交，真实同步江西铜业和沪深 300，冻结日报。退出、断网并重开后，核对现金、持仓、两个标的的收盘行情与截止时间。规格规定的三项首周验收全部通过后，同阶段归档 v0、切换入口并清理旧依赖。 |
| 第二周 | 先冻结评分参数表，再加入晴雨表和风控。用完整、部分和缺失数据检验覆盖率和档位。更换个人跟踪池后核对市场结果一致。 |
| 第三周 | 加入回测和校准。分别核对 ETF 换档与缺信号期间的净值、指数标签成熟时间及 Brier 分母。 |
| 第四周 | 贯通三个页面、命令行和 WorkBuddy 导出。在同一账本上由不同入口生成同一交易日的日报，检查冻结结果一致。浏览器验收共用一份端到端测试配置。 |
