# Roll v2.1 设计评审定稿

本文件记录 2026-11-24 确认的评审决定，作为 [v2 设计原稿](roll_v2_refactoring_spec.md) 的修订。涉及行情存储、财报可得性、评分、校准、迁移、仓位展示和第 1 周验收时，以本文件为准。以下用例是实施时的验收要求。

## 1. 行情以原始 OHLC 和复权因子为准（接纳 P1-3）

daily_bars 保存 open_raw、high_raw、low_raw、close_raw 及复权因子。次日开盘成交回测读取 open_raw。前复权和后复权按同一因子序列、各自的锚点动态计算。首版只持久化原始价格和因子，读取时计算复权价，MA 和 ATR 使用相同锚点的复权序列。原稿中固定回看五天的策略只适用于普通日常补数。

**验收**　选取一次实际除权事件。路径 A 先同步到除权日前，再跨除权日增量同步；路径 B 在空库全量重建。两条路径使用相同截止日和复权锚点，逐日比较受影响区间的复权 OHLC，以及同日 MA 和 ATR。原始开盘价须能独立核对。

## 2. 财报按披露日和版本回放（接纳 P1-4）

fundamentals 同时记录报告期、announce_date、data_version、营收同比、deducted_net_profit_yoy、单季 operating_cashflow 和资产负债率。每次更正追加版本。回放交易日 t 时，只选 announce_date <= t 的版本，再对每个报告期取当时最新版本。更正版本使用自身的披露日。累计现金流须先换算成单季金额，并处理上年末与一季度的边界。

财报红灯在任一条件成立时触发：

- 最新季营收同比低于 −10%，且扣非净利同比低于 −20%。
- 最近连续两个相邻单季的经营现金流均为负，且最新季资产负债率高于 75%。中间缺季不能算作连续。

**验收**　同一季报在首发披露前不可见，首发后可见初版，更正后可见更正版。重放两次披露之间的交易日须恢复初版及当日财报灯。

## 3. 晴雨表完整映射与缺数保护（接纳 P1-5）

四维权重为趋势与波动 35%、资金 30%、全市场广度 20%、估值 15%。广度只取最近五个交易日的全市场上涨家数占比均值，每日占比为上涨家数除以上涨与下跌家数之和。行业 ETF 相对沪深 300 的强弱只用于对应个股卡。四维均采用明确的 0–100 分段线性映射。每个子项要列明输入单位、窗口、最短有效样本数、节点值、端点归属、插值和超界处理。估值分位的 70%–85% 区间必须有连续映射。未满足预热期的指标计入缺失。

**跟踪池独立性验收**　固定交易日、市场数据及评分参数，用两份包含不同行业股票的跟踪池分别计算。个股卡展示各自的标的与行业强弱，两次计算的市场总分、仓位档和校准归档结果一致。

覆盖率是当日有效维度的权重之和。参数表逐维列明必需输入，各项齐全且达到各自的最短有效样本数时，该维计入全部权重。任一必需输入缺失或预热不足，该维计入零权重。覆盖率 **≥65%** 时，总分等于有效维度加权分之和除以覆盖率（两处权重均以小数计）。低于门槛时只显示覆盖率、缺失项及“今日晴雨表不可用”。当日总分、晴雨表总仓位上限及相应超限提示均为空。用户配置的单票上限独立核对。

第二周开始实现晴雨表前，在本节用一张参数表冻结各维必需输入、单位、窗口、预热长度、评分节点、插值与端点规则及组合公式。参数选择仅使用 2020–2023 定权期资料。2024–2026 样本外结果仅用于检验。

**验收**　固定三组输入及唯一预期输出，分别覆盖完整数据、仅趋势有效（35%）和全部缺失（0%）；另验恰好 65% 时按有效项归一化。35% 和 0% 两组均须显示不可用，且无晴雨表总仓位超限提示。

有效总分按下表确定唯一的总仓位上限。日报、风控卡和回测共用此表，快照只记录一个上限值。

**部分输入验收**　趋势、广度和估值完整，资金维度已有 ETF 净申赎但缺两融。预期资金维度权重为零，覆盖率为 70%，总分为（0.35 × 趋势分 + 0.20 × 广度分 + 0.15 × 估值分）/ 0.70。

| 总分 s | 档位 | 总仓位上限 |
|---|---|---|
| 75 ≤ s ≤ 100 | 进攻 | 80% |
| 50 ≤ s < 75 | 均衡 | 60% |
| 25 ≤ s < 50 | 谨慎 | 35% |
| 0 ≤ s < 25 | 防守 | 15% |

真实账户仅在实际占比高于上限时提示超限。均衡日持仓 55% 或 60% 均无提示，持仓 65% 显示超限 5 个百分点。低于上限不提示补仓。

## 4. 定权、样本外校准和数据源分项验收（接纳 P1-6 及扶摇补充项）

**2020–2023 为定权期，2024–2026 为样本外测试期。** 进入测试期前固定评分、仓位规则、分箱和评估口径；测试期截至实际可取得的最后一个完整交易日。按日期冻结输出，后续只追加成熟结果。验收允许“未观察到单调关系”。原稿 Phase 3 中根据测试期单调性微调权重的条款取消。

Brier 的预测事件固定为沪深 300 从 t 日收盘至第 20 个后续交易日收盘的收益大于零。校准沿用第 3 节四个仓位档位，取代原稿的五分箱。t 日概率 p 等于截至该日预测截止时、同档已成熟样本中的上涨比例。冻结预测日、档位、同档已成熟样本数和 p。首页与日报展示当前档位的样本数和历史上涨频率，回测报告按同一四档汇总。样本数为 0 时概率留空。事件成熟后记录标签 y，对已成熟且有预测的样本求 (p−y)² 的均值，并报告分母。

历史回放中，每个有档位的交易日在标签成熟后计入同档上涨频率，包括预测时概率为空的日期。当天冻结的空概率保持为空，该日排除在 Brier 分母之外。上线后沿用预测截止时已经成熟的同档历史标签估计概率。

**冷启动验收**　历史上首次出现防守档时，同档成熟样本数为 0，概率留空。若该样本成熟后的标签为上涨，且下一次出现防守档时它仍是唯一成熟的同档样本，则第二次显示样本数 1、概率 100%。此时防守档的历史 Brier 分母仍为 0。第二次样本成熟后，该档的历史 Brier 分母增至 1。

前向校准按交易日最多登记一次。用户在交易日当天显式冻结该日日报，且冻结时有档位和概率，才登记该预测。第 20 个后续交易日收盘后取得指数结果时，向校准记录追加标签。仅同步、重复生成同一日报或事后补做历史回放均不新增前向预测；历史回放计入回测。前向统计同时列出期间交易日数、实际登记预测数和其中已成熟的 Brier 样本数。

首版回测仅评估晴雨表控仓。策略持有现金和 510300.SH，唯一对照为买入持有 510300.SH。两组使用相同的价格和费用口径，结果列明该 ETF 的历史行情缺口。标的固定，省去选择器和自动替换逻辑。回测范围删去跟踪池组合、ATR 止损、MA20 择时及恒定 50% 仓位对照。个股卡仍可展示 ATR 提醒。策略表现按账户净值衡量，Brier 标签仍按沪深 300 指数计算。

t 日收盘首次得到有效档位，或该档位与上一次有效档位不同，策略才按对应仓位在下一交易日以原始开盘价调仓。同档期间允许仓位随价格漂移。缺数后恢复时仍与缺数前的最后一个有效档位比较。真实账户风控卡按当日实际仓位独立检查超限。

晴雨表不可用时，该信号日不发起调仓，已有 ETF 份额继续逐日计价，该段盈亏计入净值与回撤。该日没有晴雨表预测，排除在 Brier 分母之外。

**调仓验收**　依次输入“均衡、均衡、不可用、均衡、谨慎”，仅第一个均衡和最后一个谨慎触发次日调仓。同档期间即使持仓从 60% 漂移至 59.6%，也继续持有原份额。

首版每类数据固定一个来源。股票日线、指数日线和复权因子由扶摇提供，ETF 行情和份额由 AKShare 提供。删除 BaoStock 自动切换、其他备用行情源和 ETF 份额 CSV 补录。账本保留成交 CSV 导入。同步时只更新成功取得的数据，失败项保留已有历史并显示该项最后成功日期。当日输入缺失按第 3 节计算覆盖率。

同步代码按数据类型直接调用扶摇或 AKShare 模块。各模块负责自己的请求与字段转换，可复用口径相同的日期、单位和入库逻辑。删除原稿的通用 `MarketDataProvider` 基类及配置中的主备来源选择。

| 对象与样例 | 来源和验收口径 |
|---|---|
| 股票 600362.SH | 扶摇日线分别请求原始和前复权行情，核对证券、交易日和价格口径。原始 OHLC 与复权因子按第 1 节落库。 |
| 指数 000300.SH | 扶摇指数日线只取原始点位，请求省略 adjust。按指数交易日计算前瞻 20 日标签。 |
| ETF 510300.SH | AKShare 分别核对同一 ETF 的行情与份额，记录单位和实际日期覆盖。计算净申赎额时再核对单位净值。ETF 作为独立样例，不纳入第 1 周股票＋指数验收。 |

## 5. 新建账本、入口切换与清理顺序（部分接纳 P1-1）

用户已确认没有旧账户。v2 从空账本启动，通过日常记账入口验证现金和持仓。删除原稿中的旧库迁移、迁移样例及新旧账本对账要求。

第 1 周闭环通过后，同阶段归档 v0、切换入口、执行清理清单，删除旧 app.py、successor_* 及依赖这些模块的旧入口。不设置长期双轨期。原稿“先删再建”及“先清空 docs”的顺序由本节取代。

## 6. 风控卡与旧 ADR 0003（部分接纳 P1-2）

v2 废止 v0 的 G1–G7、资格审批及资金授权门禁。实施切换时在 README 明示，不另写长篇替代 ADR。

首版风控卡展示当前仓位占比、超限百分点、账户确认时点、行情截止时间和过期状态。总仓位超限时仅展示超限百分点和超限金额，由用户选择标的。仅在单票超过其配置上限时，按该股超限金额、计价价格和整手规则折算参考减仓股数，结果受账本确认的 T+1 可卖数量约束。缺少所需估值、价格或可卖数量时，在对应项目标明原因。该卡供个人核对风险暴露，实际委托和实际成交由用户在券商端处理并另行记账。

## 7. 盘后展示与跟踪池配置

首版行情只使用盘后日线。用户可随时打开工作台，持仓卡展示收盘价及该价格对应的交易日。删除原稿的盘中报价请求及实时风控卡要求。

跟踪池及其风控参数统一在 `config/watchlist.yaml` 编辑，于下一次同步时生效。网页只读展示已生效的跟踪池及参数，删除网页编辑器和 `PUT /api/config/watchlist`。修改配置后重新打开已有冻结报告，仍显示该报告生成时的结果。

每个交易日只在用户首次显式生成日报时冻结一份，记录当时的结果和截止时间。同一交易日再次生成直接返回原报告。同步只更新工作台上的最新数据。后续数据补齐、配置变更及校准标签成熟均保留日报生成时的内容。

**同日补数验收**　资金维度缺两融、其余三维完整时生成日报，覆盖率为 70%。同日同步补齐两融，工作台覆盖率更新为 100%。重新打开日报及再次生成该日日报，两次均返回首次冻结的 70% 和原截止时间。

## 第 1 周唯一完成条件

1. 从 v2 独立入口新建空账本，录入一笔资金和一笔成交。重启后核对现金余额与该证券持仓数量，两者均与录入记录相符。
2. 通过扶摇实际同步江西铜业 600362.SH 与沪深 300 000300.SH，记录行情口径和实际日期范围。
3. 显式冻结一份首周日报，核对账本现金与持仓、江西铜业最近收盘价和沪深 300 最近收盘点位及各自的交易日、各项数据覆盖情况、报告截止时间。列出已取得和缺失的数据，仅对当时能够验证输入完整且预热充分的维度计权。覆盖率低于 65% 时显示“今日晴雨表不可用”。断开外部数据源后，从本地重复读取同一报告，以上内容及截止时间一致。

三项同时满足即在同阶段清理 v0。原稿的“四标的六年历史、30 秒内全部拉通”不再作为第 1 周完成条件。
