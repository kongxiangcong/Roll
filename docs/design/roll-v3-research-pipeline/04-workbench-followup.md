# 04 · 工作台模块归位、审阅与复盘跟进

阶段标识为 `roll-research-workbench`。02 与 03 联验后，将后台研究编排入口按 `Data Foundation → Research → Experiment → Decision → Review` 五模块边界接入工作台，并清理现有页面的哈希串、原始 JSON 与审计回执噪音。用户既能从个股逻辑研究区发起或更新 `ResearchDossier`，也能在策略对照实验区发起或归档 E0/E1 开发实验，还能从一条复盘偏差线索一键脱敏发起后续研究。全景看盘首页与自选池日常同步由[阶段 05](05-workbench-overview.md) 承接。

## 本轮规格要回答的问题

- **模块归位与三视图骨架**：工作台顶层按用户动线收敛为「全景主台（本轮先提供干净导航入口与单股衔接）· 个股决策与复盘 · 研究与策略实验室」。实验室内部明确分设**「个股逻辑研究」**（`Research` 模块：提交研究问题与公开材料、跟踪进度、处理缺口、审阅发布 `ResearchDossier`）与**「策略对照实验」**（`Experiment` 模块：查看与发起 03 的开发实验对照、下钻交易与回撤区段差异、归档“停止或继续”决定），不再将策略实验报告混入个股档案视图。
- **界面零证据、零审计与全新空间布局**：推倒重做现有暖纸墨色工作台，采用极简克制的现代空间布局，通过分组、层级、留白与视觉动线直接传达页面逻辑，替代冗余的指导文案。工作台全程不展示证据、审计结果、材料来源、SHA-256 哈希、原始 JSON 或内部错误码；若发布草稿被后端门禁拦截，仅在操作区简短提示缺少必要条件或定位被阻断项，底层证据引用、字段依据核验与指纹反查完全保留在 SQLite 与 CLI 验收入口。
- **复盘脱敏跟进闭环**：从个股复盘视图点击跟进时，后台自动只导出标的、公开的证伪问题、触发条件及可核对的公开证据引用。内部计划和登记 ID、成交、风险预算及私有备注严格留在本地 Roll 账本，不在用户界面要求手工裁剪字段。审阅人可通过 CLI 从发布版本在本机反查任务、尝试和原始线索。
- **CLI 与网页跨进程并发一致**：CLI 与网页共用任务状态。两个入口同时领取同一尝试时只有一个执行者。最终提交草稿与登记取消的先后以 SQLite 事务为准，取消先落库便停止提交，草稿已提交则显示既有结果。重启只回收已失去执行者的尝试。根据实际并发结果选择 SQLite 配置。

## 完成标志

1. 从当期个股复盘线索一键发起个股档案更新。给演练的私有备注加可识别的标记，用 CLI 核对公开包只含获准字段。在「研究与策略实验室 · 个股逻辑研究」按明确草稿版本审阅、发布，再用 CLI 从发布版本追到原线索。另从「研究与策略实验室 · 策略对照实验」查看并归档 03 的开发实验报告（直观呈现过滤笔数、净收益/最大回撤差异及持仓区段对比），核对现行个股档案仍为原版本。
2. 后台研究和 `roll review register --mode rehearsal` 使用**同一份 SQLite 验收库副本**，登记可在研究运行期间完成。核对归档计划可重读，`roll forward-window audit` 将演练排除在真实交易日计数之外。
3. CLI 持有尝试时重启工作台，运行中的任务仍可继续。模拟执行者退出后重试，再模拟取消先于草稿入库的情况。分别核对原尝试可追溯、同一尝试最多提交一份草稿、成功取消的尝试没有草稿。
4. 工作台所有视图无任何证据列表、材料来源、审计回执、哈希串与原始 JSON；发布被后端拦截时前端清晰反馈阻断原因，且网页发布后的档案在 CLI 中完整保留字段依据、人工判断理由、确认人和有效期，从冻结计划可通过 CLI 追到当时生效的档案。
