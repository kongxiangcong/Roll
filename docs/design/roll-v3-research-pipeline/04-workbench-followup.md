# 04 · 工作台发起、审阅与复盘跟进

阶段标识为 `roll-research-workbench`。02 与 03 联验后，将同一研究编排入口接入工作台。用户既能从个股页发起研究，也能从一条可核对的复盘证伪线索发起后续研究。

## 本轮规格要回答的问题

- 个股研究页提交问题后立即取得任务 ID，可查看进度、公开输入、缺口、草稿和实验回执，能够取消、用相同材料重试或补证后发起关联任务。
- 从复盘页只导出标的、公开的证伪问题、触发条件及可核对的公开证据引用。内部计划和登记 ID、成交、风险预算及私有备注留在 Roll。审阅人可从发布版本在本机反查任务、尝试和原始线索。
- CLI 与网页共用任务状态。两个入口同时领取同一尝试时只有一个执行者。最终提交草稿与登记取消的先后以 SQLite 事务为准，取消先落库便停止提交，草稿已提交则显示既有结果。重启只回收已失去执行者的尝试。根据实际并发结果选择 SQLite 配置。

## 完成标志

1. 从当期复盘线索发起个股档案更新。给演练的私有备注加可识别的标记，核对公开包只含获准字段。按明确的草稿版本审阅、发布，用 CLI 从发布版本追到原线索。另从研究页审阅并归档 03 的历史开发报告，核对现行个股档案仍为原版本。
2. 后台研究和 `roll review register --mode rehearsal` 使用**同一份 SQLite 验收库副本**，登记可在研究运行期间完成。核对归档计划可重读，`roll forward-window audit` 将演练排除在真实交易日计数之外。
3. CLI 持有尝试时重启工作台，运行中的任务仍可继续。模拟执行者退出后重试，再模拟取消先于草稿入库的情况。分别核对原尝试可追溯、同一尝试最多提交一份草稿、成功取消的尝试没有草稿。

4. 网页审阅与 CLI 显示相同的字段引用、人工判断理由、确认人和有效期；发布被阻止时定位缺依据的字段。从冻结计划可追到当时生效的档案。开发报告能查看 03 的逐笔差异、回撤期间持仓及停止或继续的理由，按任务归档。
