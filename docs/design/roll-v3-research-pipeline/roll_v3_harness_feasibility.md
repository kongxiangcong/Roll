## 实施前应改写的契约

### 1. 研究请求只能触发开发实验

`run_experiment(..., research_ref=task_id)` 的默认路径调用 `begin_acceptance`，完成后调用 `record_historical_result`。`research_ref` 只记录关联。加 `--replay` 仍会登记从开发期到验收期末的样本揭示。在已有正式历史验收的副本上，指定新的研究引用再次运行，`strategy_exposure` 由 1 条增至 2 条，新记录为 `purpose=acceptance, independent=0, verdict=pass`。在尚未揭示的合格区间，默认路径还可能占用第一次独立检验机会。[实验实现](../../../backend/src/roll/v3/experiment.py) · [窗口登记与准入](../../../backend/src/roll/v3/strategy.py)

首版可让研究任务读取固定的开发期结果，或调用已有 `development_robustness`。后者仅在开发窗口运行，返回来源实验和情景汇总，本身没有为本次比较持久化独立结果 ID。由 Roll 保存请求、参数、窗口及成功或失败回执，结果可定位到本次尝试。M1 再增加一个有明确输入特征的开发期对照入口，复用既有裁决、撮合、权益、成本和双基准。请求及预算先核对，再计算。对仍要保留独立性的窗口，给调参任务的行情包也要裁到开发期。完整的多年行情导出包含留出期走势。[市场研究导出](../../../backend/src/roll/v3/market_research.py) · [独立验收约定](../architecture/roll_v3_trading_pipeline_spec.md#72-研究沙箱与生产隔离)

E0/E1 要求助手解释实测差异，因此在用户选定固定预设后，Roll 先计算开发回执，并把指标和覆盖说明冻结进公开输入。助手一次读完、引用并解释该结果。这样既可逐项核验正文与数字，也省去了事后拼接 Markdown 的步骤。助手临时提出的其他实验作为后续研究线索保存。[阶段 03](03-development-experiment.md)

### 2. 冻结一次研究实际使用的全部公开输入

现有 `freeze_snapshot` 要求用途、范围和截止时点，冻结的是观察序号水位。`research export` 已给出各证券缺口、可评价窗口和内容指纹。`research inputs` 只从此前发布的档案提取公开证据引用，首次研究可能为空。`followups` 读的是复盘表，还带 `plan_id`、`registration_id` 及证据引用。只保存行情 `snapshot_id` 无法复现助手看见的全部材料，新公告的原文还需要单独取得。[快照](../../../backend/src/roll/v3/market.py) · [档案公开输入](../../../backend/src/roll/v3/research.py) · [复盘线索](../../../backend/src/roll/v3/review.py)

Roll 首次准备时确定用途、截止时点、证券和区间。个股档案任务冻结当期公开公告、行情、档案版本和可公开的证伪问题。历史 E0/E1 只冻结开发期可消费的数据、计算口径及回执。分别保存实际内容或不可变引用及指纹。复盘到计划的内部关联留在 Roll。未建档股票可从用户提交的公开文件或摘录起步，并记录来源、定位和实际取得时间。

区分“用同一份材料重跑”和“补数后重新研究”。前者复用输入清单。行情或公告有新增时，后者使用带父任务引用的新任务和新清单，按需要重冻行情。小样本 CLI 验证中，导入一条观察后，同一截止时点下旧快照仍为 0 条，新快照为 1 条。工作台应把补数后的操作指向新任务。Roll 合并预检缺口与助手声明，按本问题所依赖的特征判断阻塞性。申万的 11 个缺口会削减行业比较的共同样本，个股与宽基完整的 E1 可以照常开展。

### 3. 真实助手需要可以验证的读取隔离

同一操作系统用户运行子进程时，设置 `cwd` 和移除 `ROLL_DATA_DIR` 不会改变文件读取权限。本机 `codex-cli 0.172.0` 的帮助把 `--ephemeral` 定义为不持久化会话文件，工作目录和沙箱另有选项。账户资料集中在同一个 SQLite，工作台也有本地账户及发布入口。附件不能仅凭目录布局宣称助手只能看见公开包。[SQLite 入口](../../../backend/src/roll/v3/storage.py) · [本地工作台路由](../../../backend/src/roll/v3/web.py)

首版若仅需读材料、写结构化草稿，可让 Roll 传入公开文本、收取结构化响应并落盘，关闭助手的本机工具。若需要助手读文件或执行工具，给它单独受限的运行环境，只暴露只读输入与可写输出，限制其接触宿主工作台和数据源凭据。上线前用假私有文件和测试工作台验证读写权限，并在目标平台验证超时或取消后子进程退出。Windows Job Object 负责进程树生命周期，文件和本机服务的访问权限需分别落实。真实模型调用与 Windows 行为均待实机验证。

### 4. 把一次尝试和它交出的草稿绑定

`import_draft` 会以调用参数覆盖标的，优先取 Markdown 内版本，并按 `(symbol, version)` 更新同名草稿。两次尝试若都产出 `v1`，先前供审阅的内容可能被替换。建议 Roll 分配任务草稿版本、检查原始标的及版本冲突，在同一短事务内导入草稿、绑定尝试并标记 `draft_ready`。结构校验共用一处，核对证据时点、结构化引用及来源输入。发布人、发布时间、生效时间和人工确认依据仍在显式发布时写入。涉及实质判断的来源和推断由审阅人核对。[草稿与发布](../../../backend/src/roll/v3/research.py)

### 5. 并发只处理真实存在的两个写入口

CLI 同步运行与工作台后台运行可能来自不同进程。`max_workers=1` 只约束一个进程。可用每任务一个由操作系统随进程退出释放的锁，配合 SQLite 短事务领取尝试、分配序号、保存结果。重启后只恢复确已失去执行者的尝试。查询状态不会中断另一入口的工作。首版人工重试够用，会话续接和自动重试可等实际需求出现。

当前连接已用 `timeout=15`，再写 15000 毫秒不会增加等待预算。WAL 可改善读写并行，多个写者仍会串行。现有正式实验在写事务中执行整段回放，研究后台若照搬它，会与盘后登记争写锁。开发期鲁棒性已有临时模拟库可复用，计算完成后再把结果短事务写回主库。用“研究运行中仍可盘后登记、同一次尝试最多提交一份草稿”验收并发，再决定 WAL 配置。[存储](../../../backend/src/roll/v3/storage.py) · [实验运行与开发期鲁棒性](../../../backend/src/roll/v3/experiment.py)
