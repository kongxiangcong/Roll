# 02 · 接入真实 Codex CLI

阶段标识为 `roll-research-codex-execution`。沿用 01 的任务入口、输入包和草稿格式，让 Roll 启动一次真实 Codex 研究，用户能在 CLI 中看到当次尝试的结果或失败原因。

## 本轮规格要回答的问题

- 本轮由 Roll 提供冻结的公开材料，助手返回草稿或缺口。模型服务可联网，主动上网找公告另行立项。缺失的材料由用户或 Roll 取得后再发起关联任务。
- 在本轮规格中写明目标平台和 Codex CLI 版本，优先验证无本机工具的文本输入、结构化输出。若该配置无法落实读隔离，使用权限受限的运行环境。用测试私有文件和回环服务验证实际权限。`cwd`、`--ephemeral` 和助手自行拒绝访问的文字都不足以证明隔离。
- Roll 如何区分取消、超时、进程中断、配置错误和返回格式错误？同一输入可由人发起下一次尝试，日志和产物归属各自的尝试。等待助手期间释放 SQLite 写事务。

## 完成标志

1. 用正式研究 CLI 完成一次真实 Codex 调用，按任务 ID 重读输入引用、退出结果和待审草稿。账户、成交和风险预算均留在 Roll。
2. 在声明的目标平台核对无法读取测试私有文件或访问测试工作台。取消、超时和中断后核对尝试状态、整棵执行进程树退出、运行锁释放及同输入重试。记录实际平台和权限配置，Windows 交付以 Windows 实机验证为准。

3. 抽查真实助手返回的草稿：拟放开风险的事实字段应指向冻结材料中可定位的证据；只有推断时保留不确定性。用 01 的同一发布入口核对字段级依据和人工确认。

本轮用公开材料完成一次真实个股研究即可验收。03 将已计算的开发实验回执作为公开输入接入同一执行路径。[执行隔离评审](roll_v3_harness_feasibility.md)
