# 01 · 正式 CLI 的离线研究闭环

阶段标识为 `roll-research-offline-cli`。起点是已验收的 M0a。开发者要能断网通过拟新增的 `roll research task run`，针对 `600362.SH` 提一个问题，取得可审阅的草稿，或看到哪项必要证据缺失。

## 本轮规格要回答的问题

- 让任务 CLI 接受公开公告文件或摘录及其标题、来源、定位、URL 或文档标识、实际取得时间。将内容或不可变引用、指纹与问题、标的、截止时点、行情快照一起固定。即使此前没有已发布档案，也能从用户提供的材料起步。
- 离线执行桩交回草稿或证据缺口。复用档案的证据、时间与引用校验，只补任务归属核对。Roll 为每次尝试分配独立的草稿版本，在同一短事务内写入草稿、任务关联和完成状态。发布后仍能按版本反查任务和尝试。
- 同输入重试生成新尝试并保留先前产物。补入会改变结论依据的材料后，发起关联的新任务。CLI 应能分别重读两次使用的材料。

## 完成标志

1. 在验收库副本上，先用正式 CLI 得到一次阻塞性缺证，再提供一份公开公告创建关联任务。分别按 ID 重读，只有新清单含该材料。非阻塞性缺口随草稿保留。
2. 同输入重试产生草稿 A、B。用 `roll research show 600362.SH --draft --version A` 审阅 A，按回执中的版本执行 `roll research publish 600362.SH A --reviewer 研究者`。核对生效的是 A，B 和旧尝试仍可重读。
3. 固定行情、账户及截止时点，新增草稿后 `roll plan --preview` 与基线逐字段一致。发布后，在生效前的时点仍选旧档案，在新版本有效期内的时点选 A，原冻结计划按 ID 重读仍一致。

4. 同一发布入口检查字段级依据。事实门禁通过须引用对应证据；投资逻辑完好和非空策略白名单可引用证据或记录有理由的人工判断。验收只签名、带事实引用、带人工理由三种档案，并从生效计划核对字段依据、确认人和到期时间。旧计划按原版本重读。
