# CNEquity 补充采集与数据层维护

2026-10-10 用户授权接入，首期范围固定为江西铜业 `SSE:600362`。延续从今天开始积累真实 PIT、隔离虚拟模型开发、资料与验证充分后才启用的路线。

## 接入边界

使用官方固定提交 `c118038ea82b5bb78783c0c17a1d9251b36de71d` 的适配器。源码安装于 `.roll-data/cnequity-runtime`，与 Roll 后端虚拟环境分离；运行配置为 `ROLL_BOUNDED_ADAPTERS_ONLY`，只启用本次使用的 HTTP、Polars 和配置依赖，未提供上游全市场 CLI、情绪分析或独立服务。

运行 `backend\.venv\Scripts\python.exe -B -X utf8 scripts\setup_cnequity.py` 安装。安装逐文件核对官方 Git blob，保存源码清单、包代码 SHA256、实际依赖版本及 lock，并验证实际适配器导入和Windows时区依赖。每次采集子进程验证包指纹和依赖版本；不自动升级、不加载任意可执行文件或客户端 URL。源码 Apache-2.0、TDX 内嵌实现含 MIT；原项目许可证与 NOTICE 随安装保留。软件许可不等于上游数据再分发许可。

CNEquity 提供 TDX RAW 日线、东财 RAW 日线、当前交易状态和公司行为；巨潮公告索引复用固定版本解析器，通过已核对证券代码的发行人 ID 作单证券查询。所有视图独立保存。东财、新浪等相同上游不会因为换了工具名称而增加独立证据。

状态适配器通过有限分页的ST板块／当日停牌名单检查目标证券，只登记600362的事实；这类名单响应作为参考原件保存，不生成或扩展研究股票池。

## 访问管理

`collection_source_policies` 保存启用状态、配置版本、实际 upstream、固定证券范围、认证方式、清洗版本及调用上限；`collection_source_changes` 保留每次开关的前后值与依据。修改需匹配 `expected_revision`，旧配置写入拒绝409。来源配置只允许启用／暂停，无任意主机、代理、密钥或代码入口。

每条 CNEquity 路径最多8次网络调用、8 MiB、18秒；总补充采集最多100秒。HTTP不跟随重定向，TDX仅使用固定上游清单前两台公开服务器，无全市场发现扫描。子进程不继承业务 API 密钥。所有网络调用、原件与失败记录属于当次 run；同一源内部分页或服务器轮换不改写其 upstream。

原有搜狐、新浪、东财采集也受开关和退避控制；该策略仅施加于此处的前向采集，不改变其他按需分析的来源选择。连续3次失败进入1小时冷却，期满再尝试，成功后清零连续故障计数；原失败 run 和清洗报告始终保留。当前交易状态只在交易所日历确认的当日交易日采集，休市和日历未知不补写正常状态。

## 原件与清洗

HTTP实体正文在 JSON／数据集解析前按SHA保存，TDX查询实际 recv 字节在适配器规范化前保存，不含 setup；适配器输出另存 `CNEQUITY_ADAPTER_EXPORT`。原件、实际请求范围、代码版本、取得时点、解析输出和清洗报告均可回溯，宿主桥接、子进程与清洗模块的实际SHA另随run／快照／报告保存。适配器输出不伪装成原始供应商响应。丢失原件时保留缺口并禁止日线输入资格。成功解析的有限事件查询若返回空结果，记录成功、零事件，不补造事件或宣称完整历史覆盖。

清洗保持源值和字段来源，不择优覆盖：

- 日线必须在单证券／有限日期窗口内，价量额有限且为有效数值，OHLC区间合法，股数为整数，成交额／股数落在当日高低价附近。零成交占位进入隔离区，不据此推断停牌；当前日完整性未核验时暂不允许作为模型日线。
- 完全重复行可去重；同键不同值的行全部隔离。异常行与原因保存在 `collection_cleaning_reports`，原件仍在归档中，不填均值、不补零、不静默删除。
- 交易状态、风险警示分别保留；缺失 ST、ST子类型、上市阶段、除权状态均为未知。当前板块快照不作为过去状态或交易所完整证明。
- 公司行为按证券／除权日／行为类型建立稳定事件键，更正产生新版本；配股价格、完整日期链、税费、实际到账未知时保持未知，没有账户账本写权限。
- 公告索引保存发行人、公告ID、日期和标题，未取得PDF时显式 `ANNOUNCEMENT_INDEX_ONLY_ORIGINAL_NOT_ACQUIRED`，不声称正文已归档。

`collection_comparison_reports` 对同日RAW不同来源的可比数值按Decimal逐字段比较，保存双方源值、原件哈希和未解决差异。比较不静默按显示精度归一、不选赢家、不签发独立证据或数据完整资格。

CNEquity并未对日线、状态、公司行为实现财报式strict PIT筛选；Roll依据宿主实际收到、快照完成、入库的最晚时点登记 `known_at`。旧日期仅是现在已知上下文。每次新采集保留旧版本，按截止时点和来源重放；不从后来的 current 版本补造旧可得性。

## 数据库与维护

权威数据仍是 `.roll-data/pit/roll.sqlite3`；原件在同目录 `raw/`，规范事实在 `parquet/`。追加使用既有SQLite受控事务；新增策略、健康、清洗、比较表通过幂等DDL建立，不迁移真实账户、不重置采集起点、不修改旧研究或预算。采集中断保留 run，重启按进程归属标记中断，不清空失败历史。

每日16:10任务继续调用 `scripts\collect_prospective.py`，完成原有与CNEquity采集、登记、差异比较，再校验SQLite、归档哈希、事实关联与每批Parquet重放。完整性通过才通过既有备份服务生成 `PROSPECTIVE_COLLECTION` 一致恢复包，包含数据库与已登记原件／Parquet；故障时脚本失败，不自动删除、修复、训练或启用。关机、离线或未成功执行的日期保持缺口。

安装副本与 Python 环境是可重建运行条件，恢复包内保存数据和采集时的版本依据；恢复后先重新安装同一固定提交并验证运行时，不能拿新版本接着写而不留变更记录。当前不自动清理旧版本或原件。

## 查看与操作

- `GET /api/research/collection-sources`：来源、当前配置与健康；`POST /api/research/collection-sources/{source_id}/policy`：启用／暂停。
- `GET /api/research/collection-cleaning`：最近30份清洗报告。
- `GET /api/research/collections/{plan_id}/comparisons`：最近10份源值差异报告。
- `POST /api/research/collection-integrity`：离线检查数据库、原件与重放，仅报告，无自动修复。
- 研究页面“数据源与清洗”可查看来源访问状态、暂停／启用、隔离数与完整性检查。

系统继续 `COLLECTING / NOT_GRANTED`。采集成功、单位核对、工程测试或虚拟模型都不能替代数据覆盖、成熟标签、真实训练校准冻结、确认性／前向验证、技术审阅和正式资格。
