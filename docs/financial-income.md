# 利润表观察

单股「查看利润表」复用持仓/关注名单、现有来源配置、原件归档和同一 SQLite。来源 `akshare-financial-em` 默认关闭，仅已接入 `SSE:600362`。启用后每次显式采集最多8次 HTTP、总18秒、8MiB、零重试；已有请求键只返回原回执。取消和中断不生成财报版本，也不自动重试。

AKShare 1.19.1（MIT）运行在独立 Python 环境，业务后端不导入其依赖。依赖固定在 `backend/requirements-akshare-income.lock`。本次已验证 Windows / Python 3.13.12；进程入口还校验实际 SDK 版本和 `stock_three_report_em.py` SHA-256。部署时将 `ROLL_AKSHARE_PYTHON` 指向该隔离环境的 Python 可执行文件，重启应用；缺失配置时采集回执明确失败。固定响应入口只允许 `ROLL_ENV=test`，派生证据标记 METHOD。

实际调用 `stock_profit_sheet_by_report_em`。限定传输保存 HTTP 解码实体：公司类型页、完整日期索引、利润表响应。仅将日期索引的最近五期派生视图交给库，原索引不变；不将 DataFrame 序列化冒充上游原件。活动流逐块落盘，强杀留下可校验但不完整的前缀。

原字段、规范字段、披露日期精度、来源更新、实际接收与规范事实可知时间分别记录。原件先归档；同一来源流/证券/报表/报告期的内容修订形成版本链。语义证明失配不切断该链，但新版本保持口径或单位未知，且不能证明与旧版本可比。NULL 与负数不填零。四份已存发行人 PDF 只证明匹配期间和数值的合并、人民币元、累计口径；2025-H1 使用2026-H1比较列，不能反推2025年已知。

查询保留所有旧版本，提供原响应及口径 PDF 页链接。归档损坏明确拒绝。所有记录均不授予正式能力、不写真实账户、不替换旧模型，也不声称历史 PIT 完整。真实 SDK 一次来源评估与 METHOD 的 API/浏览器整链验收分别记在该 feature 的 `evidence/09-financial/acceptance.md`。
