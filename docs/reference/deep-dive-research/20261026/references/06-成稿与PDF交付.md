# 成稿与 PDF 交付

Step 6 的全部内容。这一节解决**成稿到交付物之间的落差**——稿子写得对不对是一回事，
能不能干净地变成一份能发出去的 PDF 是另一回事。

## 一、交付什么、谁干什么

**交付物就两份：Markdown 成稿（源文件，留给用户改）+ PDF（可以直接发出去的那份）。**

| 环节 | 归谁 | 说明 |
|---|---|---|
| 稿子怎么写、写什么 | 本 skill | 正文十节 + 附录九项 |
| 排版规格、渲染、校验 | 本 skill `scripts/md_to_pdf.py` | 自建链路，**不过 Word、不走 `doc-format`** |

**为什么自建这条链路（2026-10-12 用户指定，三条理由）：**

1. **doc-format 的 PDF 路径在本机跑不通。** 它走 `build_pdf.py` → LibreOffice，而这台机器上
   既没有 LibreOffice，也没有 pandoc / LaTeX / WeasyPrint。走它必然是失败，不是"不好用"。
2. **Word 中转会带进三类与内容无关的坑**：有序列表编号连号、封面/目录前后多出空白页、
   正文首页没页码。本次实盘在收尾脚本上返工最多，全都是为绕开这些中间态。
3. **Markdown 直排没有中间态。** 改一个数就是改一行 Markdown，重跑一条命令，不用再过一遍 Word。

引擎用本机现成的 **Google Chrome 无头打印**：CSS 分页（`@page`、`break-before`）支持最稳，
中文字体族也最全。页码与 PDF 书签由 **PyMuPDF** 打完再盖——Chrome 的 `@page` 不支持
`counter()`，页码没法靠 CSS 出。

## 二、一条命令

```bash
python3 scripts/md_to_pdf.py \
    --input  "03-交付物/<公司>-深度研究.md" \
    --output "03-交付物/<公司>-深度研究.pdf"
```

用哪个解释器由你机器的实际情况决定（能跑通、装了依赖的那个即可）。
**不要照抄任何文档里的绝对路径**——换台机器就不存在了。

跑完脚本会自己报一行页序，照它核对：

```
总页数 54｜封面 第 1 页｜目录 2–2 页（罗马）｜正文 3–54 页（阿拉伯，从头数）
```

可选项：

| 参数 | 用途 |
|---|---|
| `--no-toc` | 不出目录 |
| `--no-page-numbers` | 不盖页眉页脚页码、不写书签（封面照出） |
| `--no-cover` | 不出封面，标题段并入正文（拿旧成稿做对照时用） |
| `--date` | 指定封面与页眉的日期（缺省取跑脚本那天，格式 `2026年10月16日`） |
| `--keep-html` | 保留中间 HTML，排版出问题时用来查 |
| `--title` | 指定 PDF 标题（缺省取成稿第一个一级标题） |

**依赖与解释器。** 脚本要 `markdown`（Markdown → HTML）与 `PyMuPDF`（页码／书签）；
缺了它会直接报错并给出安装命令，不会静默产出一份没有页码的 PDF。

```bash
python3 -m pip install markdown pymupdf     # 装到当前解释器
```

**Chrome 的位置。** 脚本按「`CHROME_BIN` 环境变量 → 各系统常见安装位置（macOS／Linux／Windows）→ `PATH`」
依次找，找不到会明确报错。用 `CHROME_BIN=/path/to/chrome` 指定，不要改脚本。

## 三、交付物的版式（脚本里写死的取值）

| 项 | 取值 | 为什么 |
|---|---|---|
| 纸张 / 边距 | A4，上下 22／20mm、左右 19mm | 报告正文的常规密度 |
| 正文字体 | `Songti SC` 11.5pt，行距 1.65 | 中文长报告最耐读 |
| 标题三级 | `Heiti SC`：一级 16.5pt 主色＋下横线／二级 12.5pt 次主色＋左侧竖条／三级 11.5pt 深灰 | 三级各有一种形态，翻页时靠颜色和符号认层级，不靠字号猜 |
| 一级标题 | **强制另起页**，下加细横线 | 研究档案按节翻，不按屏幕滚动 |
| 封面 | 单页；顶部满幅主色色带、底部满幅细色带；不排页码。组成见下「封面的组成」 | 交付物要有封面 |
| 页眉 | 左报告名、右日期，下一条细线；封面页不排 | 券商研报的通行做法 |
| 页脚 | 上一条细线，左「本报告仅供研究参考，不构成投资建议」、右页码 | 同上 |
| 目录 | 自动生成，取一级＋二级标题，虚线引页码；罗马数字页 | 长报告必备 |
| 页码 | 封面不排 / 目录罗马 / 正文从 1 起，右下 | 与纸质报告的习惯一致 |
| 表格 | **三线表**：顶线与底线 `1.1pt #8f3a2b`，表头浅底深字（底 `#f7ece6`／字 `#8f3a2b`），行间 `0.5pt #ecdfd8` 细线；行不跨页断、表头跨页重复 | 满格灰框是 Excel 味，三线表才是研报的样子 |
| 书签 | 一级＋二级标题写入 PDF 大纲 | 阅读器侧栏可直接跳节 |
| 文档属性 | 标题／作者／主题写报告自己的信息，不留 `HeadlessChrome`、`Skia` | 属性面板也是交付物的一部分 |
| 重点标注 | 关键结论主色 `#8f3a2b`／风险红 `#c62828`，加粗＋淡底 | 结论级信息要在翻页时跳出来，见第四节 |
| 配色 | 全篇一套主色（陶土 `#8f3a2b`）——标题、表头、封面、引用块、重点标注共用同一个值，色值表见下「配色 token」 | 一份报告只有一套色，多了就花 |

**字体名必须写系统里真有的。** macOS 上没有"宋体""黑体"这两个字体名，写上去 Chrome 会
自动替身，出来的字可能不是你要的。脚本里的字体栈按系统依次回退：

| 系统 | 正文（宋） | 标题（黑） |
|---|---|---|
| macOS | `Songti SC` / `STSong` | `Heiti SC` / `STHeiti` |
| Windows | `SimSun` | `SimHei` |
| Linux | `Noto Serif CJK SC` / `Source Han Serif SC` | `Noto Sans CJK SC` / `WenQuanYi Zen Hei` |

Linux 上先 `fc-list | rg -i "cjk|song"` 确认装了中文字体，否则正文会出豆腐块。

### 配色 token（2026-10-16 定稿 · C 陶土）

全篇一套色，改色只改 `scripts/md_to_pdf.py` 里的值，**表里这几个 token 与脚本必须一致**。
配色选的是陶土（brick／terracotta）系：正文暖、对比克制，表头铺浅底而不铺满深色块。

| token | 值 | 用在哪 |
|---|---|---|
| 主色 | `#8f3a2b` | 一级标题、二级标题左竖条、表格顶底线、封面色带与标题、引用块左条、目录标题、`==关键结论==` |
| 次主色 | `#7a2f22` | 二级标题文字、目录一级项 |
| 表头底 | `#f7ece6` | 表头底色（**浅底深字，不是深底白字**） |
| 表头字 | `#8f3a2b` | 表头文字 |
| 关键结论底 | `#f7ebe6` | `==关键结论==` 的淡底 |
| 风险红 | `#c62828` | `@@风险与雷@@` 的文字 |
| 风险底 | `#fde7e5` | `@@风险与雷@@` 的淡底 |
| 引用块底 | `#faf3ef` | `>` 引用块底色 |
| 副标题左条 | `#dcc3b8` | 封面副标题的左侧竖条 |
| 行间细线 | `#ecdfd8` | 表格行线、图表的网格线 |
| 三级标题 | `#2b2b2b` | 三级标题文字（深灰，不参与配色） |

**图表用色同步。** `scripts/chart_svg.py` 的 `SERIES_COLORS` 以主色打头，其余序列色取自
同一暖调族（陶橙／灰蓝／苔绿／赭金／灰紫红／灰褐），不另外成一派。

**风险红比上一版更亮。** 旧值 `#9c1420` 与新主色在色相上太近，红字与关键结论容易分不开，
故提到 `#c62828`。改配色时优先保住"关键结论与风险一眼能分开"这一条。

### 封面的组成（2026-10-16 新增）

**封面由脚本按成稿开头那段生成，不是手画的图。** 成稿第一个一级标题到第二个一级标题之间
就是封面段（脚本里 `split_cover_body`），它被拆成四块：

| 块 | 成稿里长什么样 | 缺了会怎样 |
|---|---|---|
| 公司名 | 第一行 `# 齐翔腾达（002408.SZ）深度研究`，尾部「深度研究」被拆出来当报告类型 | 没有一级标题就不出封面，全文并入正文 |
| 副标题 | 标题下第一段普通文字 | **没写就自动取「速览 · 一句话」的头一句**（限 96 字），属兜底不属规范 |
| 数据基准 | `**数据基准**：……` 那一段 | 该块不渲染 |
| 免责声明 | `>` 引用块 | 该块不渲染 |

版面上分四层：顶部色带（左品类名、右日期）→ 公司名与副标题 → 信息栏（报告日期／报告性质）
→ 页脚区的数据基准与免责声明。**四块全缺也不崩**，旧成稿照样出得来。

- **色带左侧不写机构名，也不写「XX证券」。** 这是用户自己的研究档案，不是任何机构的产品；
  固定用品类名 `上市公司深度研究`（脚本里 `COVER_BRAND`）
- **色带只能由 PyMuPDF 画。** 那两条色带要压到纸张边缘，HTML 到不了页面外框，只能打完 PDF 再盖
- **日期取跑脚本那天**；要复现某一天的历史报告用 `--date`

**为什么不用年报封面。** 年报封面是一张图，字体、配色、版式都与正文不成套，贴进来像拼贴；
各家年报的封面设计密度相差太大，做不到每份报告一个样。自画封面用的还是正文那套主色与同一族黑体。

## 四、成稿的写法约束

下面几条**写 Markdown 时就要避开**，踩了会在转换环节返工：

1. **块级元素前必须有空行，尤其是标题和表格。** Python-Markdown 不满足这个条件时**不报错**，
   直接把标题当正文、把表格当一竖溜文本——这是最阴的一类失败，脚本里做了补空行的兜底，
   但成稿本来就该写对。
2. **连续多行之间要有空行，否则会被并成一段。** 本次实盘踩过：附录里记三次监管处罚，
   三行挨着写又没空行，出来变成一段。
3. **封面 = 第一个一级标题到第二个一级标题之间。** 所以成稿的封面必须正好是
   「标题 + 免责声明 + 数据基准」这一块，正文第一节从第二个 `#` 开始。脚本按这条切分，
   不认公司名，换一份成稿照样成立。
   **港股标的的数据基准要多写三项**：披露渠道（港交所披露易）、报表币种与股价币种、
   会计准则（HKFRS / CAS）与年结日；A+H 标的要写明引用的是哪一套报表。
4. **不要用 `−?` 表示"未知数值"**，直接写「未披露」或「未取得」。
5. **括号全半角要成套。** `PE(TTM）` 这种一个半角一个全角，是上一版规范化脚本的经典误伤点。
6. **`---` 会被脚本丢掉。** 分节已经有强制分页，留着只会在页脚多一条横线。
7. **表格空单元格用 `—`** 是可以的，不用手改。

### 重点标注：`==关键结论==` 与 `@@风险与雷@@`

几千行的报告，读者需要有东西能被一眼看见。成稿里用两个标记把结论级信息标出来，
PDF 里分别渲染成主色与红色，带淡底、加粗。**这两个标记是本 skill 自己的语法，
由 `scripts/md_to_pdf.py` 转换，不需要装任何扩展。**

| 标记 | 语义 | PDF 里的样子 |
|---|---|---|
| `==……==` | 关键结论与关键变量 | 主色加粗字 ＋ 米陶底（`#8f3a2b` / `#f7ebe6`） |
| `@@……@@` | 风险与雷 | 风险红加粗字 ＋ 淡红底（`#c62828` / `#fde7e5`） |

**必标清单（这几处不标，等于把结论埋进三千行里）：**

1. **周期位置与阶段**：价格分位 ＋ **这条周期走的是哪条路（A 过剩出清型 / B 需求拉动型）**
   ＋ 处在第几阶段 ＋ 这条路走到哪一步、方向往哪边走（A 类给出清判据八项与"在恶化还是改善"，
   B 类给缺口判据七项与"缺口是在打开还是正在被补上"）（周期型必标。这是全篇最该跳出来的一句话。
   **A 类的结论照判据的方向写**：判据没转好就写"出清没有进展"，不写"触发条件尚未凑齐"；
   这一处要与速览页的股价节奏坐标对得上，已经涨过一轮、手上正好有起止与幅度的顺手写上，
   见 `08` 第二节末。
   **B 类禁用"尚未出清"这套词**，见 `references/08` 第三节末）
2. **决定利润的第一驱动变量**：那个"改一个数、全篇结论都要重算"的变量
3. **稀缺性 / 唯一性**：这家公司不可复制的那一项（与雷点同权，见 `04`）
4. **排雷灯号**，以及最重的那一项命中
5. **盈亏平衡价、临界值、关键阈值**
6. **速览页「核心模型」里那一条主线**
7. **参照带的核心结论**，紧接"这不是目标价"的定性
8. **现金流与利润背离的结论**（若存在）
9. **最大的单一敞口**：客户、供应商或单一产品集中度（若超过阈值）
10. **最大证伪点**：这套判断最经不起检验的地方（与最重的雷同权，见 `11-反向质疑与遗漏排查.md`）。
    正文用"最经不起检验""最容易被推翻"这类直白说法，**不写"死在××环节"**
    （见 `references/00` 第六节·生死类说法）
11. **股价节奏坐标**：这只股票当前走到哪一步（上一轮高点、已调整多久、按自身历史与行业经验
    这类调整通常多久）。**与第 1 项同属"现在是什么时候"，两处可并为同一处标注，不额外占额度**
    （见 `references/13-历史股价复盘.md`）
12. **四态与见顶／中继判定**（周期型）：这一轮落在四态（底部反转／上升中继／顶部结束／
    下跌中继）的哪一态；行业见顶信号与股价见顶信号各已出现几项；判成中继的写明为什么排除见顶，
    判成见顶的写明为什么排除中继（`references/08` 第四节）。
    **这一项与第 1 项方向相反，必须同时存在**——出清答"这一轮走到哪"，见顶答"是不是已经走完"，
    漏掉任何一半，位置判断都可能反了

**密度上限（超了就失效）：**

- 全篇 **≤ 30 处**，脚本每次跑都会数并报警
- 速览页 4~7 处；每节（`X.Y`）≤ 2 处
- 单处不超过 30 字
- **优势侧与风险侧的标注处数要相当**，与"优势与雷点同权"一致

**不许这么用：**

- 不用它标数据本身（数字已经在表格里），标的是**判断**
- 同一行、同一段里不出现两处
- **周期股在周期底部的亏损不标红。** 那是周期特征，不是雷（与铁律 8 一致）。
  只有结构性的、会造成永久性资本损失的问题才用红色
- 不跨行、不跨表格单元格；不在标题里用；同一句不要又加粗又标注
- 多空对垒表里空头最硬的那一条论据，可用 `@@` 标出（与多方最硬论据的 `==` 对称），
  同样受单处 ≤ 30 字与每节 ≤ 2 处的约束
- 代码块（``` 围起来的）里的字符不会被转换，也不计入统计

**标注是"圈原词"，不是"补一句"。** 标记里的文字必须是原句里**已经有的词**，圈出来即可；
**不许把刚说过的意思在标注里再写一遍**。东方钽业那份成稿写成了
"行业处在阶段二（缺口打开）向阶段三（供给追赶）的过渡，`==处阶段二向供给追赶过渡，缺口七项两项转向补上==`"——
前半句和标注那一半说的是同一件事，读起来像结巴（2026-10-15 实盘）。

**成稿前通读一遍，两个动作：**

1. **把标记去掉再读这句。** 去完还通顺 → 标注是圈出来的；去完读不通、断句了 → 标注是插进去的新句，改回圈原词。
2. **把全部标注连同它前面 55 字列出来，逐条读**（这是唯一能逮住这类重复的办法）：

   ```bash
   rg -n -o '.{0,55}==[^=]{4,}?==' 03-交付物/    # 关键结论；风险侧把 == 换成 @@ 再跑一遍
   ```

   一条条看：标注和它前面那句是不是在说同一件事。是，就删掉重复的那一半。

**体检**：脚本每次都会打印一行 `重点标注 N 处（关键结论 x｜风险警报 y）｜上限 30`；
超过上限、或存在落单的标记（`==` 出现奇数次），会往 stderr 报警。

### 成稿前的复核（Gate 2，2026-10-13 新增）

跑 `md_to_pdf.py` **之前**，先做三件可以数出来的事，并把结果写进
`02-工作底稿/成稿自检记录.md`。**这三件事不做完，不跑转换脚本。**

1. **重读** `references/00、02、04、05、06、08、09、11`，记下重读时间。
   会话中途被自动压缩过之后，这几份文件已经不在上下文里了——
   "我记得要求"不等于"要求还在"（机制见 `00` 第七节）。
2. **数三张表**：取数台账是否逐项填满；附录 D 是否逐项成行（A 股 28 行 / 港股 38 行）；
   附录 G 是否逐数字成行。
3. **报三个数**：成稿中文字数、附录 D 行数、重点标注处数。
   中文字数低于 15,000 的，在自检记录里回答"内容本来就少，还是取数没做完"。

**自检记录不是"已检查通过"一句话，它要写下上面这些数字。**
没有数字的自检记录，等于没做——读者看不出你查过什么。
（实盘反例：某份交付的自检记录全文 97 字节，只有一句话。）

### 投资人视角复核（Gate 3，2026-10-13 新增）

Gate 2 是**写的人**在数自己的作业：台账、行数、标注处数。Gate 3 换一副眼睛——
**用真正要管钱的人的位置**通读成稿，回答"我能不能看懂、这份报告对投资有没有帮助、
哪些重要的事没写"。做法、必问清单与记录格式见 `references/10-投资人视角复核.md`，
结论写进 `02-工作底稿/投资人视角复核.md`。

**这一步放在 PDF 出来之后做**（用户 2026-10-13 指定：生成研报后再看一遍）。
命中缺口就回补正文，然后**重跑一次 `md_to_pdf.py`**——正文变了，页码会挪。

### 反向质疑（Gate 3.5，2026-10-13 新增）

Gate 3 回答"读者拿到了什么"；Gate 3.5 再反过来一次——**把结论当成已经错了，回头找它会错在哪**。
按 `references/11-反向质疑与遗漏排查.md` 过五问（前提 / 死因 / 激励 / 空头反证 / 派生数字），
五张表落盘 `02-工作底稿/反向质疑.md`。进交付物的只有三处：速览页"最大证伪点"一行、
第 10 节多空对垒表、第 10 节"本报告未能回答的关键问题"。**这一步是自检层，不新增正文章节。**
命中缺口回补后，同样重跑 `md_to_pdf.py`。

**派生数字（第五问，2026-10-15 新增）**在成稿后还要扫最后一遍：正文与速览里的每个单位数，
在 `02-工作底稿/单位数核查.md` 有没有对应行；倒推行有没有写对照基准；
速览必记数字里有没有混进反推来的临界值。做法与五法见 `references/12-模型自检与交叉验证.md`。

## 五、表格与图（2026-10-15 新增）

**分工一句话：表管横向比较与清单，图管时序与占比，段落只管说理。**
段落里出现多个主体、多个时点、多个公司名就改写——触发线见 `02-问题链与报告结构.md` 第五节。

| 内容 | 用什么 | 为什么 |
|---|---|---|
| 多主体同口径横比（同业、分部、分产品、分地区） | **表** | 读者要按列比，读表最快 |
| 清单式事实（客户、股东、产能、附录九项） | **表** | 一行一项，可核可数 |
| 时序（价格、销量、库存、产能，≥ 6 个时点） | **折线图** | 趋势是形状，不是数字串 |
| 占比与排名（下游结构、成本构成、市占率） | **横向条形图** | 一眼看出谁大谁小 |
| 两三条要点 | **句内数字** | 不必为它起一张表 |
| 一家公司一句话 | **段落** | 上表反而更慢 |

### 图的数量与分布（2026-10-16 新增）

**表装得下数字，装不下形状。** 价格怎么走的、库存在哪一段、利润被什么压住的，这些都是形状：
用表读出来是一串数，用图一眼就看见。成稿读着像一份数据汇编，多数时候不是内容不够，是图不够。
**这一条是硬闸门——正文图数不够，Gate 2 不过。**

**正文 ≥ 8 张图**（附录里的图不计入）。其中这四张必画，它们正好落在四个部分各一节，
数量与分布一起解决：

| 图 | 哪一节 | 画什么 |
|---|---|---|
| 核心变量时序 | 三、变量 | 决定利润的那个价格或价差，近 5 年；周期型给 10 年 |
| 行业供需与库存 | 四、空间与周期位置 | 产量／消费／库存／价格里至少两条，近 5 年 |
| 公司利润史 | 六、财务 | 营业收入／归母净利／毛利率，近 5–10 年 |
| 股价与估值复盘 | 八、历史股价复盘 | 股价指数／每股收益／估值倍数里至少两条，同一条时间轴（三条量纲不同时按下面「怎么画」的归一化写法） |

**剩下的从这张表里找**——每一处都是报告本来就必答的数据，只是换个装法：

| 更容易出图的地方 | 画成什么 |
|---|---|
| 二、业务与单位经济 | 收入结构（分产品／分地区占比）横向条形；单位经济拆解（吨价 − 吨成本 ＝ 吨毛利） |
| 三、变量 | 一阶敏感度横向条形——哪个变量一动、利润跟着动多少 |
| 四、空间与周期位置 | 产能周期（资本开支 vs 在建工程÷固定资产）；价格与价差的历史分位 |
| 五、竞争与产业链 | 同业关键指标分组条形（毛利率／净资产收益率／资产负债率） |
| 六、财务 | 经营现金流 vs 有息负债；应收与存货周转 |
| 九、估值口径与参照带 | 估值倍数历史带（价格分档下的市净率／市盈率分布） |
| 附录 B | 股权结构占比条形 |
| 附录 E | 国内同业与国际同业对比 |

**上不封顶。** 同一节有两组独立的时序，就画两张，不要压成一张。

**三种不算数**——凑出来的图比没有图更糟：

- **把相邻的表原样重画一遍。** 同一组数据既列表又画图只有一种做法成立：表只留关键年份，图给全程形状；
- **一张图塞两件不相干的事。** 量纲差六倍以上脚本会提醒，要放一起就按下面的归一化写；
- **图注复述图里的数字。** 图后只写图里没有的判断，与"表后不复述"同一条规矩。

### 怎么画：`scripts/chart_svg.py`（只用标准库）

```bash
# 数据先落底稿：02-工作底稿/数据/xxx.csv （首列横轴标签，其余列各一条序列）
python3 scripts/chart_svg.py --input 02-工作底稿/数据/胶价.csv --type line \
    --out 03-交付物/图/胶价.svg --ylabel "元/吨" --source "上期所；研究者整理"

# 占比与排名用横向条形图；JSON 写成 {"x": [...], "series": {"占比%": [...]}}
python3 scripts/chart_svg.py --input 02-工作底稿/数据/下游占比.json --type hbar \
    --out 03-交付物/图/下游占比.svg --source "公司年报，研究者整理"
```

- **输入只有 CSV 与 JSON 两种**（`--type` 取 `line` / `bar` / `hbar`）；有缺口就补估计口径，
  脚本遇到空值会报错退出，不许留空；
- **图的复算性和数字一样**：生成命令写进 `02-工作底稿/成稿自检记录.md`，任何人照着能重画一遍；
  数据与图都随报告落盘（数据在 `02-工作底稿/数据/`，图在 `03-交付物/图/`）；
- **不同量纲不要画在同一张图里。** 量级相差六倍以上，脚本会提醒；要放一起就加 `--index 100`
  归一化，并在纵轴或题注里写明"以 2015＝100"；
- **图里不写标题**，标题交给成稿的题注，否则同一句话会印两遍。

### 在成稿里怎么放

```markdown
![图 4-1　钽精矿均价与公司销量（2015—2025 年）](图/胶价.svg)
```

- **题注写在 `![ ]` 的方括号里**，`md_to_pdf.py` 渲染成居中图题。格式
  `图 <节号>-<序号>　<一句话说明>`，说明里带口径与年份（例中"（2015—2025 年）"）；
- **图后不复述图里的数字**（与"表格后不复述"同一条规矩），只写图里没有的判断；
- **图必须随报告落地**：写成外链、或指向不存在的文件，`md_to_pdf.py` 直接报错退出——
  不静默丢图，也不留一张空白框；
- 正文里引用写成"见图 4-1"；**正文有图，附录 F 的图表索引就必须写**，逐张成行，编号与正文同步。

### 表格的样式（2026-10-16 新增）

三线表（顶线／表头下线／底线），表头浅底深字，样式由 CSS 定死。
**成稿里只写 `|` 分列，不手画对齐、不写重复的列单位**——单位写在表头那一格。

**整列都是数字的表列自动右对齐**（脚本逐列判定；判定从严：整列除 `—`、`不适用` 这类占位符
之外必须都是数字，且至少两个真数字，只要有一格是文字就整列留左）。
所以**同一列的数字写法要统一**：不要一格写 `1.31`、另一格写 `约 1.3` 或 `1.31 倍左右`——
那会让整列退回左对齐，一列歪在表里比整表都不对齐更扎眼。

### 表题与表头（2026-10-15 新增）

- **表题只写名称**：`表 <节号>-<序号>　<一句话>`（例：`表 4-2　上升中继与顶部结束的逐项对照`）。
  **不带规则编号**（"（`08` 4.6 六项）"）、**不带"要做几项"**、**句末不加句号**——
  那些是规范文档写给我自己的，读者手里没有 `08`（实盘见 `08` 第二节末）
- **表头用读者看得懂的词**：`读数` → "本轮的实际情况"；`取数`（内容是底稿指针）→ 直接写数值或"来源"；
  `档位`、`口径` 这类内部记法同理。**表头是给读者认列的，不是给我自己记事的**
- **表里不出现代号**：`B · 上升中继` → "上升中继"；`四态 C` → "顶部结束"。
  `A 类／B 类` 这种**路径名**可以留（正文反复出现、读者能懂），**字母索引不留**
- **从规范文档抄表之前先过一遍这三条**——`08` 的对照表原本就带代号与"取数"列

## 七、已知坑（实测）

| 现象 | 原因 | 处理 |
|---|---|---|
| 目录页码印成了 PDF 物理页序（如"速览页"显示 4，实际应是 1） | 直接把 PDF 页索引当页码用了，漏减正文起始页偏移 | 已修：目录改用 `display_map`（正文页码 = 物理页 − 正文起始页 + 1） |
| 目录页码迭代不收敛 | 目录行数变化导致正文整体挪页 | 迭代上限 4 轮，未收敛会往 stderr 报警，提示目视复核 |
| 正文起始页定位不到 | 第一段带行内标记或跨行断开 | 按"目录后一页"估算并报警；正文首段尽量写成完整短句 |
| 中文被换成别的字体 | CSS 里写了"宋体""黑体"这类 macOS 上不存在的字体名 | 写 `Songti SC` / `Heiti SC` |
| 表格跨页断在行中间 | 默认允许行内断开 | `tr { break-inside: avoid }`，表头 `thead` 跨页重复 |
| 目录里某个标题留空 | 该标题文字在 PDF 里被断行 | 脚本会在 stderr 列出定位失败的标题名 |
| 封面被切成两页（数据基准跑到第二页） | 封面下半块原来用 `position: absolute; bottom: 0` 靠底，绝对定位的盒子会被分页切开 | 已修：封面改成 `display: flex; flex-direction: column`，下半块靠 `margin-top: auto` 顶到底部 |
| 页眉的日期与「（002408.SZ）」被撑得很空 | PyMuPDF 内置中文字体 `china-s` 把阿拉伯数字也按全角渲染，`2026` 占四个汉字宽 | 已修：盖印改用 `draw_mixed()`——数字与拉丁字母走 `helv`、中文走 `china-s`，宽度各自按字体实际字宽累加 |
| 目录里**部分页／分节页标题**留空，可同一标题在正文里明明存在 | 定位标题时只去掉了半角空格，标题里的全角空格「　」（U+3000）没归一化，比不中 | 已修：定位改为去掉全部空白（`re.sub(r"\s+", "", …)`）。写标题时用全角空格分隔是允许的，不必回避 |
