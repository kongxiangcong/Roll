| 仅参考设计 | [portfolio_service.py](https://github.com/ZhuLinsen/daily_stock_analysis/blob/ce364e457aab288863a5707e7b3df79786ad07f2/src/services/portfolio_service.py) 及必要追踪的 [portfolio_repo.py](https://github.com/ZhuLinsen/daily_stock_analysis/blob/ce364e457aab288863a5707e7b3df79786ad07f2/src/repositories/portfolio_repo.py) | 参考单事件事务、去重错误处理、成本分摊及重放思路；不继承其完整账户模型 |
| 不采用 | 当前提交路径与部分账本语义 | 不采用逐行部分入账、float 累计、缺费归零、物理删除纠错、将持仓数量作为券商可卖量等行为 |

具体差异与必要改造：

- 导入 `commit_trade_records` 循环调用 `record_trade`，每个事件各自事务提交，失败后可继续后续行。DSA **有单事件事务**，但不满足 Roll 一次确认的账户版本、资金、数量、费用和审计原子提交要求；还需绑定持久化草稿、确认请求幂等键及 expected_account_version。
- 导入 hash 已含源行号，但不含来源文件身份；trade_uid 候选混含合同/委托编号，不能视为可靠的分笔成交编号。需要文件身份、原行、规范化内容与券商标识语义共同支持去重，歧义进入预览。
- 数量、价格、费用及重放金额使用 float，缺费默认为 0，日期规范化丢失时分。Roll 需要精确数值、明确舍入、费用未知/暂估状态、原精度及时间精度。
- 事件具有日期和 created_at，但现有重放未提供 Roll 要求的历史获知时点读取；删除路径使用 session.delete。Roll 需要追加更正链、当前投影重建，以及冻结历史账户版本和决策输入。
- 当前服务中的现金与 available_quantity 不等价于券商可用/冻结资金和可卖量；分红按每股金额计算不等价于用户实际到账。初始存量、对账及外部委托未决事项需按 PRD 单独建模。
- 估值服务提供 provider 与部分缺失标记，但实时价格日期使用本地 date.today()，不能替代来源交易时点、received_at、原响应依据及单位/复权契约。本轮未验收 DSA 行情供应器本体。

必要依赖：导入服务直接依赖 pandas、仓库内证券规范化函数、PortfolioRepository 与 PortfolioService；账户服务继续关联配置、存储、SQLAlchemy，估值还可进入 DataFetcherManager/yfinance 路径。[该提交 requirements.txt](https://github.com/ZhuLinsen/daily_stock_analysis/blob/ce364e457aab288863a5707e7b3df79786ad07f2/requirements.txt) 使用 pandas>=2.0.0、sqlalchemy>=2.0.0、yfinance>=0.2.0、numpy>=1.24.0 等范围，并非 Roll 的锁定版本。若仅摘取 CSV 解析，可将依赖收敛为 pandas 与标准库，并改用 Roll 的证券标识契约，避免带入配置、存储及多市场取数链。

后续适配测试至少包括：编码与前导零、非法行与原件追溯；同文件重传/跨文件相似行/一委托多成交；重复确认和旧版本并发；批中失败及提交前后崩溃；金额与费用精度；费用未知后补；历史补录、追加纠错与双时间读取；初始存量不编历史、现金分类、可卖量未知及权益到账确认。对应 PRD AT-01—04、AT-09—14、AT-44—46、AT-49—50、AT-84 等，尚未执行。

## 首轮已答决定

1. **Q1 已确认**：以预定风险、资金占用和覆盖约束下的费用后收益改善为首轮主要经济方向。用户表示能接受风险；这不提供任何真实损失金额、暴露比例或资金授权，也不撤销原有硬约束。研究方继续负责把方向转换为可预登记的指标与改善幅度。
2. **Q2 已由 Q7 更新**：不再要求金额预算；前向观察最长 3 个自然月，具体见第三轮决定。保留任务超时、调用停止条件和实验结束规则，不追问费用数值。
3. **Q3 已确认并改变原 PRD 要求**：不需要交易时段持续覆盖，盘后复盘或手动唤起分析/同步可独立成立；用户可在任意交易时段查看当前趋势、量价关系和机会概率。与 BR-06/第 5 章的差异见 [ADR 0002](../adr/0002-on-demand-analysis-and-coverage.md)。不重复询问是否接受运行缺口。
4. **Q4 已由 Q7/Q9 更新**：最初同意先交工程与实验包、等待专业复核；随后用户明确没有专业人士、全依赖模型能力，不再安排人工复核人员或费用。Q9 已确认以自动验证、模型技术审阅和确定性资格检查替换人工独立复核的必备前提；当前方案不再等待专业人士到位，正式建议仍须满足下方已确认的证据与启用门槛。

## 第二轮已答决定

- **Q5 已确认：分析入口与时点**。按需分析以当前持仓与关注名单为范围，可分别展示当前可得报价/截至当时的成交数据，以及最近完成日线支持的趋势与量价描述。未收盘累计成交量不能与完整交易日成交量直接混作同口径特征；预测保留自己的数据截止时点和期限。无合格模型时显示概率未启用，试验数字仍在研究视图。不扩张为盘中重新训练或未验证即时概率。
- **Q6 已确认：按需分析＋盘后自动影子记录**。程序运行时，已冻结且可运行的影子实验在盘后检查点保存一次记录；不要求交易时段常开，遗漏检查点保留缺失。重复点击同一输入不增加样本，按需诊断与预登记盘后样本保留来源区别。不得事后补造前向预测，也不改变独立影子账本的连续性。

## 第三轮已答决定

- **Q7 后端与费用**：使用 Codex 与 DeepSeek，支持切换。用户已说明均已订阅，费用不需要本轮考虑；撤回此前 600 元总额/100 元每月提案，不将费用额度配置作为开始开发的前提。两后端的具体认证、工具能力、取消和结果契约仍需真实接入测试，不能由订阅推定验收通过。
- **Q7 前向期限**：从冻结模型首次实际归档起，最长 **3 个自然月**。到最终检查点只评价成熟标签；期限不足以支持结论时可为 INCONCLUSIVE，不因结果不利自动延长，也不把达到三个月视为验证通过。
- **Q7 复核资源**：没有专业人士，不安排独立人工复核费用，全依赖模型能力。该决定触及原 PRD EVAL-14/15、AT-53/75 等准入条款；Q9 已接受替代路径，见 [ADR 0003](../adr/0003-automated-validation-review.md)。
- **Q8 已确认**：首轮采用手工表单＋Roll 明确 CSV 模板。专用券商原始格式在有脱敏真实样例后另加支持，当前不以某券商专用导入为首轮验收前提。

## 第四轮已答决定与对齐结论

- **Q9 已确认：正式资格门槛**。以“可复现自动验证＋模型技术审阅＋确定性资格检查”替换必须由专业人士独立复核的前提；通过其余证据门槛后，可由用户在有效资金边界内启用正式建议。这是对原 PRD 正式准入制度的修改，不仅是删除费用项。
- 保留收益预测模型 G1—G7、冻结协议和证据、完整尝试登记、授权与部署门禁；确定性风险回退政策仍按其单独协议验收。Codex 或 DeepSeek 可承担技术审阅，ReviewRecord 记录后端与模型、材料指纹、复现范围、异议、处理依据和局限。模型赞同、后端一致或用户点击不能替代成熟结果与检验依据，研究 Agent 不能自签资格。
- 自动验证结论 PASS、模型技术审阅记录完整且阻断事项已按证据处理、确定性资格检查通过，才可进入用户资金启用；必需项无法核实则保持未通过或证据不足。界面与交付如实标注“未经人工独立复核”，不将模型技术审阅称为人工独立复核。FAIL 或 INCONCLUSIVE 可按冻结协议结束并交付验证工作，但不因此启用正式建议。
- Q1—Q9 的本轮产品选择已经闭合，没有遗留的人工复核人员、费用额度、持续在线方式或导入材料选择等待用户回答。后续由 to-spec 将已确认边界转为可实施契约，再由用户另行调用 to-tickets 和 implement。

相关 [组件核查记录](component-evidence.md) 已完成公开文档和静态代码检查，并包含一次有限公开日线探针。该记录区分文档/代码事实、设计参考、改造候选及尚未验收能力；旧费用/六个月提案已撤回。
