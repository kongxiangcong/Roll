# Domain Docs

本项目采用单上下文领域文档布局。

## 探索前阅读

- 根目录的 `GLOSSARY.md`：领域术语与定义。
- `docs/adr/`：与当前工作相关的架构决策。

文件不存在时直接继续。
术语或决策得到明确结论后，由 domain-modeling 技能按需创建文档。

## 文件布局

- `GLOSSARY.md`
- `docs/adr/0001-<decision-slug>.md`
- 后续 ADR 按编号递增。

## 使用统一术语

在任务标题、设计建议、假设和测试名称中，
使用 GLOSSARY.md 定义的领域术语。

需要的术语尚未定义时，判断它是否符合项目已有表达；
确有缺口时，将其记录为待领域建模的问题。

## 显式指出决策冲突

建议与已有 ADR 冲突时，指出相关 ADR，
说明冲突内容以及重新讨论该决策的理由。
