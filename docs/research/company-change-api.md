# Snapshot comparison and immutable change sets (06)

`CompanyResearch.freeze_research_context(ResearchContextCommand)` (`POST /api/company-research/contexts`) appends a child of the current same-company snapshot. It binds explicit completed `check_ids` and `quotes`; it does not call a provider or model. The old research core, valuation IDs and economic-review IDs remain pinned. The overall child `as_of` advances to the actual `context.bound_at`, while `research_basis_as_of` and `research_basis_generated_at` retain the old operating view's dates. Today-acquired quotes/checks cannot masquerade as information known at the older research cutoff. Parent snapshots remain unchanged.

A quote has `listing_id, shares, shares_unit, shares_as_of, price, currency, priced_at, share_refs, price_refs, price_basis`, and optional direct same-day `fx` with `rate,from_currency,to_currency,as_of,source_refs`. Each component matches one registered numeric same-company fact's exact value, unit, currency, scope and single-day period, with actual receipt/consumption information retained alongside source materials. `RAW_NOMINAL` prices require a fact explicitly named `raw_nominal_price`; adjusted or unknown prices remain visible evidence but cannot serve as nominal market prices. This is source/metadata consistency validation, not an independent factual audit. Existing sources whose adjustment basis is unknown cannot be relabeled nominal; no new provider was added. Quote/check requests are bounded to128 KiB,20 quotes and100 completed check IDs.

`CompanyResearch.compare_snapshots(ChangeSetCommand(old_snapshot_id,new_snapshot_id,idempotency_key,...))` (`POST /change-sets`) compares two explicit same-company snapshots and archives a `ResearchChangeSet` in `company_research_change_sets`. The name is the concrete06 implementation of the logical01 `company_research_changes` contract. Duplicate key+request returns the same immutable record; a different request with that key is refused. `GET /change-sets/{id}` reads the exact archived version. DAILY/REPORT consumers use its snapshot IDs and pinned review IDs; they must never search for an independent latest valuation.

The three categories are `OPERATING_EVIDENCE`, `PRICE` and `VALUATION_ASSUMPTION_OR_METHOD`. The first retains newly included/removed fact versions, both conflict sides, and support/counterevidence hypothesis revisions. `evidence_changed` means selected evidence references changed; re-versioning or reinterpreting the same facts only sets `hypothesis_revision_changed`. It does not prove an operating improvement or imply that omitted facts are false.

Price conditions hold the entire old cashflow path, bridge, share counts, discount rate, terminal growth and method fixed, solving the old and new market values' yearN+1 terminal FCFF requirements. All frozen identity listings must contribute separately, on one Shanghai date with matching currency/share scale and required direct FX. A/H shortcuts, changed class share counts, missing H quotes or incompatible quotation bases return `NOT_COMPARABLE` with both snapshot IDs and a reason. The price input never changes operating forecasts. A nonpositive terminal requirement retains the existing explicit04 status and empty revenue rows.

The multi-factor counterfactual saves `BASELINE` followed by fixed replacements `OPERATING_PATH → PRICE → VALUATION_PARAMETERS_OR_METHOD`, including every config, full cashflow output, market equity, model-equity-minus-market gap and step change. A separate parameter-only reference retains the operating/parameter interaction. Allocation depends on order and identifies no unique market cause. Incompatible method/source version, FCFF basis, units, currency, operating-source scope or horizon refuses subtraction. Original04 method files are unchanged. Expanded arithmetic always has diagnostic labels and cannot upgrade an economic review.

`presentation_purpose` defaults to `CURRENT_PRICING`. The immutable quick summary deliberately has no current-price scenarios;07 may obtain a fresh safe presentation from the pinned review when it needs current applicability. `BASELINE_RESEARCH` explicitly allows supported dated conditional scenarios from05, with its conditions/limitations; blocked/unreviewed views remain empty. Saved `pinned_presentations` are an audit of the creation-time assessment, not a later fresh current-pricing verification. Archived diagnostic arithmetic is not a current fair-value claim.06 also closes a necessary05 guard: consolidated FCFF requires consolidated driver provenance and relevant same-scope source/derived facts; segment margin/partial production cannot be applied to group revenue merely by relabeling a forecast. New reviews block this, and read-time presentation blocks incompatible older records without rewriting them.

`information_state` freezes one evaluation time, both knowledge/research dates, completed source outcomes, requested/completed/failed scopes, `last_checked_at` and separately `last_success_at`. Success+zero new materials means `SUCCESS_NO_NEW`; FAILED/PARTIAL never refresh last success or the old view's validation. Check age uses its completion timestamp and the explicit `source_max_age_seconds` policy (default7 days). Source-content age uses report-period end, with disclosure age separately reported and unknowns preserved as null. Acquisition/check dates never reset an old report's age. No new evidence is not proof of unchanged operations.

Contexts, change sets and exact comparison policy sources use the existing EvidenceStore/Backups archive authority. Backup validates snapshot/hash, pinned model/review/valuation, facts, quote component values/dates/currencies/scopes, materials and check references, even when a malformed record has been rehashed. `replay_change_set(id)` / `POST /change-sets/{id}/replay` recomputes frozen deterministic price/method/counterfactual results from the restored store; it uses no model/network and retains saved information-state evaluation time. Source drift refuses `COMPARISON_VERSION_UNAVAILABLE`; supplied source code is never executed. Full backup restores references and original archives;06 does not add a standalone JSON bundle importer.
