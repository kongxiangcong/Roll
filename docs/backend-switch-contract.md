# 取证后端选择与关联重试

2026-10-08；票13。设置只决定后续取证任务，正式交易判断仍未启用。对应[票级验收](../.scratch/roll-p0/evidence/13/acceptance.md)。

`GET /api/agents/settings` 返回当前后端、版本和保存时点；`POST /api/agents/settings` 接受 `backend` 与 `expected_version`，并以 SQLite 事务追加历史。过期版本返回409，其他模型或预算字段返回422。`GET /api/agents/settings/history` 保留先前选择。设置页保存后重载仍生效。

`POST /api/data/requests/{id}/agent` 根据保存的选择启动任务；旧 `/codex`、`/deepseek` 接口及页面选项仍可明确指定后端。每个新运行保存自身 UUID、实际后端、设置快照、selection_kind、固定模型、SDK/runtime版本、配置指纹、来源依赖指纹与预算。认证只在宿主启动任务时读取必要字段并私有传递，不进入运行JSON或模型上下文；后续设置/环境变化不改变已启动任务。

两后端及活跃同目录宿主共同遵守 SQLite 并发1，设置切换不能获得第二槽位。共用宿主边界为120秒、8次工具、6次取数HTTP、64KiB单响应、256KiB累计接收、子代理/递归/自动重试0；管理员只能缩小时限。取数子任务共享剩余时限、取消和HTTP/字节额度。Codex另限8次runtime操作，总调用22；DeepSeek另限5次模型HTTP，总调用19。`call_usage` 分别报告实际模型请求、runtime操作、宿主工具与所有取数子请求，并计算总调用；晚到输出不会发布。缺凭据/权限、缺工具、无依据、坏结构、超限、超时、取消、中断保持各自状态及缺口。

关联重试接受可选 `retry_of`，必须引用同一不可变 DataRequest 的已终结 agent 运行，问题经Unicode NFC及空白归一化后相同。问题变化应发起新任务，违规重试返回409。新运行使用当前后端设置，原运行状态、候选和审计完整保留；不会合并两个模型的输出。

重试只复用该直接前驱链中相同工具参数的宿主归档。宿主重新校验来源配置/解析代码依赖、原件SHA、子快照一致性及来源修订失效记录；候选输出不作为依据。复用保存原 `received_at/available_at`、来源revision和未知/陈旧状态，`REUSED_ARCHIVE` 指向原运行，结果字节仍受当前预算。损坏原件明确报缺口且不再次联网；依赖或来源修订变化标明重新核验原因后只在既有有限预算内取得新依据。后端选择本身不改冻结模型/资格；输入依赖变化继续使用既有 EvidenceResolver 的逐对象/事实组失效范围，不据此自动升级资格。

模型任务只暴露取证工具及固定来源GET，无账本、资金授权、门槛、资格、券商登录或下单撤单写通路。开发技能、参考AGENTS/SKILL、文件文字和网页内容只能作为不可信材料；Codex使用独立空home/cwd与已核验关闭的指令/技能能力，DeepSeek不装载技能或内建工具。真实注入验收的网页是明确METHOD来源，模型任务是真实SDK/提供方；审计区分模型拒绝和实际被宿主拒绝的工具尝试，不把未尝试的写操作称为实际403。
