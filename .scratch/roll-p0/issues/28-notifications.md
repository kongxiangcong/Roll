# 28: 有效通知与当前状态深链

**What to build:** 用户在站内和一个已配置的自用外部渠道接收有意义的提醒；重复信息合并，重要新增风险可升级，旧消息链接打开当前状态和失效原因。

**Blocked by:** [27 · 暂停、撤回、到期与恢复](27-suspend-revoke-recover.md)。

**Status:** ready-for-agent

**Completion:** pending

**Primary acceptance:** AT-24。

**References:** [规格](../spec.md) ID-11/12/13/17/18、Testing Decisions；[任务计划](../ticket-plan.md)；[目录与实施约束](../project-layout.md)。验收场景原文以 [PRD](../../../ashare_market_decision_prd.md) 为准，补充追踪 UI-07、EVAL-05/06/16 的送达边界与执行时间依据。

## Acceptance criteria

- [ ] 从已持久化且符合条件的事实/动作产生 SQLite 出站记录，经发送、失败/未知结果、站内查看及深链查询形成完整路径；按需要行动、需要同步/恢复、阶段摘要区分。重启和重试不重复创建业务通知，不承诺外部供应商无法保证的严格恰好一次送达。
- [ ] 动作通知出站记录引用动作版本；各类通知分别保存发送尝试、渠道受理、可证明的送达和已读时间及证据来源，供 26/29 关联执行时间链。发送成功或渠道受理不推定用户收到、已读或已操作；无回执或渠道不支持时对应状态/时点保持未知，晚到回执保留实际时点与系统获知时间，不改写旧发送记录。
- [ ] 去重依据动作、状态与严重程度；普通波动、重复新闻、文字变化不产生新提醒。重大新增风险或关键失效可越过普通冷却，常规重复仍合并；摘要频率是上限而非强制每日发送。正常未运行不持续制造故障通知。
- [ ] 将通知去重/合并、重复发送风险、失败及送达未知接入 15 的运行审计，保留出站、发送尝试和渠道回执的对应关系；分别统计业务通知与传输尝试，不把一次重试必然当成用户收到两条。联验真实内部出站链的重复/未知记录、异常定位及重启后的计数一致性，外部无法证明的结果继续保持未知。
- [ ] 每条通知有有效期。动作通知出队前重新核对最新动作、账户、相应资格、资金和依赖状态；事实、同步与恢复提醒检查自身时效和适用状态，不以模型 grant 存在为前提。过期入场机会仅归档；发送期间撤权保存失效事件并按需追加提醒，已发出的内容不可偷偷改写，不声称可以消除外部传输竞态。
- [ ] 深链查询当前状态，能解释旧卡已到期、被替代或撤回；旧消息不能建立新有效意向。研究内容不进入行动通知；客观风险提醒不能夹带未经授权的卖出/持有建议。
- [ ] 选定一个实际可配置渠道并登记版本、认证、内容/长度、超时重试与送达语义；在用户配置的自用验收目标上完成真实受控发送、失败与当前状态链接检查，不联系第三方。无配置或不可达时站内功能继续并明确需打开查看；外部真实验收未完成不得记通过。
- [ ] 经 FastAPI 与真实 SQLite/出站记录覆盖 AT-24、撤权竞争、冷却/过期、失败/送达未知；真实进程在出队前后终止并恢复，检查业务记录及供应商未知结果处理。与 26 联验有发送记录但无送达/已读证据、延迟回执和延迟回报的时间链，供 29 验证报告不推定用户响应；浏览器打开旧通知验证当前状态。固定响应检查与实际渠道证据分别记录。
- [ ] 遵守目录与实施约束；仅引入本票实际需要的模块、接口和校验，保留 PRD 必需控制，不新增假设性兼容层、审批或泛化框架。用单进程与 SQLite 出站记录解决当前需求，不预建多渠道消息中台。
