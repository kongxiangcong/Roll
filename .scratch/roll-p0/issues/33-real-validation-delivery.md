## Acceptance criteria

- [ ] 以实际起点、协议终点和归档记录确认结束依据；未到结束条件时本票保持未完成，记录实际日期和再次执行条件，由后续显式调用继续，不将工程会话结束视为研究完成。
- [ ] 核对全部确认性样本、拒绝机会、缺失、修订关联和全部尝试；只评价按冻结规则已成熟的结果，未成熟项单列，不补造漏日预测，不为不利结果、缺席或等标签成熟延长期限。
- [ ] 对真实材料执行冻结方法的自动验证，形成完整 validation_manifest 与 G1—G7 实际结果；工程稳定、测试时钟、历史回放及合成凭证均不能替代真实 G7。
- [ ] 通过已验收后端完成真实模型技术审阅，保存材料指纹、复现检查、异议及处理证据；未核实的必需项保持未通过或不足，文字赞同不覆盖统计与门槛结果。
- [ ] 实验、验证、审阅与能力状态分别呈现，验证包记录窗口、支持度、成本/延迟、统计限制、适用域与“未经人工独立复核”；真实 FAIL 或 INCONCLUSIVE 也能构成完整交付，不要求必须 PASS。
- [ ] 必需验证或审阅未完成时保留具体缺口，本票不得据此结项；完整 PASS/FAIL/INCONCLUSIVE 的交付通过应用查询、原始归档与导出包相互核对，证据注明实际环境/版本和执行日期。
- [ ] 交付验证不自动激活正式能力，不修改原实验期限或门槛；后续正式启用或明确未启用由 34 按实际结论处理。
- [ ] 遵守目录与实施约束；仅引入本票实际需要的模块、接口和校验，保留 PRD 必需控制，不新增假设性兼容层、审批或泛化框架。
