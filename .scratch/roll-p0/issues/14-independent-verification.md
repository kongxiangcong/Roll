# 14: 关键复盘的独立来源核验

**What to build:** 用户从影响结论的疑点进入关键复盘，查看决定性事实的原始依据、来源独立性及已核验、冲突或证据不足的结果，并复用未发生版本变化的核验。

**Blocked by:** [08 · 换源、局部降级与证据修订](08-source-fallback.md)。

**Status:** ready-for-agent

**Completion:** complete

**Primary acceptance:** AT-79、AT-80、AT-85。

**References:** [规格](../spec.md) ID-06—08、ID-17、ID-20、Testing Decisions 1、3—4、6—7；[目录与实施约束](../project-layout.md)。

## Acceptance criteria

- [x] 用户指定、足以改变重大盈亏/失效/规则修订归因的疑点，或关键字段冲突才触发关键复盘；普通记录单源基本检查仍可完成，不把每日摘要都升级成多源审查。
- [x] 仅核验决定结论的事实，寻求至少两个原始依据独立且口径可比的来源；同上游转载、不同网页域名和多个 Agent 重述只算同一依据。
- [x] 每次核验保存所用证据版本、独立性依据、字段原值、时点/口径比较和核验结果；单一权威原始来源可作单源事实，不能显示多源核验完成。
- [x] 关键价格、日期等冲突先核对时点与口径；无法消除时保留各方原值并暂缓相关归因，其他部分继续。不投票、不平均、不挑有利值，证据不足与存在冲突分开。
- [x] 独立且可比的一致证据产生可追溯核验记录，同证据版本后续复用；来源修订后旧核验不继续被当作当前已核验。核验不赋予模型资格，也不替用户确认真实到账或成交。
- [x] 从 FastAPI、真实 SQLite/归档到关键复盘页面验证同源识别、冲突、缺口和复用，保留真实来源样例及确定性回放证据；可直接用接口/已存证据完成，不强制依赖 11/12 或多个模型后端。
- [x] 遵守目录与实施约束；仅引入本票实际需要的模块、接口和校验，保留 PRD 必需控制，不新增假设性兼容层、审批或泛化框架。
