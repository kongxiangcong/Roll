# 01: 首次建立真实账户镜像

**What to build:** 用户从手工填写当前现金和存量持仓开始，先查看差异、再确认入账，获得可查询的持久化回执，并在“今天”看到真实账户镜像与确认时点。

**Blocked by:** None (can start immediately)。

**Status:** ready-for-agent

**Primary acceptance:** AT-01、AT-02、AT-04、AT-44。

**References:** [规格](../spec.md) ID-01—05、ID-13、ID-17—19、Testing Decisions 1—3、额外边界组合；[PRD](../../../ashare_market_decision_prd.md) 1.3、ACC-01—04、12.1 Account；[目录与实施约束](../project-layout.md)。

## Acceptance criteria

- [ ] 按目录设计落地首个可启动的 FastAPI、React、SQLite 切片和对应测试；只创建当前路径实际使用的目录，未来模块随责任票添加，不生成空目录大脚手架或另拆只搭架构的任务。记录实际运行环境、所需依赖和可重复启动方法，默认仅本机访问。
- [ ] 固定初始输入的字段、精度、舍入、序列化及未知值契约；现金账面余额、券商可用/冻结、持仓和可卖数量分别表达。金额与数量使用精确数值，不能以二进制浮点累计资金。
- [ ] Account.permission_profile 记录用户明确确认的账户交易权限、适用市场/板块、依据和确认时点，分别表达已开通、未开通与未知；存量持仓、添加关注或系统支持某板块都不证明用户已开通权限。权限草稿不生效，确认及后续变更保存版本和历史，沿用账户确认的幂等、旧版本冲突与审计规则；API 和页面验证三种状态及变更后旧版本可查询。06 使用该事实区分规则适配，25/26 再联验正式动作及执行意向门禁，未知权限不妨碍先记录真实资产。
- [ ] 初始存量以 INITIAL_POSITION 建立基线，保留来源与实际确认时点；未知的买入时间、费用、可卖量和基线前收益保持未知，不补造历史。手工草稿及差异预览不改变正式账户。
- [ ] 用户确认后，账户事件、当前投影、账户版本、审计和回执在同一受控写入中持久化，成功回执可再次查询。HTTP 入口调用业务用例，后续后台入口可复用同一规则，无第二套确认逻辑。
- [ ] 同幂等键同内容重试返回原回执，即使原确认已推进版本也不改报冲突；同键异内容拒绝，两个页面的旧版本提交返回当前版本与差异，均不部分入账或覆盖已确认事件。
- [ ] “同步账户”到“今天”的浏览器流程可完成预览、确认和查询回执，首页显示确认时点、待核信息与正式判断未启用；不从未知状态推导 HOLD 或卖出数量，不要求配置取证后端才能建立账户。
- [ ] 在 FastAPI 应用入口使用真实 SQLite 与隔离归档验证精度、幂等和竞争；以真实进程在提交前后及回执后注入崩溃，重启证明已确认事件/回执不丢失、不重复。逐项记录输入、预期、实际、环境与证据；后续 26/27 负责已有动作的真实失效联验。
- [ ] 遵守目录与实施约束；仅引入本票实际需要的模块、接口和校验，保留 PRD 必需控制，不新增假设性兼容层、审批或泛化框架。
