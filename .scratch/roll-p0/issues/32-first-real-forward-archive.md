## Acceptance criteria

- [ ] 启运前核对真实数据来源、完整冻结协议/候选/政策、执行和缺失安排、部署指纹及备份/恢复可用性，记录版本和环境；按协议处理已有硬失败，不能把“尚无真实 G7”改写为 G7 已通过。
- [ ] 在实际合法检查点取得所需真实输入，并在未来结果发生前可靠保存首个前向预测及动作/拒绝原因；通过应用查询与归档指纹证明真实写入，禁止用 fixture、历史导入或事后回填替代。
- [ ] 首次成功归档生成不可随意移动的实际 forward_started_at、forward_deadline、实验/样本身份与材料引用；真实终点不晚于三自然月，重复执行返回原记录而不重复起算。
- [ ] 页面显示实际启动状态、当前缺口与预定终点，交付程序在线时的盘后记录方式、正常离线缺失规则、备份位置和恢复方式；不承诺持续盘中覆盖，不因程序关闭自动延长期限。
- [ ] 未到窗口、输入不完整、来源失效或启动条件不符时，保留未完成及具体条件/后续执行时间；不得伪造归档或留开发代理驻留数月轮询，也不由本票创建桌面定时任务。
- [ ] 留存真实接口/归档/查询与去重证据，并与工程模拟证据分开。首个有效归档成功且启运记录完整即可完成本票，正式能力仍关闭；M4 动作与通知未完成不构成本票额外前置。
- [ ] 遵守目录与实施约束；仅引入本票实际需要的模块、接口和校验，保留 PRD 必需控制，不新增假设性兼容层、审批或泛化框架。
