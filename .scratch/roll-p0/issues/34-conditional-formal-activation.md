# 34: 条件性正式启用或明确未启用

**What to build:** 依据真实验证结论、完整工程交付和当前有效条件进入有限正式使用，或明确记录正式能力仍未启用；两条分支都向用户说明实际结果。

**Blocked by:** [33 · 协议终点的真实验证交付](33-real-validation-delivery.md)；[31 · 本地交付与工程验收收口](31-engineering-delivery.md)。

**Status:** ready-for-agent

**Completion:** pending

**Primary acceptance:** 无新增 AT；本票负责真实条件性启用或明确未启用的交付证据。

**References:** [规格](../spec.md) ID-10、ID-12、ID-16、ID-18、ID-19、ID-21；Testing Decisions 的主要边界 1、4、5、7；[PRD](../../../ashare_market_decision_prd.md) EVAL-15—17、RUN-03—06、18.3；[目录与实施约束](../project-layout.md)。

**Start condition:** 真实验证交付与工程交付均完成；PASS 分支还须用户实际确认有效资金启用及当前账户事实等必需条件。ready-for-agent 是分诊标签，不等于条件已满足，发布本票不签发资格。

## Acceptance criteria

- [ ] 核对 33 的实际结论、完整证据与审阅记录，以及 31 的工程验收和未解决问题；不将测试凭证、工程完成或两个模型赞同作为实际正式资格。
- [ ] PASS 分支通过受控资格服务重新检查部署/模型/政策指纹、证券/频率/期限与动作范围、当前账户/数据和真实有效资金授权；用户实际启用后才登记当前 CapabilityGrant，不替用户猜测资金或代填启用确认。
- [ ] 实际启用前核对 27 所需监测方法、输入/范围、检查点、维护窗口、到期与受限/复核条件均来自当前冻结协议和有效授权，实际部署可查询监测及处置记录、接收 26 的真实结果并按 29 的报告契约呈现偏差。没有历史正式运行数据时明确尚无样本；以配置、记录入口与工程验收证明监测链可用，不宣称长期真实正式监测或未来有效性已经通过，不为补样本要求用户实际交易。
- [ ] 正式能力页面显示有效范围、到期/暂停/撤回条件、资金授权和“未经人工独立复核”；实际端到端检查只覆盖批准范围内的建议与手动结果流程，不执行券商交易，不为验收要求用户真实下单。
- [ ] FAIL 或 INCONCLUSIVE 分支核实正式能力关闭，实际应用仍能进行账户同步、事实观察和许可研究；记录明确“未启用”及证据后可完成本票，不降低门槛或要求再试直到 PASS。
- [ ] PASS 但资金启用、账户事实或其他必需条件尚缺时，记录当前受限原因与待满足条件，不能标为正式启用已通过；不自动延长原实验，也不把缺少专业人士作为额外阻塞。
- [ ] 通过应用查询、持久化资格/审计记录及关键网页流程保存实际启用或未启用分支证据；分开报告工程交付、验证交付和正式状态。任何仍缺必需检查的分支保持未完成，不以总括“上线成功”掩盖。
- [ ] 遵守目录与实施约束；仅引入本票实际需要的模块、接口和校验，保留 PRD 必需控制，不新增假设性兼容层、审批或泛化框架。
