## Acceptance criteria

- [ ] 在实际 Windows 环境按交付说明，从干净安装路径使用锁定依赖启动 React/FastAPI 与一个后台任务进程；记录版本、配置位置、运行目录、启动/停止、升级备份和恢复操作。浏览器关闭不终止仍运行的服务；默认本机访问，密钥和私有运行数据不进交付源码。
- [ ] 由五个一级入口走通已实现的初始账户/CSV、确认与回执、无交易声明、按需/仅盘后分析、部分成交/待结果、暂停恢复及隔离研究流程；展示当前真实能力和使用限制，不要求用户配置统计方法。安装与页面证据来自交付版本。
- [ ] 根据任务计划逐一核对 90 项 AT 的责任票及输入、期望、实际、环境/版本与日志/回放/截图依据；分别列确定性应用、真实进程恢复、关键浏览器、实际来源、Codex、DeepSeek、外部渠道和统计/前向证据。失败、未执行与部分覆盖明确列出，不用测试数量或一次连通替代业务通过。
- [ ] 同时按 P0 需求追踪核对 14 项 BR、125 项编号 P0 要求、10 项数据不变量及所列无编号正文/附录要求，逐项关联主责任票的实际证据与通过/部分/失败/未执行状态。没有独占 AT 的要求也须有行为验收；市场与事件数据、账户交易权限、损失口径、利息/待结算项、执行偏差、持续复核和 G5 补充样例均须有结果。仅引用 PRD 或填写“已覆盖”不能关闭条款。
- [ ] 追踪表由主责任票维护，跨票联验在调用方存在后补齐；核对 07→15 事件展示、01/06/10/09→25/27 权限与额度、26/28→29 偏差报告、17/20/21/26→27 监测处置及 15/26/28 的运行审计。未实现项回责任票；32—34 的真实时间证据保留实际状态，不因本票工程完成提前标通过。
- [ ] 仅对安装环境差异及未被现有证据覆盖的跨票风险补集成：账户确认与动作失效、模型/网络失败不阻塞确认、最新资格与通知、恢复锁与研究不补造。按真实设备/数据/缓存条件核对首页 P95 ≤ 2 秒、单笔确认 P95 ≤ 2 秒、30 股加 5 指数的本地评估 P95 ≤ 30 秒；不无理由重复全部测试。
- [ ] 按目录方案核对实际布局、依赖和运行数据归属；没有未来空骨架、无调用抽象、纯转发层、假想兼容分支或未经票据要求引入的基础设施。新增抽象有当前用途，保留精确账本、资格检查和恢复锁；只需简短说明，不要求额外长篇设计报告。
- [ ] 第三方摘取记录包含实际文件、固定版本、许可证/版权、必要依赖、语义修改和适配结果；仅参考的外部技能与示例未进入生产 Agent。确认开发配置与生产后端权限分开，两个后端独立验收。
- [ ] 未完成的既有 P0 功能或验收回到责任票处理，本票不接收“后续优化”来替代先决交付。31 完成仅表示工程交付；32—34 的真实启运、协议终点验证和条件启用另留状态，不能以工程完成关闭真实 G7 或宣称整个规格已完成。
- [ ] 遵守目录与实施约束；仅引入本票实际需要的模块、接口和校验，保留 PRD 必需控制，不新增假设性兼容层、审批或泛化框架。
