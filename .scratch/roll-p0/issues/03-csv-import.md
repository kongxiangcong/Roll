# 03: Roll CSV 草稿与整批确认

**What to build:** 用户下载明确的 Roll CSV 模板、上传初始状态或已支持事件，检查逐行错误、歧义和合计差异，再整批确认或保留待修订草稿。

**Blocked by:** [02 · 同步真实成交与暂估费用](02-actual-fills.md)。

**Status:** ready-for-agent

**Primary acceptance:** AT-46。

**References:** [规格](../spec.md) ID-04、ID-17、ID-20—21、Testing Decisions 1—4 与账户确认组合、Further Notes 外部资产追踪；[目录与实施约束](../project-layout.md)。

## Acceptance criteria

- [ ] 冻结并随应用提供有版本的 Roll CSV 模板，覆盖初始现金/持仓及当前已支持事件；页面提供下载、上传、逐行错误/歧义和合计变化预览。未确认文件不改变正式账户，不承诺尚无脱敏样例的券商原始格式。若 04/05 先完成，则本票覆盖其已支持事件；若后完成，由新增事件的责任票同步扩展已有模板，不为此改变执行依赖。
- [ ] 保存文件身份、原始行、编码及数值原始精度，证券代码前导零不丢失；缺失、非法字段、未知费用和含指令文字分别按数据契约处理，不把缺失费用当零。
- [ ] 同文件重传可找到原草稿/确认结果；跨文件相似行和一委托多成交保留明确来源，可靠分笔标识与确认幂等共同防重复，不以同价同量判定重复。
- [ ] 一次整批确认中的事件、资金、持仓、版本、审计和回执全部成功或全部不提交；批中错误、旧版本和幂等内容冲突产生清楚原因与可修订草稿，不能继承逐行部分入账语义。
- [ ] 评估 DSA 的 CSV 解析改造候选时记录具体摘取组件、检查版本 ce364e457aab288863a5707e7b3df79786ad07f2、MIT 许可及版权、实际必要依赖和语义修改。原依赖 pandas、内部解析/配置/存储与 SQLAlchemy 不默认全部引入；账户服务只参考，是否摘取须以适配结果决定并分类登记。
- [ ] 文件内“忽略风险规则”等文字只能成为原始材料或字段错误，不能进入生产指令、增加工具、改变账户确认权限或资格规则；草稿确认仍由受控服务执行。
- [ ] 在真实 SQLite 上从 FastAPI 上传/确认/查询验证编码、前导零、重复与歧义、未知费用、批失败、并发和进程崩溃；浏览器贯穿模板上传、差异预览和回执。分别记录解析候选适配与 Roll 业务验收证据，不把 DSA 自身测试算作 Roll 通过。
- [ ] 遵守目录与实施约束；仅引入本票实际需要的模块、接口和校验，保留 PRD 必需控制，不新增假设性兼容层、审批或泛化框架。
