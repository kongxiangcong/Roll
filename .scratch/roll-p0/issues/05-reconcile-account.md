# 05: 补录更正、账户声明与对账

**What to build:** 用户在需要使用账户时声明变化或无变化，补录漏记、追加更正，并分别核对现金、券商可用、持仓和可卖量；页面解释当前差异及系统当时知道什么。

**Blocked by:** [04 · 确认资金与权益变动](04-cash-corporate-actions.md)。

**Status:** ready-for-agent

**Primary acceptance:** AT-12、AT-13、AT-14。

**References:** [规格](../spec.md) ID-04—05、ID-11—12、ID-17、Testing Decisions 1—3、账户确认及权限竞态组合；[PRD](../../../ashare_market_decision_prd.md) ACC-07、ACC-10—15；[目录与实施约束](../project-layout.md)。

## Acceptance criteria

- [ ] 每项补录保留 effective_at 与 recorded_at；昨日事件可重建当前投影，但历史查询依当时已知时间返回旧状态，已发布快照仍指向其原账户版本。
- [ ] 更正以可追踪的冲正/替代链追加，保留原件、原因和回执，不物理删除事件、直接改余额或静默改旧历史。重放完整事件后当前投影与实际查询一致。若 03 已完成，新增可导入事件同步进入有版本的 CSV 模板及整批确认验收；否则由 03 按已支持事件接入，不复制确认规则。
- [ ] 无变化声明记录明确范围与截至时点；数日未使用后只在依赖账户的用途检查所需声明，不要求补每日打卡，独立市场观察不因账户声明不足被禁用。
- [ ] 对账分别展示账面现金、券商可用/冻结、数量、可卖量及权益差异，不猜哪方正确；未知可卖量保持未知，矛盾和未决事项可见且不显示假正常。
- [ ] 对账包含 04 的利息、分红、税费和待结算应收/应付，分别核对确认依据、未结余额与实际到账/扣款；待到账不视为可用现金，也不因现金未增加就重复补记收入。以利息漏记、分红部分结算和税费更正样例验证差异、追加确认和历史查询，后续 09 验证估值/收益呈现。
- [ ] CONFIRMED_AS_OF、UPDATE_PENDING、RECONCILE_REQUIRED、STALE_DECLARATION 在服务查询和页面一致，说明受限用途与下一步事实处理；状态不足不变成 HOLD 或确定可执行数量。
- [ ] 更正/补录与账户版本推进仍是同一原子确认链，保留使旧依赖失效所需版本语义；26/27 出现真实动作后必须联验已有动作在确认事务中失效，本票不以替身提前宣称完整动作联验通过。
- [ ] 经 FastAPI 和真实 SQLite 验证双时间、追加更正、幂等、并发旧版本与投影重建；浏览器完成无交易声明和差异处理。记录输入、期望、实际及关键页面证据，旧快照查询须可复现。
- [ ] 遵守目录与实施约束；仅引入本票实际需要的模块、接口和校验，保留 PRD 必需控制，不新增假设性兼容层、审批或泛化框架。
