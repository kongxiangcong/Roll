# 29: 研究查看、导出与跨出口隔离

**What to build:** 用户在现有五入口内的折叠研究视图查看和导出实际、历史、连续影子及账户条件诊断，分别理解平台策略结果、实际用户结果与执行偏差；任何出口都不会把试验结果包装成正式建议。

**Blocked by:** [28 · 有效通知与当前状态深链](28-notifications.md)。

**Status:** ready-for-agent

**Primary acceptance:** AT-61。

## Acceptance criteria

- [ ] 公共查询、研究页面与导出均保留 ACTUAL、HISTORICAL、SHADOW、ACCOUNT_CONDITIONAL、实验/运行标识、版本、时点、依据和资格来源；各自汇总和曲线不合并为真实盈亏。查看模型诊断无需新增一级门户。
- [ ] 连续影子展示冻结基线及持续资金/持仓变化；一次账户条件诊断不能冒充连续策略。被拒机会的成熟反事实评分只进入预测/筛选诊断，不叠加为受资金约束的策略收益；研究缺口、未成熟及实际结论明确可见。
- [ ] 查询、折叠研究页面和导出分别报告平台策略结果、实际用户结果与执行偏差。依据 26 的动作/成交关联和 28 的通知时间证据，对照冻结方案解释延迟、价差、数量/费用差异及未执行原因，标明比较时段、资金/持仓与执行条件是否可比；各项延迟明确起止事件，送达/已读或成交关联未知时不推定响应时间、不强行归因。实际收益减影子收益不能直接称为执行造成的损益，诊断不改写旧影子成交、历史收益或模型结论。
- [ ] 以影子高概率结果尝试通过 API、文字摘要、导出、曲线、通知和深链进入“今天”，服务端均保留试验来源并阻止正式买卖内容、执行意向入口与行动推送；深链转向隔离研究视图。不能仅靠页面标签防止越权。
- [ ] 正式视图仍可展示合格实际动作和客观事实；用户自主参考试验在券商交易后，允许原账户确认链记录真实成交，但不追认原研究建议为合格、补发资格或改写原实验历史。
- [ ] 从 FastAPI 入口连接真实 SQLite、归档、20 的连续影子、25/26 的动作/意向和 28 的出站记录完成 AT-61 跨出口联验；浏览器覆盖研究展开、导出及旧研究深链，逐个核查来源与无正式操作入口。测试替身不可替代已有真实内部调用链。
- [ ] 与 26/28 联验延迟成交与更晚回报、部分/未执行、费用后补、送达/已读未知、无关联成交及真实账户偏离影子的样例，核对三类报告和时间链可回到原依据；同输入重放结果一致，补录实际事实不改变旧影子。报告在应用查询、页面与导出中一致保留可比限制和未知项，工程样例不称为真实用户行为分布或 G7 证据。
- [ ] 报告可追溯到 27 已保存的监测方法、输入、检查点、偏差/不足及受限或复核记录；同一实际事实的展示与监测口径一致，诊断展示本身不新增统计判定点或签发资格。以一项冻结执行假设失配和一项证据不足样例联验查询/导出，不要求等到真实用户发生该情形才完成工程验收。
- [ ] 记录各出口输入、期望、实际与对应证据；合成高概率/资格材料限定隔离测试环境，导出不包含密钥或不必要的私人原件。未经人工独立复核与验证未完成状态如实显示。
- [ ] 遵守目录与实施约束；仅引入本票实际需要的模块、接口和校验，保留 PRD 必需控制，不新增假设性兼容层、审批或泛化框架。复用已有查询契约和页面，不建设新的研究门户或通用报表平台。
