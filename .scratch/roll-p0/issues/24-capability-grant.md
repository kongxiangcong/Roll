# 24: 确定性资格签发与范围核验

**What to build:** 由受控服务检查验证门槛、技术审阅、部署范围和用户资金启用，满足当前条件才持久化能力授权，页面说明可用范围或具体拒绝原因。

**Blocked by:** [10 · 资金授权与默认关闭的正式能力](10-funding-boundaries.md)；[23 · 模型技术审阅与验证交付](23-technical-review-delivery.md)。

**Status:** ready-for-agent

**Primary acceptance:** AT-53、AT-73、AT-75。

**References:** [规格](../spec.md) ID-02、ID-12、ID-16、ID-17；Testing Decisions 的主要边界 1、5、7 及“权限竞态”；[目录与实施约束](../project-layout.md)。

## Acceptance criteria

- [ ] GrantCapability 入口检查候选自身冻结协议的必需门槛、技术审阅完整性与阻断项处理、部署指纹、适用范围、有效资金启用以及当前账户/数据条件；缺项逐项解释，PASS 或模式开关本身不签发资格。
- [ ] CapabilityGrant 及状态事件持久化能力/动作/证券/市场/频率/期限、执行假设、模型政策与代码依赖、账户及风险授权版本、审阅依据、生效/到期与撤回条件；查询准确区分技术资格、资金授权和运行健康。
- [ ] 仅受控应用服务能登记资格，研究或审阅 Agent 无可调用签发工具；模型宣称通过、两个后端赞同或用户单独点击均不能越过缺失证据。直接调用服务端入口同样受到检查。
- [ ] 部署模型/政策/代码指纹或范围与证据不一致时拒绝授权并留审计；范围扩展不继承旧资格。风险回退政策若被申请，按自身协议核验，不作为收益模型资格签发的强制前置。
- [ ] 无专业人工复核但自动验证 PASS、模型技术审阅及全部启用条件齐全时允许通过确定性检查；呈现“经自动验证与模型技术审阅，未经人工独立复核”，不得残留额外人工复核门槛。
- [ ] 经 FastAPI 应用入口、真实 SQLite 和关键页面验证合格、缺证据、自签、部署不匹配与资金未启用路径；正向工程场景使用明确隔离的合成凭证，生产加载/签发入口拒绝这些凭证。
- [ ] 本票交付资格机制与工程证据，不伪造真实研究资格；实际研究完成与条件性正式启用由 33、34 留证，不产生券商交易能力。
- [ ] 遵守目录与实施约束；仅引入本票实际需要的模块、接口和校验，保留 PRD 必需控制，不新增假设性兼容层、审批或泛化框架。
