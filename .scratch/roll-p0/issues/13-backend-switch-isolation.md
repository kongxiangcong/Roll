## Acceptance criteria

- [x] 设置页可切换后端；两种真实后端分别启动任务并在运行中更改设置，证明原任务的模型、配置和 SDK/runtime 指纹不变，后续运行采用新配置。切换不改冻结量化版本或资格，输入依赖变化则报告需重新核验的范围。
- [x] 中断后重试生成关联运行，保留原状态与证据；不能混合两后端输出冒充同一运行。相同问题优先复用仍适用的归档依据，不反复搜索直到得到偏好的答案。
- [x] 宿主统一控制总调用、递归深度、并发、时长及取消，子任务共享边界；缺工具、无依据、坏结构、权限失败和超时明确区分，有限结束而不无限派发。
- [x] 模型/新闻工具失败时已有合格输入支持的功能继续；必要缺口允许有限补查但未解决就局部暂停，不填值。与 02 实际并行验证模型任务超时/取消不阻塞账户确认，记录环境与确认 P95 ≤ 2 秒。
- [x] 检查真实暴露的服务端接口、工具与配置，无券商下单、撤单、登录、交易口令托管或网页交易能力；取证进程无账本、资金授权、门槛或资格直接写入通路，仅隐藏按钮不算通过。
- [x] 以开发技能、参考 AGENTS/SKILL、上传文件和网页材料中的越权指令测试两个真实后端，生产运行不自动装载这些指令，越权失败并留审计；不为隔离新增插件发现平台或多角色金融裁决。
- [x] 通过 FastAPI、真实 SQLite/归档与设置/任务页面核对运行身份、重试和状态；真实接入证据与固定回放分别记录。审计默认本地且脱敏，不泄漏完整账户或密钥、不自动上传云 trace。
- [x] 遵守目录与实施约束；仅引入本票实际需要的模块、接口和校验，保留 PRD 必需控制，不新增假设性兼容层、审批或泛化框架。
