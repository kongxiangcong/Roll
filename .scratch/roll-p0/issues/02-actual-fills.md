# 02: 同步真实成交与暂估费用

**What to build:** 用户录入实际买卖成交，确认现金与数量变化后查询到账本事件、持仓和费用待核状态；与建议相反或没有对应建议的真实成交同样能够同步。

**Blocked by:** [01 · 首次建立真实账户镜像](01-account-baseline.md)。

**Status:** ready-for-agent

**Primary acceptance:** AT-03、AT-08、AT-09、AT-40。

**References:** [规格](../spec.md) ID-04—05、ID-11、ID-17—19、Testing Decisions 1—3 与财务守恒/运维容量组合；[目录与实施约束](../project-layout.md)。

## Acceptance criteria

- [ ] 手工成交草稿展示证券、实际时间、方向、数量、原始成交精度、费用状态与预计资金/持仓变化；用户确认后通过既有原子确认入口入账，并可在页面和历史查询中找到回执。
- [ ] 优先使用可靠分笔成交标识；同价同量的不同成交分别保留，一委托多成交不按委托号合并。缺少可靠标识时保留来源与歧义，不悄悄合并实际交易。
- [ ] 逆建议、超量、离线发生或无建议的真实成交可记录；无明确动作对应关系时标记关联未知，不由风险规则拒收已发生事实，矛盾原始输入保留并进入待核。
- [ ] 未知费用允许先确认真实成交，标明暂估及有依据的保守占用，净收益/对账保持待核；后补费用追加调整事件，不归零、不覆盖原费用记录，重放后资金一致。
- [ ] 精确验证 100,000.00 元买入 300 股、10.00 元/股、5.00 元费用后现金为 96,995.00 元、取得成本为 3,005.00 元，并组合部分卖出与费用调整验证数量和金额守恒。
- [ ] 使用 FastAPI 应用入口、真实 SQLite、持久化查询与关键同步页面验证上述行为，重试和失败无重复或部分入账；记录真实设备、数据规模与档案配置，证明单笔确认 P95 ≤ 2 秒。
- [ ] 为 08/13 保留确认性能与外部补查的集成验收入口；当真实外部获取和模型任务存在后，由对应票证明其超时不阻塞本票确认，不能仅凭当前没有联网任务就声称该组合已通过。
- [ ] 遵守目录与实施约束；仅引入本票实际需要的模块、接口和校验，保留 PRD 必需控制，不新增假设性兼容层、审批或泛化框架。
