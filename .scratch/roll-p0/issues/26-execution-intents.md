# 26: 执行意向、部分成交与未决委托

**What to build:** 用户从有效动作进入“准备操作”，在自行向券商操作后同步实际结果；页面清楚区分意向、外部待结果、部分成交、已同步与未执行，并保留余量和资金约束。

**Blocked by:** [25 · 有资格的当前动作与联合预算](25-current-actions.md)。

**Status:** ready-for-agent

**Primary acceptance:** AT-05、AT-06、AT-07、AT-49。

**References:** [规格](../spec.md) ID-04/05/10/11/12/13/17、Testing Decisions；[任务计划](../ticket-plan.md)；[目录与实施约束](../project-layout.md)。验收场景原文以 [PRD](../../../ashare_market_decision_prd.md) 为准，补充追踪 EVAL-05/06/16 的实际执行时点与偏差要求。

## Acceptance criteria

- [ ] 经 FastAPI 应用入口与浏览器完成当前动作 → 准备操作 → 意向记录 → 已操作待同步/实际成交关联/未执行原因 → 最新账户及余量查询。创建意向时核对最新动作、账户、grant、资金版本及事实声明；幂等重试返回原结果，旧版本不得绕过检查。
- [ ] 创建意向时重新核对 01 的当前账户 permission_profile，与 25 的市场规则/资格/资金检查一致；覆盖动作生成后账户权限变更、未知或未开通的情形，限制依赖该权限的新意向，保留已发生成交和外部待结果事实。接入 15 的运行审计，未完成意向、部分同步及旧动作失效可定位到实际记录；重试不重复计数，不能把未决事项记为零。
- [ ] “准备操作”仅记录 ExecutionIntent 和明确临时占用，现金及真实持仓保持不变；“已操作”但细节未知持续显示待同步。不包含券商登录、下单、撤单或网页代操作能力。
- [ ] 实际成交经原账户确认链入账，ActionFillAllocation 显式保留一对多/多对多分配；关联不明保持未知。同价同量不误并，不强行归因绩效；逆建议、超量或无关联实际成交仍可记录事实。
- [ ] 以动作版本、通知和实际成交的显式关联保存可追溯时间链：动作发出、可证明的送达/已读、准备操作、实际成交发生及用户回报/系统获知分别记录时点、来源和未知状态，不用回报时间冒充成交时间或推定已读。保存实际数量、价格、费用及未执行原因供 29 对照冻结方案；通知侧发送与回执由 28 接入，本票先验证已有时间与未知状态，不提前认定通知联验完成。
- [ ] 建议 500 股而实际仅成交 300 股时只入账 300 股；原未执行部分按新账户与当前条件重新评估。账户事件、费用、版本、审计和依赖旧版本的现存动作失效在同一受控事务链提交；失败不留下已入账但动作仍有效的中间状态。
- [ ] 同一外部委托在券商可用资金中已反映的冻结与平台预留通过关联标识去重，不能重复扣建议预算或净资产；无法确认占用归属时明确待核，不静默释放资金。
- [ ] 动作到期、暂停或用户不继续操作不等于券商已撤单。外部委托待结果继续存在，不自动认定未成交或释放全部占用；已同步部分、未决部分和未执行原因分别可查。
- [ ] 以真实 SQLite 的应用测试及关键浏览器流程覆盖四项 AT，并与 01/02/05 联验实际现存动作失效、重试与竞争；在提交边界注入失败并重启查询，证明事实与失效记录一致。延迟回报、部分成交、未知费用和关联不明样例保留输入及实际时间，供 28/29 接入后完成时间链与偏差报告联验；保留输入、期望、实际、版本与证据，不把仅有替身回调当联验完成。
- [ ] 遵守目录与实施约束；仅引入本票实际需要的模块、接口和校验，保留 PRD 必需控制，不新增假设性兼容层、审批或泛化框架。
