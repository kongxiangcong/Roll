# 19: 透明候选、校准与模型冻结

**What to build:** 完成一个透明量价候选与必要基线，在允许的开发及校准窗口取得时间外预测，保存模型和校准器指纹，让用户在研究视图查看概率定义、支持度和限制。

**Blocked by:** [18 · 日线执行模拟与成熟标签](18-daily-execution-labels.md)。

**Status:** ready-for-agent

**Primary acceptance:** AT-41。

**References:** [规格](../spec.md) ID-06、ID-10、ID-14、ID-16、ID-21；Testing Decisions 的主要边界 1、5、6；[目录与实施约束](../project-layout.md)。

## Acceptance criteria

- [ ] 按 M0 真实覆盖证据确定首轮事件、主期限和特征，实施一个透明候选及必要基线，不扩展无界候选搜索、复杂组合或分钟级模型；开发参数与失败尝试全部进入 17 的记录。
- [ ] 训练、拟合与校准按时间隔离，处理标签跨窗、同日多股和重叠期限；只用当时可得的已完成日线，修订、陈旧或缺失输入按协议处理，不使用未来事实。
- [ ] 本票仅访问获准的开发/校准证据，禁止查看封存最终测试。冻结模型、校准器、特征与相关代码/数据指纹；明确完整实验还须由 20 补齐并冻结研究政策后，才能进入 21 的确认性检验。
- [ ] ForecastBundle 持久化证券、事件/期限、观察截止、模型/校准/执行假设、费用和收益情景、适用域、支持度及不确定性；LLM 自述信心不进入概率计算，也不与不同事件/期限直接平均。
- [ ] 研究视图可比较必要基线、查看开发窗口的可靠性与支持度，并显式呈现不足；只显示 Brier 改善或更高胜率不能宣称资格通过。
- [ ] 压力或输入支持检查未通过的候选留在实验区，原有正式版本及资格不变；没有生产资格时保持正式能力关闭，冻结产物不自动发布动作。
- [ ] 经 FastAPI 应用入口和真实持久化验证模型产物、输入版本、失败隔离及同输入结构化预测重放；保留真实开发数据范围、环境和模型版本证据，将测试样例与实际研究结果分开。
- [ ] 遵守目录与实施约束；仅引入本票实际需要的模块、接口和校验，保留 PRD 必需控制，不新增假设性兼容层、审批或泛化框架。
