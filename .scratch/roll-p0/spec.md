# Roll P0：账户镜像、按需观察与受控量化验证

Status: ready-for-agent

日期：2026-10-07  
规格版本：1.1
依据：PRD V1.3、GLOSSARY、已接受的 ADR 0001—0003、实现对齐 Q1—Q9。  
范围：M0—M3 的工程与验证能力，以及满足资格时才启用的 M4；不是实施任务清单。`ready-for-agent` 表示本规格可进入拆票与实施，不表示实验协议、数据接口、后端适配、软件或策略已经验收。

1.1 补齐 PRD 覆盖审查确认的票级要求：最小市场与事件数据、账户交易权限、损失计算口径、利息与待结算项、执行偏差、持续复核及 G5 分项验收。沿用 34 票拆分、现有依赖和 90 项 AT 主责任；正文要求与证据另按 [P0 需求追踪](requirements-traceability.md) 收口，本次修订不表示任何功能已实现。

## Problem Statement

A 股个人用户已有真实持仓，但手工记录、行情观察和分析工具相互割裂。用户很难知道系统掌握的账户是否准确、分析使用了哪个时点的数据、当前是否有可执行的合格动作，以及实际交易后应如何同步结果。大量报告和相互矛盾的观点增加了操作负担。

用户不需要交易时段持续覆盖，也不愿承担统计方法选择或技术验收。用户希望只在需要时打开系统，或盘后进行复盘，在事实可靠、能力有效时获得明确判断；没有充分依据时能继续使用账户与观察功能。缺少专业人工复核人员，不能让整个产品永久等待人员到位，也不能将模型赞同当作通过验证。

Roll 目前只有需求、领域与对齐文档，没有生产实现、锁定依赖或可复用的现有测试入口。外部组件的定向检查仅提供适配依据，需要在建设中证明账户正确性、数据时点、取证权限、研究隔离和资格控制。

## Solution

提供一个本地优先的 React Web 应用。用户通过手工表单或 Roll CSV 模板维护单个人民币普通现金账户，先查看草稿及差异，再确认入账。账户始终注明确认时点；建议、执行意向与实际成交分别保存。

默认进入“今天”，展示当前能力、账户确认与数据截止时点、实际运行状态、合格动作或客观待处理事项。支持任意时点按需分析、手动复盘及程序运行时的盘后记录。当前可得报价和量价事实，与最近完整日线支持的概率分别标注时点。没有合格模型时明确显示交易判断未启用，研究数字留在隔离研究视图。

以 Python/FastAPI 模块化单体承载账户、数据、决策和验证流程；SQLite 保存正式状态，Parquet 保存适合归档的行情与研究数据。OpenAI Agents SDK 承载受控取证，完整 Codex 任务后端与 DeepSeek 模型路径可切换，分别通过实际接入验收。模型返回证据或技术审阅记录，不能直接修改真实账户、风险边界或能力授权。

从一个透明候选与必要基线开始研究。前向阶段从冻结模型首次实际归档起最长 3 个自然月，缺失照实记录，允许 FAIL 或 INCONCLUSIVE 结项。只有自动验证、模型技术审阅、确定性资格检查及用户资金启用均满足条件，才在已验证范围提供正式建议，注明“未经人工独立复核”。用户始终自行在券商交易，Roll 不具有交易写能力。

## User Stories

1. 作为已有持仓的个人用户，我希望从当前现金和持仓建立真实账户镜像，以便立即使用系统而不必补造历史成交。
2. 作为个人用户，我希望现金余额、券商可用资金、冻结资金和可卖数量分别展示，以便知道哪些是资产、哪些当前可以支配。
3. 作为个人用户，我希望看到账户确认截至时点和待核状态，以便了解系统实际掌握的账户范围。
4. 作为个人用户，我希望通过手工表单录入真实成交，以便在券商操作后准确同步。
5. 作为个人用户，我希望使用明确的 Roll CSV 模板批量导入初始状态与已支持事件，以便减少重复录入。
6. 作为个人用户，我希望确认前看到现金、数量和旧动作失效的差异预览，以便发现输入错误。
7. 作为个人用户，我希望重复点击确认仍只入账一次并能找回回执，以便放心处理网络重试。
8. 作为使用多个页面的用户，我希望旧账户版本提交被明确拒绝并显示差异，以便避免覆盖更新。
9. 作为个人用户，我希望同价同量的两笔真实成交能分别保留，以便不会因简单去重丢失事实。
10. 作为部分成交的用户，我希望只同步实际成交数量并重新评估余量，以便不会被记成全量成交。
11. 作为已向券商提交委托的用户，我希望结果未知时持续显示外部委托待结果，以便动作到期不会掩盖潜在占用。
12. 作为没有照建议交易的用户，我希望仍可记录相反或额外的真实成交，以便账户镜像始终反映事实。
13. 作为尚不清楚成交费用的用户，我希望先确认成交、标明费用暂估并在以后调整，以便已发生交易不会整笔缺失。
14. 作为发生出入金的用户，我希望外部投入与投资盈亏分别计算，以便存款不会被误报为收益。
15. 作为收到分红或送转的用户，我希望确认实际到账后再更新账户，以便公司公告不会被当成我的到账事实。
16. 作为发现漏记或错记的用户，我希望追加补录或更正并保留原记录，以便能解释过去与当前状态的差异。
17. 作为需要对账的用户，我希望分别核对现金、可用资金、数量和可卖数量，以便定位具体差异。
18. 作为个人用户，我希望估值、成本、费用和收益说明口径及未知历史，以便不会误读陈旧报价或不完整绩效。
19. 作为可卖数量未知的持仓用户，我希望仍能看到风险事实并被提示先核对数量，以便不会得到假定可执行的卖出数量。
20. 作为个人用户，我希望持仓自动纳入观察，并能添加少量关注对象，以便只跟踪自己的范围。
21. 作为持有尚未适配板块或范围外证券的用户，我希望资产完整可见并显示能力不足，以便系统不会套错交易规则。
22. 作为持仓超过默认容量的用户，我希望系统提示容量而不隐藏资产，以便保持完整账户视图。
23. 作为个人用户，我希望在任意时点唤起市场分析，以便按自己的节奏查看趋势和量价关系。
24. 作为只在盘后使用的用户，我希望只做盘后复盘也能完成日常流程，以便无需维持交易时段在线。
25. 作为盘中查看行情的用户，我希望当前报价和日线概率各有截止时点，以便不会把旧预测误认为即时胜率。
26. 作为个人用户，我希望未通过资格的概率仅在研究视图呈现，以便不把试验结果当成正式交易建议。
27. 作为个人用户，我希望未完成的日线和不完整成交量不会被用于完整日线模型，以便观察尺度保持一致。
28. 作为偶尔关闭程序的用户，我希望恢复后看到实际缺口而非不断收到故障提醒，以便按需使用不变成每日打卡。
29. 作为在休市日使用的用户，我希望系统正确识别交易日并允许历史查看和账户同步，以便不会生成虚假的当日盘中记录。
30. 作为遇到数据缺失的用户，我希望已知部分继续展示并明确哪些能力受限，以便局部问题不会伪装成完整结论。
31. 作为发起关键复盘的用户，我希望影响结论的疑点事实获得独立来源核验，以便了解结论的证据基础。
32. 作为查看证据的用户，我希望同源转载不会被算成多个独立依据，以便不会被表面的多来源误导。
33. 作为查看冲突事实的用户，我希望各方原值、时点和未解决问题被保留，以便模型不会投票或挑选有利值。
34. 作为个人用户，我希望取数工具可替换且口径转换可追溯，以便单个供应商失效不会改变事实含义。
35. 作为复盘历史的用户，我希望能重放当时已知的账户与数据，以便事后补录不会被包装成事前判断。
36. 作为个人用户，我希望能选择 Codex 或 DeepSeek 承担取证任务，以便使用已有的后端服务。
37. 作为遇到模型或联网失败的用户，我希望任务有限结束并返回证据和缺口，以便不会无限等待或收到编造内容。
38. 作为账户所有者，我希望外部取证只收到必要信息，以便完整账户、资金授权和密钥不会进入无关上下文。
39. 作为账户所有者，我希望网页、上传内容和开发技能不能给生产 Agent 增加权限，以便正式状态保持受控。
40. 作为日常用户，我希望首页优先显示当前能力、待处理事项和最近变化，以便不必先阅读长篇研究报告。
41. 作为具备正式能力的用户，我希望动作说明对象、数量、价格范围、有效期和主要不确定性，以便知道当前允许做什么。
42. 作为准备手动交易的用户，我希望“准备操作”只记录执行意向，以便不会在真实成交前改变账户。
43. 作为从旧通知打开动作的用户，我希望服务端重新检查当前权限和条件，以便不会按失效卡片执行。
44. 作为已有持仓风险的用户，我希望新增机会数量限制不会遮蔽存量风险，以便优先处理已有暴露。
45. 作为暂时没有合格机会的用户，我希望系统允许不新增仓位，以便不会为了产生建议扩大股票池或放宽门槛。
46. 作为当前能力不足的用户，我希望未知、不可卖和未启用状态不会被写成 HOLD 或判断型 WAIT，以便事实限制与市场判断不混淆。
47. 作为选择不执行建议的用户，我希望保留原动作及未执行原因，以便不把行为差异直接算成模型亏损。
48. 作为日常用户，我希望重复行情、重复新闻和措辞变化不触发新通知，以便减少噪声。
49. 作为错过提醒的用户，我希望过期入场机会只归档、重大新风险仍可升级，以便不会收到过时机会或漏掉重要变化。
50. 作为个人用户，我希望监控、影子和正式能力清楚分离，以便模式按钮不会被误认为获得授权。
51. 作为资金所有者，我希望自己确认资金用途、暴露与损失暂停条件，以便模型不会替我猜测承受金额。
52. 作为个人用户，我希望能分别暂停新增风险、停止模型建议或停止全部监控，以便按实际目的控制服务。
53. 作为已暂停或撤回能力的用户，我希望旧动作立即失效且不会因价格反弹或回滚程序恢复，以便撤回决定持续生效。
54. 作为本地用户，我希望在有持久化变化的运行日自动备份并可手动导出，以便了解可恢复到哪个时点。
55. 作为恢复备份的用户，我希望先核对账户和当前资格再恢复正式动作，以便旧 ACTIVE 记录不会越过最新撤回。
56. 作为维护者，我希望确认成功后进程崩溃重启仍保留事件和回执，以便持久化承诺可验证。
57. 作为研究任务的执行者，我希望先冻结候选、范围、基线、方法和结束规则，以便结果出来后不能改写原要求。
58. 作为研究任务的执行者，我希望根据实际数据覆盖制定时间窗、样本与最小改善目标，以便不让普通用户临场选择统计参数。
59. 作为验证记录的使用者，我希望失败、中止、参数尝试和封存结果访问全部可查，以便结果不会只展示赢家。
60. 作为验证记录的使用者，我希望训练、校准、测试和标签成熟严格按时间隔离，以便避免未来信息和重复样本制造优势。
61. 作为概率结果的使用者，我希望概率绑定明确事件、期限和执行假设，并有校准与样本支持，以便不把模型信心当成胜率。
62. 作为研究结果的使用者，我希望实际、历史回放、连续影子和账户条件诊断分别汇总，以便不同结果不会混成真实收益。
63. 作为影子实验的执行者，我希望影子现金与持仓从冻结基线连续演化，以便真实补录不会重置试验成绩。
64. 作为研究结果的使用者，我希望被拒机会和重叠机会的诊断保留现金约束与用途区别，以便不会用无法同时成交的收益拼成策略业绩。
65. 作为影子实验的执行者，我希望首次实际前向归档才开始计时，重复运行不增加样本，以便记录对应真实发生的研究过程。
66. 作为项目使用者，我希望前向研究最迟在 3 个自然月内结束且只评分成熟结果，以便研究不会为了通过而无限延长。
67. 作为项目使用者，我希望 FAIL 或 INCONCLUSIVE 也能完成有证据的验证交付，以便工程成果无需等待盈利结论。
68. 作为缺少专业复核人员的用户，我希望由可复现自动验证和模型技术审阅支持资格检查，以便无需等待不存在的人力。
69. 作为正式建议的使用者，我希望模型审阅意见不能代替门槛证据或自行签发资格，以便正式能力有可检查的准入依据。
70. 作为正式建议的使用者，我希望看到“未经人工独立复核”及适用范围、到期和撤回条件，以便理解当前资格的实际含义。
71. 作为切换取证后端的用户，我希望正在运行的任务保持原配置、后续任务使用新配置，以便证据来源不会被静默混合。
72. 作为维护者，我希望新证券、版本、执行政策或范围的扩展重新检查适用性，以便不会自动继承不匹配的资格。
73. 作为日常用户，我希望在五个一级入口内完成查看、同步和设置，以便不必承担模型选择或多角色观点裁决。
74. 作为维护者，我希望能定位数据、模型、授权、账户和通知各自的故障并查看脱敏审计，以便修复局部问题而不抹除历史证据。

## Implementation Decisions

### ID-01 产品范围与默认技术路线

采用独立 Roll 仓库、Python/FastAPI 模块化单体、React Web、一个后台任务进程、SQLite 正式状态与版本化文件归档。Parquet 用于适合归档的行情、特征与研究数据；不得形成另一份能覆盖真实账户的权威来源。浏览器关闭不终止仍在运行的服务，宿主关闭期间无监控能力。

P0 为单用户、单人民币普通现金账户、A 股现货多头。沪深北按市场、板块与证券类型分别记录适配范围；未适配的真实持仓仍可记录和展示。默认在线持仓与关注合计 20 只以内，性能基线为 30 只个股与 5 个指数；超额不隐藏资产。指数只作背景与基准，不形成指数产品交易建议。所有持仓自动纳入名单，新增关注不自动取得模型适用资格，不从全市场替换或补齐机会。

本规格不重新进行框架选型。只有具体的 PRD、环境或正确性冲突证据才允许提出最小替代方案，并记录代价。数据接入、依赖组合和规则支持通过实际验收确定，默认路线不等于组件已通过。

### ID-02 模块与写入职责

模块在同一应用内组织，通过类型化命令和查询协作，不拆成微服务。账户与资格的正式写入集中在受控应用服务；HTTP 与后台任务共享相同业务检查，不各自实现一套规则。

| 模块 | 职责 | 不可越过的边界 |
|---|---|---|
| AccountLedger | 草稿确认、事件、投影、对账、双时间及持久化回执 | 不从建议或预测生成账户事实 |
| MarketData / EvidenceResolver | 事实请求、来源适配、取证委派、原始归档和关键复盘核验 | 不补造缺值，不直接给买卖判断或修改账本 |
| FeatureStore / ForecastService | 冻结特征、已登记预测与校准、支持度与适用性 | 不使用未来修订、未完成日线或修改风险授权 |
| DecisionEngine | 确定性门禁、联合预算、规则与唯一当前动作 | 不让模型自由文本覆盖约束 |
| MonitorScheduler | 按需、盘后、可选阶段、恢复与幂等 | 不把补取数据冒充实时覆盖或前向预测 |
| ActionCenter | 动作版本、执行意向、实际结果关联与通知出站 | 不具有券商下单、撤单或登录能力 |
| EvaluationLab / ShadowLedger | 冻结实验、完整尝试、回放评分、独立连续影子 | 不改真实镜像，不签发自己的资格 |
| ValidationRegistry / CapabilityGuard | 自动验证、模型技术审阅、资格检查及授权生命周期 | 不以文字同意覆盖证据，不绕过用户资金启用 |
| AuditService | 输入输出指纹、证据依赖、运行与操作追踪 | 不事后改写已发出的判断 |

取证和审阅任务使用受控读取与结果提交契约。资格签发、真实账户确认和风险授权不作为这些 Agent 的可调用工具；仅隐藏前端按钮不满足该边界。

### ID-03 存储与数据对象

SQLite 保存正式业务状态、版本、任务、审计和通知出站记录。原始依据先持久化，再建立规范化事实和快照引用；归档清单与内容指纹用于校验。事务不能引用尚未可靠保存的必需附件；备份和恢复校验数据库与归档清单的一致性。

| 对象组 | 必需对象及语义 |
|---|---|

### ID-04 账户草稿、确认与精确账本

首轮输入为手工表单与 Roll CSV 模板，模板覆盖初始现金/持仓和已支持事件。解析必须保留原文件身份、原行和原始精度；缺失、非法值、去重歧义和预计变化先进入草稿与差异预览。初始存量用 INITIAL_POSITION，不补造历史买入、税费或基线前收益。

正式事件包括 BUY_FILL、SELL_FILL、CASH_IN、CASH_OUT、DIVIDEND、TAX、FEE、SHARE_CHANGE、CORRECTION、RECONCILIATION。用户确认才允许入账；一笔确认包含的资金、数量、费用、账户版本、审计与所需动作失效必须原子完成，持久化成功后返回可再次查询的回执。

利息属于经确认的投资收入，不能归为外部净投入；04 固定其事件分类、到账与更正口径。已确认的待结算应收/应付单独记录依据、金额、发生与结算状态，到账时关联结清，避免重复计算收益或现金；未到账金额不进入券商可用资金。09 分列待结算项及其估值口径，提供利息、未到账和实际结算的守恒样例。

确认带 idempotency_key 和 expected_account_version。同幂等键且内容相同的重试返回原业务结果和回执，不因该确认已经推进账户版本而改报旧版本冲突；同键不同内容返回冲突且不重新执行。其他旧版本提交返回当前版本及差异，不静默覆盖。优先使用可靠的分笔成交标识，缺失时使用来源文件、行号与规范化内容；同价同量不充分证明重复，一委托多成交不能按委托号合并。

金额使用定点十进制或最小货币单位，数量按证券规则使用精确数值，不用二进制浮点累计资金。保留原成交精度，在明确的计费、展示或规则边界舍入。具体字段精度、舍入与序列化契约由 M0 固化并用守恒样例验证，不能以数据库默认类型代替业务规则。

与建议相反、超量或离线期间发生的真实成交仍可入账。矛盾输入隔离待核且保留原件，不由风险规则拒绝记录事实。费用未知时确认成交并标明暂估，使用明确的保守占用、保持正式净收益与对账待核；后续追加费用调整，不默认为零。

### ID-05 双时间、资金口径与一致性状态

AccountEvent 保留 effective_at 与 recorded_at。历史补录按实际发生时间重建当前投影，并使依赖旧账户版本的未执行动作失效；过去决策仍指向当时已知版本，不用后来事实覆盖。更正追加冲正/替代链，禁止物理删除旧事件或无依据改余额。

现金账面余额、券商可用、可取、冻结、执行意向预留与授权现金保留额分别建模。净资产不重复扣冻结款；建议预算为已确认券商可用资金，减去尚未包含其中的执行意向占用，再减授权现金保留额。同一外部委托按关联标识去重，已反映在券商可用资金中的冻结不再扣除。成本分摊可重放且金额守恒，出入金不计投资收益；百分比收益注明现金流调整方法。报价分别带时点，缺报价或停牌的最近价只能作显式陈旧估值。

| 账户状态 | 外部行为 |
|---|---|
| CONFIRMED_AS_OF | 展示确认时点，在该用途所需声明和其他门槛满足时计算数量 |
| UPDATE_PENDING | 保留草稿、待回报或外部未决委托，抑制重复占用资金/数量的建议 |
| RECONCILE_REQUIRED | 列明现金、可用资金、数量、可卖量或权益差异，不输出假定确定余额的新增风险数量 |
| STALE_DECLARATION | 在依赖账户的入口请求事实确认；独立市场观察继续，不要求补齐未使用日的声明 |

实际权益到账必须由用户确认，网页只能生成待核事项。可卖量未知不推成全部可卖；未知也不代表安全或应继续持有。进入新增风险执行意向前，检查自上次同步后有无其他成交、委托、资金与权益变化。

Account 的 permission_profile 由用户确认，记录账户交易权限的适用范围、依据、时点及版本，未知状态明确保留。它与市场规则适配、模型资格和资金授权分别核验；系统支持某板块不表示用户已开通。01 登记事实，06/25 检查未开通、未知和权限变更对相关新增动作的限制；真实持仓及已发生成交仍正常记录，不能通过省略权限检查生成可执行建议。

### ID-06 事实契约、时点与版本

固定来源按实际支持的对象、范围、粒度、深度、延迟/时间戳语义、权限、单位/复权及失败表现登记。临时网页按次保存证据，不要求建设供应商管理平台。来源名不能替代事实本身的时点和口径。

07 的实际取数覆盖 PRD 6.1 的最小数据组：名单与基准日线/报价、预先固定的宽基及少量相关行业指数、当前异常与公司行动、名单内公告/业绩/重大事项。事件规范化后保留类型、对象、实际可得时点、来源与修订，生成可追溯的 Observation/RiskAlert，15 接入按需/盘后展示。逐组记录实际取得或缺失状态，未查到不等于没有事件；真实样例与固定响应分别验收。使用既有证据契约，日常可单源，不扩展成全市场新闻流或特殊股历史库。

每条外部事实至少包含对象/证券、字段与值、对应交易日或事件时间、来源标识/链接、获取时间、原文片段或响应依据；适用时包含 published_at、上游时点、received_at、available_at 及其依据、时间精度、币种、单位、调整口径、revision_id、raw_hash。只有日期不补时分，财报报告期不当披露时点，批次最新时间不当每只证券的新鲜证明，缓存包装时间不替代实际采集时间。

原始可交易价用于成交与资产计价；调整价用于明确版本的特征与收益研究。单位转换有依据，股/手、元/万元不能猜测。缺失、真实零成交、休市、停牌、占位与获取失败分别编码。日线携带 completion_state，未完成输入不得进入要求完整日线的模型。原始价因公司行为跳变与账户实际权益到账分别处理。

来源切换先检查对象、日期、单位、复权和字段定义，保存转换或阻断理由，不静默拼接。重放读取已归档证据，补查只形成新的依据或修订；旧运行不能重新联网替换输入。证据修订使依赖的派生结论失效并保留原因，不删除旧结论。

### ID-07 质量降级与关键复盘

数据状态区分 HEALTHY、DEGRADED、BLOCKED_NEW_RISK、MONITORING_UNAVAILABLE。正常未启动由运行覆盖表达，不能被持续报告为服务故障。新鲜度按用途、交易日和已验证动作条件判断，不设置对全部输入通用的分钟门槛。

可选材料缺失时，已有合格输入支持的功能继续；模型必需特征缺失时仅能使用已验证且输入齐全的替代版本，否则暂停相应能力。不能临时删除特征后继续宣称原模型合格。联网补查异步、有停止条件，不阻塞用户确认账户。

普通按需、盘前或盘后记录允许一个可追溯来源经基本检查使用。仅用户指定重点复盘、可能改变重大盈亏/失效/规则修订归因的疑点，或足以影响结论的关键字段冲突，触发关键复盘。只核验决定结论的事实，已核验且版本不变可复用。

关键复盘寻求至少两个原始依据独立、口径可比的来源，结果为已核验、存在冲突或证据不足。相同上游转载、不同域名和多个 Agent 重述不增加独立来源数。冲突先检查时点与口径，保留各方原值，不投票、不平均、不挑有利值；无法解决时暂缓相关归因，其他部分继续。单一权威原始材料可作单源事实，但不能标称多源核验完成。

### ID-08 受控取证、后端切换与模型技术审阅运行时

OpenAI Agents SDK 用于受控取证任务；Codex 接入完整任务运行时，DeepSeek 接入受控模型路径。两者共用事实请求与证据输出契约，分别验收，不把“API 能通”“有订阅”或官方文档能力升级为实际工具适配通过。实现阶段选择并锁定具体 SDK/runtime、模型和认证方式，以本机与真实接入证据判断是否需要额外桥接。

DataRequest 明确对象、日期或截止时点、所需字段/问题、用途及技术限制。每个 RetrievalRun 固定 backend、model、config_fingerprint、sdk_runtime_version、实际工具、状态、证据与缺口。配置切换影响后续任务，运行中任务不变；中断重试保留关联的新运行记录，不静默拼接两后端输出。取证后端切换不改变冻结量化模型或自动授予资格，若改变模型必需输入或依赖则重新检查适用性。

宿主统一限制任务时长、调用总量、递归深度、并发和取消，子任务共享边界。返回部分证据与缺口是合法结果；坏结构、缺工具、权限不足、取消和超时明确记录，未经检查的模型回答不能成为已验证事实。相同问题优先复用仍适用的证据，不反复搜索直到出现希望的答案。

生产任务使用独立工作目录和明确允许的工具/配置，不自动继承开发 AGENTS、SKILL、个人技能、参考示例或正式数据写权限。网页和上传内容作为不可信材料，不能改变宿主权限。只传必要对象和问题，不把完整账户、资金授权或密钥放入取证上下文；默认本地审计，不自动上传含账户信息的云 trace。只读文件限制不能替代对联网工具副作用的控制。

模型技术审阅可使用同样的后端配置与运行留痕机制，但拥有独立的冻结材料读取及 ReviewRecord 输出契约；它不承担多角色金融裁决，也没有能力签发工具。

### ID-09 按需调度、日线与实际覆盖

统一使用 Asia/Shanghai，交易日和阶段来自适用交易所日历及规则版本，不按工作日猜测。按需分析和仅盘后使用均为完整使用路径；盘前、开盘与盘中阶段为可选，不要求三阶段齐全。初始盘后时间可采用 PRD 建议，但实验的盘后检查点必须在运行前冻结，触发时间不证明数据已经完成。

按需分析可返回当前可得报价、累计成交与事件，以及最近完整日线支持的预测；分别保存和展示观察时点、数据截止、预测生成与期限。盘中累计成交量不混作完整日线特征，不将昨日预测改称今日即时胜率。条件观察不等于预测更新，更不触发盘中自动重训或调阈值。

程序运行且冻结实验可运行时，在盘后检查点实际归档一次影子预测。任务以交易日、阶段、截止时点、账户/影子、数据及所属版本限定身份，持久化去重；重试不得重复动作、样本或通知。按需诊断与确认性盘后样本保留来源区别，相同输入重复点击不能增加研究样本或 PASS 判定点。

确认性样本另有独立于任务重试和数据快照的唯一标识，按实验与预登记检查点/交易日限定。同检查点的新快照、账户版本或重试可生成关联运行与修订/诊断记录，但必须保留原归档和处理依据，不增加确认性样本；没有合格归档时按冻结协议记录缺失。不能通过重新生成任务键重复计数。

实际记录通过前后快照关联，无新信息标记无实质变化。正常关闭或休眠期间保留缺口，恢复可补取事实与历史复盘，过期机会只归档，未曾实际归档的预测不得补为前向证据。缺失期间影子状态按冻结缺失政策处理而不重置账本；恢复本身不追发失效动作。

### ID-10 预测、规则与确定性动作

正式主链为冻结特征、简单模型、样本外校准、交易结果分布、账户与规则约束、唯一当前动作。首轮一个透明量价候选和必要基线，20 个交易日为主期限候选；具体事件、期限、执行价、退出规则和方法在 M0 依据数据冻结，不在本规格虚构统计阈值。不同事件、期限与 LLM 信心不能直接平均。

ForecastBundle 绑定证券、观察截止/频率、期限、模型及政策版本、入场窗口、费用、退出与可交易假设、适用域、支持度与收益情景。优先研究固定日线交易方案的费用后收益是否为正及较差/中位/较好情景。无法从日线确定的盘中顺序按冻结保守或区间口径处理，不择有利顺序；未成交、部分成交和到期未退出都有结果定义。

正式动作按次执行固定检查顺序：能力与模式 → 系统/数据 → 账户与资金授权 → 证券规则 → 单独合格风险回退政策 → 模型适用性 → 存量与新增机会 → 联合预算 → 发布前版本及权限复核。任何硬失败不得由其他评分抵消。

Decision 分别保存 action 与 account_status、data_status、model_status、execution_eligibility、capability_status，绑定 basis_type、grant_id/version、风险授权、账户/影子、数据、模型与规则版本。BUY、ADD、HOLD、REDUCE、EXIT 和判断型 WAIT 均属于需资格的正式动作；无资格输出 UNQUALIFIED 与原因，客观事实用 Observation / RiskAlert。无法交易不自动等于 HOLD，无机会但条件全部合格时才可形成有依据的 WAIT。

新增风险同时受费用后优势、已验证机会阈值、资金、损失暂停口径、单票与总暴露及数量规则约束。跳空、不可成交和人工延迟须进入压力假设，止损距离不代表亏损保证。仅当前有限名单进行联合分配，采用冻结优先级与稳定排序，默认同时最多一条新增入场意向；存量风险单独展示。反向动作与冷却条件属于同一经验证政策，不随每次报价任意翻转。

### ID-11 动作、执行意向与实际结果

动作卡包含证券、动作、当前/目标数量、允许价格范围、生成与数据截止时点、账户版本、有效期限、触发与失效条件、主要依据、不确定性及未成交处理。数量未知就显示暂不能计算，不把模糊判断转交用户补全。发送后的结构和文字不可编辑，变化创建后继版本。

动作流转采用 CANDIDATE → READY → TRIGGERED → INTENT_RECORDED → AWAITING_ACTUAL → PARTIALLY_SYNCED / COMPLETED；未实际发生部分可进入 EXPIRED、SUPERSEDED、CANCELLED_BY_USER 或 BLOCKED。状态推进不得伪造触发、意向或成交事实。

“准备操作”只创建 ExecutionIntent 和明确的临时占用；“已操作”缺细节则进入待同步。实际成交与动作通过显式 ActionFillAllocation 关联，可一对多或多对多；不明确的关联保持未知，不强行凑绩效。部分成交仅改变实际部分，剩余建议须用新账户与当前条件重新评估。外部待结果不随卡片到期自动消失，也不默认释放全部占用。

26/28 保留动作发出、可证明送达、已读、准备操作、实际成交发生与回报的时间和来源；未知不以发送成功或页面打开自动补齐。29 分别报告平台策略结果、实际用户结果及执行偏差，在明确关联和可比口径下对照延迟、价差、数量、费用与未执行原因。缺乏关联或时点时标明不可比较，不能将实际收益减影子收益直接解释为模型错误或用户行为的因果效果。27 消费实际回报开展监测，29 的展示不成为其前置。

规则按市场、板块、类型与生效版本适配，包括可买/可卖日期、数量、价格、费用及当前状态。未知规则或范围外状态限制相关动作，真实持仓与已发生成交继续可见。没有合格风险回退政策时只保留事实与待处理状态，不默认清仓或持有。

### ID-12 资格、资金授权与撤回

模型技术资格、用户资金授权和运行健康分别持久化，每次正式动作取三者有效范围的交集。CapabilityGrant 绑定能力/动作/证券/市场/频率/期限/执行假设、模型政策及代码依赖指纹、账户、风险授权版本、复核依据、生效与到期时点。

10 冻结损失暂停计算契约：账户或试验授权范围、计算起点、外部现金流调整、已实现/未实现损益、已确认待结算项的处理、陈旧估值和缺失数据策略、剩余额度、暂停与恢复条件。用户确认自身金额和范围，方法不交给用户临场选择。每日切换日期或重启不重置累计损失；更改边界保留旧版本与历史。09 提供带时点及版本的实际估值事实，20 提供隔离试验事实，25/27 联验当前额度与触发，未知输入不算零损失或自动恢复；先在 10 验证契约，不倒置实现依赖。

| 能力状态 | 允许的生命周期 |
|---|---|
| UNGRANTED | 无授权，不能发布对应正式动作；部署、PASS 或模式切换不改变此事实 |
| ACTIVE | 在版本、范围、账户/数据与资金条件仍满足时使用 |
| SUSPENDED | 按故障、资金条件、证据恶化或用户意愿分别登记；只按对应预登记恢复证据恢复 |
| REVOKED | 不重新激活旧记录；再用须通过当前检查并建立后继授权 |
| EXPIRED | 到期关闭正式能力，当前有效的新授权完成前不放行 |

授权变化追加 CapabilityEvent，不改旧历史。缩小或撤回资金授权立即限制新动作；扩大仍受已验证范围约束。暂停事件不倒改历史 PASS 为 FAIL，价格反弹不自动恢复。回滚代码先检查当前资格，不能恢复已撤回或过期权限。

生成、发布、通知出队、打开当前卡片和记录执行意向时，服务端分别核对最新动作、账户、grant、资金版本、有效期及必需输入。撤权与依赖它的未执行动作失效原子提交，之后不得新入队有效动作。历史授权只供审计重放，不供当前放行。撤权不代表撤单、清仓或风险解除，外部未决事项和实际持仓继续存在，真实成交照常受理。

### ID-13 页面、通知与状态呈现

最多五个一级入口：今天、持仓与关注、同步账户、历史记录、设置。首页顺序为能力与原因、账户确认时点、最近分析/数据时点、实际运行状态、合格动作或客观风险、最近变化及按需分析入口。监控阶段区分验证中、不通过、证据不足、待技术审阅、暂停、撤回和到期，不制造默认交易判断或新闻填充。

单股页以当前状态、持仓、价格/计划条件、时间线和短依据为主，概率诊断与原始证据展开查看。同步页提供成交、文件、现金/权益、账户核对入口，确认前展示差异，成功后可查看持久化回执。用户不选择统计方法或投资人格，Codex/DeepSeek 设置仅选择任务后端。

研究结果在服务端查询、文本、导出、曲线、通知和深链上均保留模式、依据类型和资格来源。影子内容只能进入研究视图，无“准备操作”入口或行动推送。用户自行按试验交易可同步事实，但不追认该建议或资格。

平台内通知必需；外部渠道通过一个可测试适配器接入，供应商属于实施配置，无可用渠道时明确需打开查看。分类为需要行动、需要同步/恢复、阶段摘要；普通波动、重复新闻和措辞变化不发新通知。按动作、状态与严重程度去重，重大新增风险或失效可越过普通冷却，阶段摘要是上限而不是每日必须发送。

通知有持久化出站记录、有效期和发送前复核。送达/已读未知就保持未知；已送达内容不可收回或修改，撤权遇在途消息须附加失效记录/提醒，深链显示当前状态。不能声称外部通知绝无传输竞态，任何旧卡均不能创建新的有效意向。

### ID-14 实验协议、时间隔离与全部尝试

ExperimentProtocol 在测试前冻结研究假设、候选版本、样本与迁移范围、主要经济目标、必要基线、数据时点、特征/校准/阈值拟合窗口、封存测试、成本、人工执行、统计方法、检查点、技术限制与停止规则。首轮目标为预定风险、资金占用和覆盖约束下，相近风险的费用后收益改善；不能看结果后改为较容易通过的目标。

必要对照为持币、同一起点持有不动和透明简单规则；若采用组合模型另比较等权组合。初始资金、外部现金流、佣金税费、滑点、交易限制和信息时点可比，并报告仓位差异。初始只使用当前名单的条件性回溯与受控研究样本，不伪造过去的选股过程；具体支持范围写入结论。

训练、组合拟合、校准与最终测试按时间隔离；处理标签跨窗、同日多股及重叠期限的依赖，不随机切分后称独立。评分同时检查概率损失、可靠性、区分能力、入选子集、有效支持与不确定性，不能只用 Brier 下降或 Agent 一致比例证明可靠。经济评价联合净收益、盈亏比、尾部损失、回撤、资金占用、持有期与覆盖，长期空仓或扩大损失换胜率不构成通过。

登记所有候选、特征、期限、阈值、提示词、人工筛选、失败与中止，以及封存数据访问。依据已看封存结果改模型后，该区间已使用，新候选须后继协议与未使用证据或已预登记的多重方法；不重命名为独立最终测试。

默认一个预登记最终确认性 PASS 判定点；按需查看与中期运维不增加判定点。多次可判 PASS 的查看须预先定义且验证覆盖全部查看的序贯/多重方法，固定日期本身不够。label_matures_at 或提前结算规则明确，未成熟结果不评分、不学习，相关记录不冒充独立样本。

17 预登记 G5 的跨时间段、成本压力、延迟、参数邻域及迁移范围检查，20 在完整协议中冻结，21 输出各分项输入、结果、局限与判定依据。测试后缩小范围或挑选参数不能翻转原协议结论，修改进入后继协议。正式期对照执行假设、数据漂移及成熟结果的监测项、适用域、阈值/方法与检查点也须在启用前冻结并经验证/审阅；工程样例仅验证方法，不充作真实持续监测证据。

### ID-15 连续影子、执行假设与三个月终点

ShadowAccount 从冻结现金/持仓基线开始，仅按所属实验的模拟成交与现金流政策演化，受现金和持仓共同约束。真实交易、更正和费用调整不重置影子；改变基线、模型、校准、决策政策或执行假设须保留原实验并登记新实验，不拼接版本成绩。ACCOUNT_CONDITIONAL 只作一次账户条件诊断，不计连续策略业绩。

按冻结协议在未来结果发生前归档预测、动作或拒绝原因，包括没有形成可执行影子动作的机会。被拒机会的反事实结果在成熟后关联评分，仅用于预测/筛选诊断，不混入连续影子收益；拒绝或未执行不自动标为模型亏损，不能只保留模拟成交的机会。

日线执行模拟包含响应延迟、价格窗口、错过/不执行/部分执行、价格偏差、费用、可卖日期、无法成交与覆盖缺口。最低压力方向包含下一交易日开盘/收盘、再延迟一日、价格范围外不成交；具体方案在协议中固定，有真实归档报价才可另测下一可观察价格。历史状态不足采用预登记的保守/区间处理并报告限制，不按输赢删样本。模拟不测得用户真实照做的行为分布，这一限制须保留。

首次成功持久化冻结模型的实际前向预测时，记录 forward_started_at 与不可随意移动的 forward_deadline；最终截止不晚于起点加 3 个自然月。不得以建实验、部署、导入历史或按需点击提前伪造起点，也不以 90 天替代自然月。M0 固定时区、月份加法/月末、截止边界及较早停止条件，并保留边界测试。

缺席、换取证后端、重试和不利结果不延长期限。缺日保留缺失；后取行情可以补事实或按冻结政策结算已归档预测，不能创建“当时已经归档”的预测。截止时只评价已成熟结果，未成熟项单列，不提前标输赢，不为了等待其成熟自动续期。新研究需新增数据/假设价值和后继协议，不能作为原实验的隐形延长。

### ID-16 自动验证、技术审阅与条件性发布

收益预测模型保留全部 G1—G7：数据可信、工程正确与重放、预测有效、决策有价值、稳健与适用、在线工程一致、前向成熟结果。G6 通过不能代替 G7。独立确定性风险回退政策使用自己的冻结协议，至少覆盖数据、规则计算、授权、压力执行和在线一致性；不能借此替收益模型免除预测与经济/前向证据。

validation_manifest 保存协议/候选指纹、目标与最小改善、基线、窗口、全部尝试、依赖估计与统计方法、停止规则、成本延迟、各门槛、范围、证据截止、局限、到期与未决事项。门槛组合预登记，硬失败优先于证据不足，不平均评分抵消。

分别保存 experiment_status、ValidationVerdict、review_status 与能力状态。PASS 表示协议必需门槛均满足；FAIL 有违反要求的证据；INCONCLUSIVE 表示支持不足或区间无法判定，未显著不等于已经证明无效。未完成自动验证或审阅只能显示初步结果和具体缺口。

Codex 或 DeepSeek 读取冻结材料进行技术审阅，ReviewRecord 包含审阅方法、后端/模型/配置、材料指纹、时间、工具与复现检查、异议、处理证据和局限。宿主检查记录与证据引用；模型文字赞同、两个后端一致或用户点击不能替代必需证据。无法核实的必需项保持不足或未通过，不声称人工独立复核。

正式启用必须同时满足：必需门槛 PASS、技术审阅完整且阻断事项有证据处理、确定性资格检查通过、部署指纹/范围匹配、用户在有效资金边界内启用、当前账户与数据允许。仅受控发布服务登记 CapabilityGrant，研究与审阅 Agent 不可直接调用。无专业人工复核人员不再构成额外否决条件；界面和交付如实标注“经自动验证与模型技术审阅，未经人工独立复核”。

工程交付、验证交付与正式资格分别报告。按协议结束且验证/审阅完整的 FAIL 或 INCONCLUSIVE 可以交付；必需检查未完成则记录未完成。M4 不是项目结项前提，也不能用极小真实资金试用绕过技术资格。

### ID-18 持久化、恢复与运行限制

确认回执须经真实持久化保证。持久化任务表与统一写入入口避免同一账户决策重入，允许受控并行取数但不产生竞争写账链；任务有退避、超时、停止条件、积压和健康状态。未执行或取消任务不可事后伪装完成。

实际运行日有持久化变化时自动本地备份，提供手动导出、最近成功备份与未覆盖变化。连续运行建议间隔不超过 24 小时；停机不承诺新备份，重启发现待备份变化后补做。恢复以实际成功备份为界，升级前备份，迁移具有回滚或恢复办法。

恢复校验附件哈希、事件数和账户投影，并先进入 RECOVERY_LOCK。旧备份中的 ACTIVE 仅为历史；核对当前账户、部署、用户资金授权和可能遗漏的撤回后，依据有效验证与技术审阅材料建立当前权限才可解锁。无法核实保留观察能力，禁止正式动作及旧通知发送。

默认仅本机访问；远程访问必须显式启用鉴权与加密。密钥不进日志、报告或模型上下文，账户文件/备份具备访问控制与脱敏展示。不存在券商交易凭据字段、订单模块或模拟点击券商网页的能力。

不设置运行金额预算或人工复核采购前提；保留技术调用/递归/时间限制、实验完整尝试和结束规则。佣金、税费、滑点与费用后收益仍是账户和研究的必需口径。

### ID-19 性能与可观测性

以普通四核、8GB 内存、30 只个股和 5 个指数为建议工程基线，记录实际环境与模型配置。缓存可用时首页读取 P95 ≤ 2 秒、单笔确认 P95 ≤ 2 秒、一次名单本地模型评估 P95 ≤ 30 秒。外部获取、sub-agent 补查与本地计算分别计时，不把联网时间混入纯本地评估指标，也不承诺分钟级捕获或秒级行情。

运行审计包含代码、数据、模型、配置、随机种子、输入输出指纹、错误与实际工具；分别呈现账户、数据、服务、资格和通知健康。15 在实际运行日及按需/恢复入口检查数据覆盖、账户差异、未完成意向、动作失效数量、重复通知、动作翻转及模块错误，异常能追溯到相关运行和版本；26/28 存在后完成对应联验。涉及关键复盘触发条件时关联 14 的核验，不将普通运行摘要升级为多源任务。

15 提供按交易日历执行的维护触发与实际覆盖记录，27 接入健康、成熟标签、到期资格和新实验条件检查；建议每周/每月安排可按运行计划配置，离线留缺口，恢复时检查当前条件，不补造已执行维护。维护不增加统计 PASS 查看次数，没有足够新增信息不强制重训。

27 使用冻结监测方法及实际回报，检查执行延迟/成交/费用与验证假设的偏差、数据适用域及漂移、到预登记检查点的成熟结果，保存输入、方法版本、结果、缺口和后续处置。操作故障、资金边界和明确输入越界可立即限制相关能力；统计恶化按冻结方法复核，不以几次亏损倒改历史 PASS。修正记录错误来源、预期改善、受影响模块和验证方案；数据修复走回归，费用或模型/政策改变走相应后继验证。34 核查该监测配置与记录入口可用，实际长期证据按运行情况逐步积累。

### ID-20 复用结论与适配责任

当前没有确认可直接复用的完整外部服务。DSA 的 CSV 字符串解析、编码/列映射及少量单证券请求映射为改造候选；Roll 的账户事务、精确数值、双时间、事实与权限契约优先。不得继承逐行部分入账、缺费归零、浮点累计、删除纠错、缺行情补值、无口径切换或默认全市场报价。

LangAlpha 只参考证据编号、来源/时点、派生依赖与修订/冲突；ai-hedge-fund 只参考连续影子状态与完整性。外部的 approved、漏日重跑或 redo 不等于 Roll 资格与真实前向证据。参考项目的技能、配置和金融工作流不迁入生产 Agent。

组件记录必须包含具体来源、固定版本、许可证、必要依赖、改造语义和适配测试，分类为直接复用、改造后候选、仅参考或不采用；已检查依据见 Further Notes。数据源与 SDK 的真实权限、范围和失败语义待实现验证；小样例可达不能升级为长期可用或全部市场支持。

## Testing Decisions

### 主要边界与证据层次

2026-10-07，用户已确认以 FastAPI 应用入口作为主测试边界，补充关键网页流程、真实进程崩溃恢复及两个真实取证后端的接入检查。

1. **主要自动化边界是 FastAPI 应用入口。** 用外部命令/查询完成“输入或触发 → 持久化 → 查询回执/投影/当前动作/通知”的行为验证，实际使用 SQLite 和隔离临时归档。测试不依赖内部类、调用次数或私有表布局。后台任务经相同用例入口触发；冻结时钟、源响应和研究输入，避免把在线波动混入确定性验证。
2. **关键持久化风险使用真实进程与文件。** 在提交前后、回执后、通知出队与恢复边界注入崩溃/竞争，重启后通过公共查询证明事件不丢、确认不重复、旧权限不恢复。只 mock 存储无法证明这些性质。金额分摊、日历和标签边界仅在较高入口不能清楚定位时补充少量纯计算测试。
3. **React 仅补关键用户流程。** 浏览器贯穿初始导入/差异确认/回执、无交易声明、按需分析时点、部分成交与待同步、旧卡拒绝、暂停/恢复及研究隔离，检查可见结果与真实服务交互。UI 不重复全部领域组合，也不以截图代替服务端越权检查。
4. **外部适配采用同一契约分别实测。** 固定原始响应重放验证口径与错误路径；实际数据来源、Codex、DeepSeek、外部通知渠道另保留运行环境和真实结果。真实多轮取证、结构化输出、缺工具/坏结构、超时取消、切换期间任务配置、权限隔离与脱敏须逐后端核实；测试替身不能宣称接入通过。不得为验收自动执行任何券商交易或联系第三方。
5. **工程与统计证据分开。** 用合成合格凭证验证正向资格流程、模型自签拒绝、撤回和 UI 行为，但限定测试环境并防止生产使用。真实 G1—G7、成熟前向和研究价值只认冻结协议的实际结果，不由模拟时钟、fixture 或后台稳定运行替代。
6. **同输入重放检查结构化结果。** 对动作、数量、有效条件、依赖、授权与账本结果断言，不要求生成式说明逐字一致。LLM 输出使用已归档结果重放；重新联网或再次生成是新运行，不修改原输入。
7. **负面与缺失路径为同等验收要求。** 覆盖未知、失败、证据不足、过期、无权限、部分完成与恢复；禁止把它们全部折算为成功或 WAIT。无专业人工复核但其他条件齐全的正向场景必须通过，防止旧门槛残留。

仓库没有现成测试代码或框架可作为先例。测试的先验材料是 PRD 的 AT-01—AT-90、十项数据不变量、账本/资格例子及已查外部组件的具体缺陷语义；不把参考仓库的测试套件或默认流程当成 Roll 已有验收。

### 额外边界组合与实际验收记录

- 账户确认：同文件重传、跨文件相似行、一委托多成交、批中失败、提交前后崩溃、不同窗口旧版本、重复请求内容不一致；断言无部分入账、无错误合并与可靠回执。
- 财务守恒：PRD 例子中 100,000.00 元现金买入 300 股、10.00 元/股、5.00 元费用后为 96,995.00 元现金和 3,005.00 元取得成本；再组合未知费用调整、外部现金流、部分卖出与陈旧估值，验证守恒而非照抄计算实现。
- 权限竞态：撤回发生在生成/发布/出队/开卡/建意向任一点，恢复备份遗漏撤回，模型配置或账户变更；断言无新的有效意向、历史不改、外部未决事项不消失。并发测试检查可观察结果，不承诺外部通知绝无在途竞态。
- 研究隔离：从 API、文本摘要、导出、曲线、深链和通知尝试将影子高概率引入正式动作，全部保持研究来源且无执行入口；用户自行交易后的真实事件仍可确认。
- 时点与有限研究：日期粒度公告、未完成成交量、复权修订、相关股票/重叠期限、截止瞬间未成熟、月份长度与月末、缺席恢复和新实验后继；只验证预登记规则，不以测试时钟造出真实 G7。
- 后端与外部组件：两种实际后端分别跑同样的事实任务及取消/错误/越权检查；DSA 改造候选逐项验证单位、原价/复权、缓存时间、截断和未知值。只测静态返回或单次连通时，验收状态须明确为局部证据。
- 运维与容量：记录真实设备、数据集、缓存状态和 P95，验证账户确认不被联网补查阻塞；有变化的运行日备份、停机无新备份、重启补做与迁移失败恢复分别留证。

每项验收记录包含编号、输入/期望/实际、版本与环境、日志/回放/截图依据、缺陷及状态。分开报告确定性应用测试、进程恢复、浏览器流程、真实外部适配和统计/前向证据。未执行、失败或部分覆盖须明示；生产授权不能引用测试合成凭证。任何未完成 P0 工程要求不能被标成“后续优化”或由策略 PASS 抵消。

90 项 AT 是场景基线，不能代替正文、数据不变量和附录要求的逐条追踪。[P0 需求追踪](requirements-traceability.md) 为每项指定责任票及验收证据入口；责任票记录条款级结果，31 核对工程分支，32—34 分别更新真实启运、验证和条件启用证据。覆盖审查新增的例子随原责任票验收，不改原 AT 编号或冒称原场景已覆盖。

## Out of Scope

- 券商自动交易、撤单、登录或交易口令托管，以及模拟点击券商网页。
- 港美股、加密货币、融资融券、做空、衍生品、基金交易、自动再投资、多用户与多账户业务。
- 全市场选股排行、全市场逐日特殊股/停牌历史库、ST/退市专题、分钟级采集与概率模型、盘中触发先后重建和秒级监控承诺。
- 整仓继承 DSA、LangAlpha、ai-hedge-fund 或 TradingAgents 的业务流程，多角色金融裁决、大师人格、独立长篇投研门户与自然语言改风险规则。
- 在没有真实脱敏样例前承诺支持专用券商原始格式；自然语言/OCR 导入与更多文件格式留待后续范围。
- 复杂动态组合、深度序列模型、自动因子发现、无界候选搜索与自我批准；这些属于有证据才启动的后续增强。
- 强制交易时段在线、每日打卡、每日三阶段齐全、补造漏日预测、模型不通过就无限延长研究。
- 运行费用金额规划、独立人工复核采购或专业人员到位前提；交易成本、用户资金授权及技术限额不在排除范围。
- 固定盈利或胜率承诺、要求研究必须 PASS、让普通用户选择统计方法或替模型签技术担保。
- 本次规格工作中的生产实现、依赖安装、Git 初始化、提交/推送、实施任务文件或实际长期前向实验；由用户后续分别调用相应流程。
