# Roll P0 项目目录与实施约束

日期：2026-10-07。用途：落实用户在任务发布时提出的“需要有项目框架目录设计，不过度抽象，不过度防御”。本文件是 [任务计划](ticket-plan.md) 的共同实施约束，沿用 [规格](spec.md) 与 [ADR 0001](../../docs/adr/0001-default-engineering-route.md)，不修改父规格或重新选型。本轮只发布文档，下面的生产目录尚未创建。

## 目标目录

```text
Roll/
├─ backend/
│  ├─ pyproject.toml
│  ├─ src/roll/
│  │  ├─ app.py              # FastAPI 入口与依赖组合
│  │  ├─ worker.py           # 一个后台任务进程，调用相同应用用例
│  │  ├─ config.py           # 有实际用途的启动配置
│  │  ├─ accounts/          # 账户草稿、确认、事件、投影、对账
│  │  ├─ market/            # 名单、规则、日历、来源、事实和证据核验
│  │  ├─ research/          # 特征、预测、协议、执行模拟、验证和影子
│  │  ├─ decisions/         # 资格、资金边界、正式动作、意向和通知
│  │  ├─ agents/            # 受控任务、Codex 与 DeepSeek 接入
│  │  └─ runtime/           # SQLite、归档、任务执行、审计和备份恢复
│  ├─ migrations/           # 随实际状态变化增加版本化迁移
│  └─ tests/
│     ├─ application/       # FastAPI 命令/查询，真实 SQLite 与隔离归档
│     ├─ recovery/          # 真实进程、崩溃、恢复和竞争
│     ├─ adapters/          # 固定响应重放与分别受控的真实接入检查
│     └─ fixtures/          # 合成或脱敏材料，不能充当真实运行证据
├─ frontend/
│  ├─ package.json
│  ├─ src/
│  │  ├─ main.tsx           # React 启动
│  │  ├─ app.tsx            # 五入口导航与页面组合
│  │  ├─ api.ts             # 实际使用的请求与响应契约
│  │  ├─ pages/             # 今天、持仓与关注、同步账户、历史记录、设置
│  │  ├─ components/        # 已有实际复用的展示控件
│  │  └─ styles/            # 当前页面使用的样式
│  └─ tests/e2e/            # 关键用户路径连接真实应用服务
├─ scripts/                 # 有需要时添加本地启动、交付辅助脚本
├─ docs/                    # 现有 agents、adr、alignment；后续使用/运行说明
├─ .scratch/roll-p0/         # spec、目录方案、任务计划和逐票追踪
│  └─ issues/
├─ AGENTS.md
├─ GLOSSARY.md
└─ ashare_market_decision_prd.md
```

这是逐步采用的布局，不是一次性生成清单。依赖锁文件由 01 按实际验证的包管理方式生成并纳入版本管理；不为目录设计新增包管理或构建框架选型。忽略规则随实际生成物建立，不能把项目追踪用的 `.scratch/roll-p0/` 一并忽略。

01 只创建首次账户基线“表单 → 差异 → 确认 → 回执 → 今天”实际需要的启动、账户、SQLite、页面与测试文件。worker、其他业务目录、迁移增量和复杂研究页面随负责票出现，不先生成空包、全部对象类型或占位实现。完整框架由后续票逐步落地，31 核对实际布局和交付说明。无需单独增加一张只做骨架、不交付用户行为的任务。

目录表达职责聚合，不把规格 ID-02 的每个逻辑 Module 机械翻译成独立包。单个 Module 的 Interface 是调用者需要理解的命令、查询、不变量及失败语义；其 Implementation 留在所属职责内。各目录按需要使用普通函数、类型和文件，不统一复制 router/service/repository/schema 四层。若少量文件足够，就不继续分目录；规模确实增长时在责任票中说明拆分原因即可，无需重新进行产品审批。

## 职责与调用方向

| 目录 | 规格中的职责 | 实施限制 |
|---|---|---|
| accounts | AccountLedger | 真实事件、回执、投影集中写入；不能从动作或预测推定成交 |
| market | MarketData / EvidenceResolver | 管理来源和事实语义；来源 Adapter 放在这里，不把金融规则交给通用网络层 |
| research | FeatureStore / ForecastService / EvaluationLab / ShadowLedger / 验证材料登记 | 一个透明候选及必要基线；冻结政策计算可供正式动作复用，但研究不能签发资格或修改真实账户 |
| decisions | DecisionEngine / ActionCenter / CapabilityGuard | 资金授权、资格生命周期和正式动作由宿主掌握；验证材料来自 research，正式授予权限留在此处 |
| agents | 取证和模型技术审阅的执行后端 | 使用限定读取和结果契约；不拥有账户、资金、资格写入工具 |
| runtime | MonitorScheduler 的执行部分 / AuditService / 存储与恢复 | 交易日、行情完成度及事实缺失/用途时效归 market；前向检查点、样本缺失与终点归 research；runtime 执行任务并记录实际运行/覆盖状态；权限规则归 decisions，不能变成收纳全部业务的 common |

HTTP 和 worker 调用同一应用用例；React 展示服务端结果，不实现第二套账本、资格或研究判定。跨目录通过少量类型化命令/查询传递已定义结果，避免互相读取私有实现。

账户确认与现存动作失效、撤权与未执行动作失效，必须在受控写入链中原子完成。对应票出现后，由拥有该用例的应用 Interface 协调同一 SQLite 事务并明确传入所需依赖；不能为了目录整齐拆成最终一致的两个写入，也不为此建设通用事件总线或事务框架。开始阶段没有正式动作时不预造整个动作系统，26/27 补做真实集成验收。

后台仅一个进程，使用 SQLite 持久化任务及通知出站记录，异步外部获取与短事务分开。业务时序需要持久化，不意味着引入分布式队列、消息中台或通用 DAG 编排。

## 运行数据与源码分开

部署时使用可配置的运行目录；`ROLL_DATA_DIR` 是本方案的配置名称，实际路径在本机启动配置中确定，不硬编码用户个人目录。

```text
ROLL_DATA_DIR/
├─ roll.sqlite3             # 唯一正式业务状态
├─ raw/                     # 原始响应、文件及证据，按内容指纹引用
├─ parquet/                 # 行情、特征、研究归档
├─ backups/                 # 数据库与归档清单一致的恢复材料
├─ tasks/                   # 各受控任务的独立工作目录
└─ logs/                    # 脱敏运行记录
```

生产账户数据、密钥、原始私人文件、备份与运行日志不进入源码提交；代码与脱敏可复现测试材料可以进入。SQLite、raw 与 Parquet 的所有权按规格执行，Parquet 不成为另一份真实账户权威。01 只需要最小配置与数据库；相应票再增加归档、任务或备份目录。

`tasks/` 的目录分离本身不构成权限隔离。11—13 必须按两个真实后端核实有效工作目录、允许读取的材料、工具及联网副作用；不因父目录可见就授权读取数据库/密钥，不自动继承开发 AGENTS、SKILL 或个人技能。采用能满足已知权限要求的最小运行配置，不建设通用沙箱产品。

## 不过度抽象

- 新 Interface、基类或 Adapter 应解决当前票中真实的变化点或重复复杂性。先写清现有调用者或两个实际实现；仅为“以后可能换”不够。调用者和测试通过同一个小 Interface 验证行为，不为 mock 再加纯转发层。
- Codex 与 DeepSeek 是两个实际后端，数据换源和一个实际通知渠道也有明确契约；这些 Seam 有用途。它们不要求动态插件发现、任意 Agent 编排、运行时技能市场或策略 DSL。
- SQLite 是唯一正式数据库；用具体持久化实现和实际需要的事务/迁移即可，不预建多数据库 Repository、通用 Unit of Work、CQRS 平台或分布式存储。
- 研究先有一个透明候选、必要基线和确定性政策；用普通数据结构及计算函数表达冻结规则，不做全市场研究平台、自动因子搜索或通用规则引擎。
- 前端以五个用户入口组织；有真实复用才提取展示控件，不逐后端对象复制一套前端领域层，不预建组件库或全局状态平台。
- 实际摘取外部代码时，仍须登记具体文件、检查版本、许可证、依赖、修改语义与适配测试；默认技术路线和仅参考设计不等于整仓复用。

## 不过度防御

校验集中在外部输入、外部工具结果、持久化承诺与会改变执行资格的位置。有效内部类型在同一可信调用链中不逐层重复相同空值/类型校验，不包裹只换名字的异常。已知失败返回可行动的原因；未知异常保留可定位的脱敏诊断，不吞成成功、零值、HOLD 或无穷重试。

必须保留的正确性约束包括：金额精度、确认幂等/版本冲突/原子提交、回执可靠持久化、事实时点与缺失口径、正式与研究隔离、关键节点当前资格复核、撤权和恢复锁、真实前向不可补造。这些有具体 PRD 场景依据，不属于可以删掉的多余防御。生成、发布、出队、开卡、建意向之间可能发生状态变化，因此这些节点再次检查当前条件是必要的，不等同于在内部函数重复同一检查。

P0 维持本机单用户边界。默认本机绑定、必要文件访问控制、密钥脱敏与受控工具按规格落实；未启用远程访问时不建设多租户权限平台、远程灾备或跨地域容灾。用户确认账户事实和资金授权是既有业务流程，不新增逐次模型结果人工审批、专业复核采购或与已知风险无关的确认弹窗。

普通事实可单源，关键复盘才进行独立来源核验；程序正常关闭不是持续故障，缺失数据不让无关已知功能停摆。重试、兼容与回退只针对已查明的失败语义，记录停止条件，不增加无限补查、静默补值或假设性旧版本兼容。

## 逐票验收与责任

每票均含共同验收项：只引入当前行为实际需要的 Module、Interface 和校验，保留 PRD 必需控制，不新增假设性兼容层、审批或泛化框架。验收证据简单说明本票目录/依赖变化，以及新增抽象的现有用途；未引入新抽象可以直接记为无，不要求长篇设计报告。

| 责任票 | 需要直接检查的内容 |
|---|---|
| 01 | 最小目录与首条可运行账户路径一起交付，没有先建全部骨架 |
| 07/08 | 实际单证券来源和语义适配；没有全市场采集框架 |
| 11—13 | 两个真实后端的 Adapter 与受控契约；没有开发技能自动装载或多角色裁决 |
| 15/30 | 单后台进程、持久化任务、唯一检查点样本；没有分布式队列或通用工作流引擎 |
| 17—22 | 一个候选、必要基线与冻结确定性政策；没有研究 DSL 或无界搜索 |
| 16/27 | 数据一致备份、恢复锁、撤权不复活；没有额外灾备或企业权限平台 |
| 24—29 | 必需节点的当前资格检查和跨出口隔离；不过度防御不削弱这些验收 |
| 31 | 核对实际目录、依赖和运行说明；没有空骨架、无调用抽象或未经票据要求增加的基础设施 |

测试沿用已确认的 FastAPI 主 Seam，采用真实 SQLite/隔离归档；关键浏览器、真实进程恢复和两个实际后端分别留证。不为低价值目录封装写镜像实现的测试，也不以减少测试为由删去已有验收场景。本文件不改变 34 票粒度、依赖或 90 项验收主责任分配。
