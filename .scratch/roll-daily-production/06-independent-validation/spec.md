# 阶段 6：独立验证执行器

基线：`820c6d14e81fe7ba8ca826e906255359c65175cc`；开发分支 `codex/roll-research-validation`。阶段 5 验证后再实施阶段 6。

## 需求与验收

复用 ForwardArchive 的实时归档预测与成熟结果，新增预测开始前不可变预登记与一次终点评估；拒绝 CAL 改名、事后登记、未知代码、历史污染和重复检验。按相同日期、资金、费用、执行政策生成 CASH/START_HOLD/MA5_MA20 对照；记录概率质量、成熟/未成熟/不可评分以及独立性限制。输出 PASS/FAIL/INCONCLUSIVE 的门级判断和总体结论，不能自动授予正式资格。样本不足或统计假设未验证必须 INCONCLUSIVE。冻结资源/阈值、审计家族既往曝光，支持幂等、重启、离线重放；不得读取 SEALED 来补足样本。

## 边界

不改真实账户、资金授权、已有模型参数或旧阈值；不清零研究预算，不承诺模型通过。METHOD_CASE 仅用于工程验证。真实前向时间与成熟支持不能用合成数据替代。

## 实施设计

1. `GET .../independent-validation/admission` 只读冻结元数据、家族尝试和曝光审计；不打开模型输入或保护价格/标签。所有家族训练、CAL、保护窗口取最晚排除日期；真实前向开始必须在其后。
2. 先通过已有 `/forward` 登记归档，再 `POST .../independent-validation/plan` 绑定完整冻结指纹、执行器依赖指纹、原始期限、资源和阈值。计划只允许同命令幂等重试，不可修改。事务内再次检查预测数，阻止并发事后登记。
3. 使用已有 `/forward/check`、`settle`、`stop`；正常到期或显式提前停止关闭后，才允许 `POST .../independent-validation`。没有预登记不可运行，不创建新预测或新前向起点。
4. 核验模型/校准原件、样本与结果原件；重算预测和连续账本、逐机会成熟结果；同一输入/费用/规则/资金/日期计算 CASH、START_HOLD、MA5_MA20。未知仍保留，无成交不能标负。
5. 保存一次终点结果与输入归档；重复提交返回同一结果；`.../replay` 只重放原输入，不增加检验。界面展示证据类别、样本分类、G1—G7、能力状态及下载。

## 当前协议的可行性与未实现准入

原协议三自然月，即使把每个自然日当交易日，扣除 20 日成熟期后仍不足 30 个 20/40 日块。预检报告 `INFEASIBLE_FOR_PASS_UNDER_FROZEN_LIMITS`，不会更改旧阈值或重开预算。可完成有明确期限的工程归档、算术检查与 FAIL/INCONCLUSIVE 验证结果。

当前版本没有可核验的真实抽样假设证明、独立可靠性支持、风险匹配及完整 G5 工件准入。G3/G5/G7 保持 INCONCLUSIVE；G4 仅可由冻结硬限制判 FAIL，否则 INCONCLUSIVE。**此执行器不提供将当前候选提升为总体 PASS 的入口**；通用组合器支持三态，G2/G6 的工程 PASS 不能替代这些缺项。未来确认性 PASS 需要另行设计并冻结可行的后继协议及真实证据适配，不能通过请求参数宣称已独立或放宽阈值。

宿主之外的既往曝光无法证明，明确 UNKNOWN；仅核验宿主归档范围。新结果独立存表，不写旧 `research_validations`、不改旧协议结论，不自动启动收费技术审阅或正式授权。真实前向起点仅由已有归档器第一次持久化预测产生。
