## Acceptance criteria

- [ ] 固定财务字段口径、新闻标签/聚合方法、缺失/拒判政策和可消费截止，形成不可变特征快照；后来修订不能倒填。
- [ ] 登记原量价基线、加财务、加情绪和两者组合的最多四种消融设计；实际配置数受现有家族剩余预算约束，不开新家族绕过预算。
- [ ] 提前固定标签事件/期限、费用/执行、时间切分/隔离、主要目标、候选顺序、样本支持、统计方法、调用与自然终点。
- [ ] 预训练/训练语料时间不明、历史原版不足、标签未成熟等保持限制；不能把现在采集的信息混入过去预测。
- [ ] 通过公共注册→快照→预检→查询/页面与重放，支持成立和拒绝均可验；只完成工程准入，不自动启动真实拟合或打开SEALED。
- [ ] 附本票适用的代码/依赖版本、公开行为验收、真实与METHOD边界、原失败及剩余条件；若继承另一会话成果，引用精确验收并核对当前版本。不得以仅写计划或仅实现拒绝路径替代所要求的正向能力。

## Implementation boundary

优先复用原服务和指定成熟组件；新增表、接口、页面与测试围绕本票用户路径增量实现，不横向重写整个模块。01交接票只做交接核对；08及23—25是真实运行操作。其他票的API/持久化/界面与测试应作为同一可演示切片交付。新组件不可写真实账本或自签资格；没有必要不新增测试入口或插件框架。
