## Acceptance criteria

- [ ] 以只读适配调用QuantStats，输入Roll已有收益及基准序列，不使用库自动下载或另算交易账本。
- [ ] 保持ACTUAL/HISTORICAL/SHADOW/ACCOUNT_CONDITIONAL分列；外部转入、费用及真实成交差异不混成策略收益。
- [ ] 固定窗口、年化和无风险口径；核验dropna、首非零匹配、填零等预处理，未知区段单列，不缩短窗口伪装完整。
- [ ] 在既有报告页提供曲线/回撤/月度收益及导出，报告包含数据/方法版本、覆盖和资格限制。
- [ ] 公共接口与浏览器/导出验全零、短窗口、漏日、现金流、基准错位和旧报告重放；不足支持不显示误导指标。
- [ ] 附本票适用的代码/依赖版本、公开行为验收、真实与METHOD边界、原失败及剩余条件；若继承另一会话成果，引用精确验收并核对当前版本。不得以仅写计划或仅实现拒绝路径替代所要求的正向能力。

## Implementation boundary

优先复用原服务和指定成熟组件；新增表、接口、页面与测试围绕本票用户路径增量实现，不横向重写整个模块。01交接票只做交接核对；08及23—25是真实运行操作。其他票的API/持久化/界面与测试应作为同一可演示切片交付。新组件不可写真实账本或自签资格；没有必要不新增测试入口或插件框架。
