# 15: 新闻证券关联与转载去重

**What to build:** 用户看到按证券和事件组织的新闻，转载不会重复计数而更正仍可追溯。

**Blocked by:** [14 · 单股新闻与正文归档](14-news-ingestion.md)

**Status:** ready-for-agent

**Completion:** pending

**Execution:** NOT_STARTED；当前仅发布计划，用户稍后启动后才执行。

**Scope / inheritance:** 新增新闻派生事实；原文不可变。

**User stories:** US-29、US-30；共同遵循US-53—58。

**References:** [规格](../spec.md)、[执行顺序与依赖](../ticket-plan.md)、[验收追踪](../acceptance-map.md)。

## Acceptance criteria

- [ ] 先用规范URL/内容hash精确去重，存逻辑事件组和所有原件引用；只在实际近重复样本需要时复用datasketch，不先建设大索引。
- [ ] 证券关联区分明确公司、行业背景、不相关、不确定；多公司消息按对象保存，查询词命中不自动证明相关。
- [ ] 数字、日期、否定和更正变化不得误并；相似组保留版本与组建算法参数，重跑不抹除旧判断。
- [ ] 页面按事件组展开转载和修订，汇总采用唯一事件数，多媒体同上游不增加独立证据。
- [ ] 公开接口与真实SQLite验同文异URL、同标题异内容、修订、别名冲突、多对象与重启幂等；小样本手工核查结果留证。
- [ ] 附本票适用的代码/依赖版本、公开行为验收、真实与METHOD边界、原失败及剩余条件；若继承另一会话成果，引用精确验收并核对当前版本。不得以仅写计划或仅实现拒绝路径替代所要求的正向能力。

## Implementation boundary

优先复用原服务和指定成熟组件；新增表、接口、页面与测试围绕本票用户路径增量实现，不横向重写整个模块。01交接票只做交接核对；08及23—25是真实运行操作。其他票的API/持久化/界面与测试应作为同一可演示切片交付。新组件不可写真实账本或自签资格；没有必要不新增测试入口或插件框架。
