## Acceptance criteria

- [ ] 把财报按需更新与盘后新闻观察加入已有任务链，公开设置可查看/暂停受支持来源；无第二套调度或桌面自动化。
- [ ] 按原版本/截止判断缓存新鲜，不用包装时间刷新；同一输入只存一次逻辑观察，重启复用任务回执。
- [ ] 每源失败局部退避，模型推理失败不阻断事实新闻、原行情与账户；资源超限可取消并留回执。
- [ ] 真实离线区间显示缺席，不事后生成假当日预测；观察后台采集与研究预测归档分开。
- [ ] 重复新闻/文字变化不重复通知；外部渠道不因组件接入自动启用，实际发送待既有用户配置。
- [ ] 公共API/真实隔离进程重启和网页状态验收，METHOD时钟与实际在线运行收据分列。
- [ ] 附本票适用的代码/依赖版本、公开行为验收、真实与METHOD边界、原失败及剩余条件；若继承另一会话成果，引用精确验收并核对当前版本。不得以仅写计划或仅实现拒绝路径替代所要求的正向能力。

## Implementation boundary

优先复用原服务和指定成熟组件；新增表、接口、页面与测试围绕本票用户路径增量实现，不横向重写整个模块。01交接票只做交接核对；08及23—25是真实运行操作。其他票的API/持久化/界面与测试应作为同一可演示切片交付。新组件不可写真实账本或自签资格；没有必要不新增测试入口或插件框架。
