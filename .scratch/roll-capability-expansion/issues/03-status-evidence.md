# 03: 有效交易状态与未知覆盖

**What to build:** 用户在单股查看具有日期、范围和依据的交易状态及未知原因。

**Blocked by:** [01 · 交接基线与既有能力继承](01-handoff-baseline.md)

**Status:** ready-for-agent

**Completion:** partial

**Execution:** PARTIAL — 有截止的来源查询及单股折叠页已验收，完整枚举/否定覆盖待权威依据。

**Scope / inheritance:** 旧P030状态范围；复用已接入状态适配与源配置。

**User stories:** US-5、US-6；共同遵循US-53—58。

**References:** [规格](../spec.md)、[执行顺序与依赖](../ticket-plan.md)、[验收追踪](../acceptance-map.md)。

## Acceptance criteria

- [ ] 从已有停复牌/ST/上市阶段来源补01识别的最小缺口，查询与页面均保留身份、适用日期、完整性与原件。
- [ ] 空名单、目标未出现、分页未完、日期缺失、过期缓存都不能直接推定正常；只有明确覆盖依据才允许负向结论。
- [ ] 状态变化追加版本，给定历史截止查询不读后来状态，休市不伪造当日交易状态。
- [ ] 适用范围外证券和板块返回明确未覆盖；不默认扩为全市场采集。
- [ ] 公共API与真实SQLite验证正/负/未知路径、同源不独立、损坏/过期拒绝；真实来源响应与工程夹具分开。
- [ ] 附本票适用的代码/依赖版本、公开行为验收、真实与METHOD边界、原失败及剩余条件；若继承另一会话成果，引用精确验收并核对当前版本。不得以仅写计划或仅实现拒绝路径替代所要求的正向能力。

## Implementation boundary

优先复用原服务和指定成熟组件；新增表、接口、页面与测试围绕本票用户路径增量实现，不横向重写整个模块。01交接票只做交接核对；08及23—25是真实运行操作。其他票的API/持久化/界面与测试应作为同一可演示切片交付。新组件不可写真实账本或自签资格；没有必要不新增测试入口或插件框架。
