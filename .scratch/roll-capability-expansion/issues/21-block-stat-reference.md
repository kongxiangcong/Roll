## Acceptance criteria

- [ ] 复用arch区块bootstrap，对照现有冻结方法而非替换；记录许可、版本与数值依赖。
- [ ] 显式处理同日多证券成对分组、空条件组、漏日、区块长度、重复次数、seed和单/双侧区间定义。
- [ ] 不同随机实现不要求逐样本一致；用固定重采样索引或分析可检验样本核验统计量，再解释分布差异；容差和比较法先登记。
- [ ] 公开运行→保存→报告/重放完整，不能压缩漏日来增加有效独立块，样本不足显示不足。
- [ ] 库计算通过不把assumptions_verified或独立有效性改为true，不降低G1—G7门槛；旧工件和预算不变。
- [ ] 附本票适用的代码/依赖版本、公开行为验收、真实与METHOD边界、原失败及剩余条件；若继承另一会话成果，引用精确验收并核对当前版本。不得以仅写计划或仅实现拒绝路径替代所要求的正向能力。

## Implementation boundary

优先复用原服务和指定成熟组件；新增表、接口、页面与测试围绕本票用户路径增量实现，不横向重写整个模块。01交接票只做交接核对；08及23—25是真实运行操作。其他票的API/持久化/界面与测试应作为同一可演示切片交付。新组件不可写真实账本或自签资格；没有必要不新增测试入口或插件框架。
