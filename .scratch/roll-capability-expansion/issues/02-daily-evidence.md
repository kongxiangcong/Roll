## Acceptance criteria

- [ ] 只实施01确认尚未交付的日线/session消费者与来源差量；已有sse日线等实现先核对不重建。
- [ ] 通过公开采集/查询链保存单证券原响应、日期、单位、RAW/调整、会话完成和修订，显示用途准入及具体拒绝原因。
- [ ] 报价、未收盘行、错日、分页截断、停牌占位、无量额与冲突不自动升级为完整可评分日线；新来源同上游不算独立。
- [ ] 为每个缺字段绑定可执行的固定来源/请求与预算；没有真实依据则该项保持partial并给出来源字段缺口，不以再换一个库完成。
- [ ] 固定响应测试、一次有界真实来源验收、原件损坏拒绝及离线零联网重放分别留证；旧包和模型不变。
- [ ] 附本票适用的代码/依赖版本、公开行为验收、真实与METHOD边界、原失败及剩余条件；若继承另一会话成果，引用精确验收并核对当前版本。不得以仅写计划或仅实现拒绝路径替代所要求的正向能力。

## Implementation boundary

优先复用原服务和指定成熟组件；新增表、接口、页面与测试围绕本票用户路径增量实现，不横向重写整个模块。01交接票只做交接核对；08及23—25是真实运行操作。其他票的API/持久化/界面与测试应作为同一可演示切片交付。新组件不可写真实账本或自签资格；没有必要不新增测试入口或插件框架。
