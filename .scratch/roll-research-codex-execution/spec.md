# 02 · 从正式研究 CLI 执行一次真实 Codex 研究

Status: ready-for-agent

## Problem Statement

研究者已经能为一只股票冻结公开材料、重读证据缺口并按版本发布研究档案。阶段 01 的离线执行桩能证明这条流程可重放，但要用真实助手回答问题，研究者仍需把材料交给另一个程序，再把回答带回 Roll。他很难核对助手实际看到了什么、失败后该补材料还是重跑，以及正在审阅的判断究竟来自哪次执行。Roll 的本地 SQLite 同时存有账户、成交与风险预算，直接在工作目录启动助手也会带来额外的读取权限。

## Solution

研究者在原有 `roll research task run` 入口选择 Codex，提交标的、问题、截止时点和公开材料。Roll 为这次研究尝试启动一次受限的 Codex CLI。研究者可在终端得到待审草稿版本、具体缺口或可采取行动的失败原因，之后按任务 ID 找回冻结输入和每次尝试的结果。材料相同可以人工重试，补入新证据可以建立关联任务。只有研究者在现有发布入口确认指定版本后，档案才按生效时间进入盘后决策。

## User Stories

1. 作为研究者，我希望在熟悉的研究任务命令中显式选择 Codex，以便用真实助手研究同一类个股问题。
2. 作为离线使用者，我希望原有命令仍可断网运行，以便复核历史材料和演练发布流程。
3. 作为研究者，我希望助手收到我选定的公告原文或摘录、行情及其定位，以便按当时可得的材料回答问题。
4. 作为账户使用者，我希望账户快照、交易日志、风险预算和本机工作台只由 Roll 访问，以便提交研究时控制披露范围。
5. 作为研究者，我希望得到具体缺失的材料和原因，以便判断是否需要补证；对不妨碍回答的缺口，我希望在草稿中看到其影响。
6. 作为审阅者，我希望从草稿中的事实字段定位到冻结公告的页段或行情观测，以便核对原文、数值和时点。
7. 作为审阅者，我希望助手明确哪些结论仍属推断，以便在证据不足时保留未知状态。
8. 作为研究者，我希望查询任务时看到当次尝试正在执行还是已经退出，以便决定继续等待或取消。
9. 作为研究者，我希望能取消一次正在运行的研究，以便及时收回它占用的进程和运行锁。
10. 作为研究者，我希望能分清超时、异常中断、执行配置错误和无效回包，以便决定修复环境、重试或检查助手的输出。
11. 作为盘后操作者，我希望等待助手时仍能向同一数据库登记业务，以便长时间的模型调用不会占住写事务。
12. 作为研究者，我希望手动重试后保留每次尝试各自的回执、日志和草稿，以便比较相同材料产生的两个结果。
13. 作为研究者，我希望补充公告后能从原任务发起关联任务，以便分辨哪项新依据改变了判断。
14. 作为审阅者，我希望按回执中的版本检查字段依据并具名发布，以便盘后计划只消费我确认过且已生效的约束。
15. 作为维护者，我希望能在声明的目标机上复验文件权限、工作台访问和子进程退出，以便说明这版执行配置实际提供的保护。

## Implementation Decisions

- **运行基线。** 首个验收目标为 Ubuntu 24.04.5 LTS x86_64、`codex-cli 0.172.0`。真实执行由研究者显式选用，原有离线调用和历史任务仍可使用。每次真实尝试记录实际平台、CLI 版本、执行方式和可复核的权限配置摘要。
- **输入和输出。** 复用阶段 01 的研究任务编排与执行器交接。Roll 从冻结清单构造本次公开文本，将其交给一次非交互式 `codex exec`，收取符合阶段 01 草稿／缺口契约的结构化最终响应。文本保留证据引用与定位。若问题所需材料无法提供可读内容，明确记录缺口。模型服务连接仅用于本次推理，助手可用的研究材料限于该清单。
- **权限。** 优先采用无本机工具的文本输入和结构化输出，核对实际启用的工具、扩展与服务。如果这一版本的配置无法落实读隔离，改用受限运行环境，只暴露本次公开输入和必要的输出通道，隔离宿主数据库、数据源凭据与回环工作台。两种方式均须通过同一组目标机探针；无法落实隔离时以配置错误结束尝试。更换工作目录、启用临时会话和模型口头拒绝均不足以通过验收。
- **尝试回执。** 在等待模型前提交领取记录，研究期间可用任务 ID 和尝试 ID 查询。回执将执行器及退出结果、可用的退出码或终止原因、诊断日志引用和结果版本绑定到尝试。启动前失败也保留原因。日志按尝试隔离，并排除凭据和本地账户内容。旧回执仍可重读。
- **结束原因。** 用户主动停止记为取消，超过配置时限记为超时，执行者意外退出或重启后确认失去执行者记为中断。可执行文件、认证或权限配置不可用时指明配置问题；服务或 CLI 运行失败时保留退出诊断。进程正常退出但最终响应缺失、结构不符、标的不符或引用越出清单时标明回包校验错误。有效回包报告的阻塞性缺口沿用 `blocked`；有合规草稿则沿用 `draft_ready`，保留非阻塞性局限。
- **清理和提交。** Roll 对同一任务的在途尝试持有运行锁，在 SQLite 写事务外等待。取消、超时或执行者异常退出后，清理该次助手及其后代进程并释放锁。恢复时核对执行者是否仍存活。取消与结果提交竞争时仅保留一个终态，迟到结果无法覆盖它。成功时在同一短事务内写入草稿、唯一版本和回执关联，其他终态均可单独重读。
- **重试和补证。** 人工重试沿用原任务清单，为新尝试分配独立日志和产物。新增材料按阶段 01 由用户或 Roll 取得后冻结到带父任务引用的新清单。助手不自行检索公告、续接会话或自动发起下一轮。
- **人工发布。** Roll 复用研究档案的字段依据与人工发布规则。`fundamental_gate=pass` 必须引用支持该字段的证据；`thesis_status=intact` 和非空 `strategy_whitelist` 需要对应证据或审阅者明确确认的判断理由。助手须把仅有推断的结论标为不确定。版本、审阅人、生效时间及有效期沿用现有档案记录。

## Testing Decisions

主验收入口采用正式 `roll research task` CLI。测试从任务回执、指定版本的档案、同库其他操作和目标机观测判断结果。沿用已有研究任务测试中的冻结清单重读、错误回包、草稿提交回滚与同输入重试场景，以及研究档案测试中的字段级发布校验。可控故障使用测试用 CLI 子进程，经相同 Roll 入口启动，以便稳定制造挂起、子孙进程和坏回包。

1. **真实往返。** 在验收库副本上，以江西铜业（600362.SH）和一份已冻结、有页段定位的公开材料提出一个能从原文核查的问题。通过正式 CLI 调用目标版本的真实 Codex 一次并取得待审草稿。另起 Roll 进程执行 `research task show` 和 `research task attempt`，核对清单指纹、执行器、退出结果、日志归属和草稿版本，再用 `research show --draft --version` 重读该版本。记录可重放的命令和引用。
2. **实际权限。** 在公开包外放置含独有标记的假私有文件，启动会记录请求的回环测试工作台。先从宿主确认文件可读、服务可达；再按真实执行配置检查助手暴露的能力并尝试两项访问。记录工具不可用的生效配置或同一受限身份下的系统拒绝结果，并核对服务访问记录、实际送出的公开输入和返回产物。宿主对照须成功，受限端须无法取得标记或触达工作台。只看助手回答或搜索输出中的标记不能单独构成证据。
3. **停止与恢复。** 分别触发主动取消、等待超时和执行者意外退出，使用会启动后代进程的受控助手。重开 CLI 核对三种原因、无可发布草稿、整棵执行进程树已退出且锁已释放；每种情况均可立即用原清单人工重试。检查新旧尝试 ID、输入指纹与日志归属。另在结果交付时取消，核对唯一终态及其草稿归属。
4. **运行期间的同库操作。** 让一次尝试停在等待响应阶段，从另一 CLI 进程查询它并在同一库副本完成独立业务写入，随后让助手返回。检查查询未中断原执行者、同任务没有第二个并行执行者、业务写入在等待期间已提交。
5. **缺口与故障。** 分别提供缺少必要证据的有效回包、无法启动的 CLI、非零退出和正常退出却不合约的回包。按 ID 重读所需材料或具体失败原因，核对均未登记草稿版本。通过原入口补证或重试后，旧回执与原清单仍可查。
6. **字段依据与发布。** 人工抽查真实草稿，将拟放开风险的事实逐字段追到冻结材料中的具体段落或观测，核查其是否支持所述判断，同时核对推断的措辞和未知字段。在同一 `research publish` 入口复验阶段 01 的三种情形：仅签名而缺字段依据的版本被拒；有对应事实证据的门禁可由人确认；允许人工判断的字段可凭具名审阅者的具体理由发布。用固定输入预览盘后计划，核对发布前所用版本及生效后的字段依据、确认人和期限。

## Out of Scope

主动联网取证、自动重试、多轮会话、工作台异步操作及复盘跟进、开发实验计算与回执格式、独立验收与策略准入、M0b 真实前向计数。Windows 交付需在 Windows 实机按相同条件验证权限、进程树及运行锁；本轮的平台验收范围为上述 Linux 基线。
