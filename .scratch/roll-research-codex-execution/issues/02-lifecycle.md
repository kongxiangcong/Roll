# 02 · 取消、中断恢复与同输入重试

Status: ready-for-agent

Resolution: completed

Closed: 2026-11-26

Blocked by: 无，可直接开始

## What to build

从正式任务入口控制单次执行的生命周期，查询中途状态，在停止或失去执行者后安全重试。

## Acceptance criteria

- [x] 研究等待期间可从另一 CLI 进程重读任务、完成独立同库写入，同任务同时只有一个执行者。
- [x] 在目标平台区分主动取消、超时、执行者异常退出；观察含后代的执行进程树全退出和锁释放，随后同输入立即重试。
- [x] 取消和最终交付竞争时只保留一个终态；查询不会导致活跃任务中断。重试保留旧日志、产物与清单，补证沿用关联任务。

## Comments

在 Ubuntu 24.04.5 LTS x86_64 上，`backend/tests/test_v3_research_lifecycle.py` 通过正式 CLI 运行受控助手。等待回包时，另一进程读取正在执行的尝试、向同库写入账户基线。并发重试返回当前尝试 ID。执行中的任务 ID 与尝试 ID 会输出到标准错误；`roll research task cancel <attempt_id>` 在本次清理完成后返回回执。

分别取消、触发时限、以 SIGKILL 结束 Roll，以及令助手自身被信号终止。通过 /proc 核对助手及开启独立会话的后代均已退出，再以相同输入执行新的 Codex 尝试并取得带具体缺口的回包。原日志可重读，重试拥有独立日志和相同的清单指纹。立即重试会等候遗留后代清理；在执行者死亡后才发出的取消保留中断原因。

在受控投递点取消，重读结果仅有一个终态，旧草稿未被替换。结果先提交时再调用取消，回执与原版本保持一致。阶段 01 的原清单重试、补证关联和草稿写入回滚用例继续通过。
